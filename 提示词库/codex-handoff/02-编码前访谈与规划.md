# 02 编码前访谈与规划

**什么时候用**：需求还不够清楚，希望 Agent 先问关键问题、给方案，获得批准后再改代码
**什么时候别用**：任务和验收标准已明确，且无需新增方案确认
**产出**：关键问题清单与等待批准的实施方案
**来源**：用户提供，原始出处未标注
**状态**：未实测

---

```text
编码之前，先向我确认需求。

只问最少、最关键的问题，弄清目标、约束、成功标准、
边界情况，以及哪些内容不在范围内。

暂时不要修改文件。等我回答之后，如有需要，请先检查仓库，
再给我一份方案，包含：
- 可能涉及的文件
- 实施阶段
- 主要风险
- 最小有效里程碑
- 验证步骤

得到我的批准后，再开始修改。
```

## 英文原文

```text
Before coding, interview me.

Ask only the fewest high-leverage questions needed to understand the goal, constraints, success criteria, edge cases, and what
should stay out of scope.

Do not edit files yet. After I answer, inspect the repo if needed, then give me a plan with likely files, implementation
phases, main risks, the smallest useful milestone, and verification steps. Wait for my approval before making changes.
```
