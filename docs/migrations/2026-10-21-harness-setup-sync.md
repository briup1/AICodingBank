# 项目底座入口收敛：Setup / Sync

## 决定与范围

用户确认仅保留两个公开职责：`wl-harness-setup`建立/补齐，`wl-harness-sync`按明确变化维护。两者共用harness-pack中的正文模板、内容标准和结构检查。登记验证清空，不能沿用旧版验证日期；不自动安装或修改业务项目。

旧版具有模板和内容深度要求，但没有逐项目执行的标题/章节顺序检查，测试只锁定若干关键词；轻量wl-harness-pack只约定职责，不能保证跨项目正文骨架一致。本次将结构约束落在共享模板和只读检查器，不声称它能证明内容真实性或自动触发。

新登记路径：

- `tools/skills/engineering/wl-harness-setup/`
- `tools/skills/engineering/wl-harness-sync/`

两个Skill平级放置，harness-pack仅保留references/assets/scripts共用资源，不含SKILL或skills子目录。用户明确要求删除旧内容后，核对目标归属再移除.agents/.claude中的六条旧软链，并从Pi本机索引删除三个旧条目；不触碰其他Skill，不新建全局链接，不声称新名字已自动发现。已启动会话注入的旧清单不会因此原地刷新。

## 统一产物与差异

- 新项目需求、设计、用例、结果统一归 `docs/changes/YYYY-MM-DD-主题/`。仅长期规则、模块职责/关键契约或重要取舍变化时加`规范变更.md`，一般修复和事实补齐直接改原文。已有需求目录保留并显式映射，调用下游覆盖其默认目录；不改其他需求Skill默认路径。归档不代表全部提交，原始证据须明确忽略/受控保存及脱敏。
- rules四份、Wiki四份的标题、二级章节顺序来自同一模板；章内可紧凑列表/表格或详细条目，不强制固定四级字段和正反例。不适用章保留并说明理由，不需要整份不建。
- 不新增ARCHITECTURE/CONTEXT双正文：工程结构完整承接架构链路与不变量，领域术语承接名称边界，业务模型承接业务背景。已有正文获准迁移时修引用，旧依赖路径可留指针；公共Owner未获准时只映射。
- 框架/接口/状态以源码、schema和既有契约为事实Owner，模板不强制复制全集；新项目不虚构技术栈、空架构。
- 个人模式沿同一骨架写`.harness-local/`，先核验忽略，团队规则优先。测试入口卡只写网址、账号/登录方式，获准测试密码仅进受保护的忽略个人文件。
- setup和sync独立使用；旧项目异构正文先报告差异，未授权不强迁。草案入口顶部明确未启用、不覆盖现行规则；启用后只留指针，未实测不承诺宿主隔离。草案和目标设计不冒充当前实现。

## 验证与限制

验收以本次实际命令输出为准：共享模板的独立固定章节预期、两种项目手写正文、模拟内容更新、漏章/重章/改名/错序/空正文反例、紧凑/详细条目均可用、文件名漂移、已有路径映射、CLI退出码、未读取测试账号卡与只读重复检查。

这些是结构与接入契约验证，不是全新Agent实际执行setup→sync，也不是真实业务项目迁移、账户登录或跨宿主加载验收。两新登记verified保持空；不自动提交或全局安装。历史记录与其他研究文档不改。
