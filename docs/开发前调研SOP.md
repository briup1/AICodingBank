# 开发前调研SOP

状态：初版，待真实项目试运行。适用：从零开发软件或重要功能，需要决定用户问题、竞品差异及技术复用时按需使用。小任务可裁剪；不替代项目规则、授权和现有任务记录。2026-11-15 基于公开资料形成工具建议，未做同题工具对比实测；外部工具能力、费用、覆盖与可用性使用前核对。

入口：产品想法 → 列关键决策 → 按需组织业务与技术调研 → 验证关键未知 → 汇总决定及证据 → 回到团队开发流程。

## 角色与产出

职责可合并，不固定人数；必要独立复核须由实际独立执行者完成。

| 职责 | 研究目标与素材 | 产出 |
| --- | --- | --- |
| 负责人 | 定义用户、业务目标、关键决定、预算、时间及不做什么；汇合冲突 | 问题清单、研究范围与决策 |
| 用户与场景 | 用户访谈、真实工作过程、求助与评论；查现有替代办法 | 谁在什么处境遇到什么困难，附原话和来源 |
| 竞品 | 按同一场景试用产品；查文档、价格、更新和用户反馈 | 关键路径、差异、限制、适用人群，区分实测和宣传 |
| 技术与开源 | 搜同类项目、组件、实现；查源码、测试、许可证、依赖、维护和接入成本 | 候选、可复用范围、风险、实验与自建/复用建议 |
| 复核 | 独立查反例、遗漏和证据是否支持决定 | 需要修正的问题、未证实假设与阻塞 |

## 执行步骤

1. **定决策**：写下谁要完成什么、为什么现在研究、要决定什么和预算；先查现有资料，判断需要哪些职责，不预设所有维度必查。
2. **找证据**：业务侧查原始用户反馈、实际操作、竞品和人工替代方案；技术侧按下方路线找项目和具体实现。选择目标用户实际出现的渠道，而非把所有网站查一遍。
3. **交叉判断**：同一用户场景对比竞品；把发现的功能与真实需求联系起来；对核心方案比较自建、采用、参考和暂缓。区分事实、推断与假设。
4. **验证风险**：对足以改变决定的未知做最小实验，例如验证 Agent 进程的审批事件能否接入。确认源码版本、环境、操作和结果；有费用、外发、账号、共享环境或不可逆影响时遵守相应授权。许可证和依赖按实际分发方式核对，必要时寻求法律意见。
5. **决策与停点**：在项目现有记录中汇总结论及证据；关键问题没有证据时写未知或阻塞。主要路径和反例已核对、关键未知已验证或明确阻塞，且继续搜索不太可能改变当前决定，或已达到约定资源边界时停止。

## GitHub 宝库：工具与方法

### 默认发现入口：当前可用的 Exa 网页搜索

优先使用当前 Agent 可用的网页搜索，指定 Exa 并面向 GitHub 搜索；本轮 Exa 返回了真实的项目发现结果，但未比较其召回率，也未验证其他工具的实际接入。它不是 GitHub 专用索引，结果可能不全或过期；筛选和结论必须回到原仓库核对。无须为使用它自动安装工具、配置服务或密钥。

例：想做桌面端 Agent 工作台，先把想法拆成多组英文检索：`desktop coding agent electron open source`、`agent approval workflow github`、`agent session resume repository`；同时搜索同义词、已有替代方案和相关组件。记录查询与时间，去重后按场景吻合、维护、许可证、依赖、运行条件筛选，再读 README、Issue、关键源码和测试。必要时才做隔离的最小实验；不要只按 Star 排名。不要把私有代码、凭据或敏感需求发到第三方服务。

| 工具 | 擅长的阶段 | 局限与证据 |
| --- | --- | --- |
| [Exa](https://exa.ai/docs/get-started/exa-mcp) | 用自然语言从网页和 GitHub 发现候选；可服务 Agent | 非专用 GitHub 全库搜索；文档说明可用额度及认证条件，详情以当时为准。2026 年有 [Exa 代码搜索接口变动记录](https://github.com/nicobailon/pi-web-access/issues/24)。本轮以当前网页搜索调用获得结果。 |
| [Grep by Vercel](https://grep.app/) | 跨公开仓库搜索代码片段、API 和实现例子 | 强项是代码模式，不等于按产品需求发现完整项目。2026 年 [开发者文章](https://adiology.dev/blog/best-mcp)提及其 MCP；本轮未实际查询。 |
| [DeepWiki](https://deepwiki.com/) | 已有仓库后，以生成式文档和问答快速理解结构 | 不保证覆盖所有仓库，答案可能过时或出错；回源码和版本核对。2026 年 [开发者文章](https://adiology.dev/blog/best-mcp)提及；本轮未实际运行。 |
| [Sourcegraph Code Search](https://sourcegraph.com/code-search) | 在其可访问和已索引的仓库范围内查符号、文本或正则 | 面向代码检索，覆盖、部署及费用取决于服务；不是默认公开 GitHub 全量搜索。见其 [2026 年工具使用说明](https://sourcegraph.com/blog/the-right-tool-at-the-right-time-using-sourcegraph-search-effectively)，属厂商材料；本轮未实测。 |
| [Repomix](https://repomix.com/) | 将已选仓库打包为适合 AI 阅读的材料 | 不负责发现项目；打包可能涉及隐私、上下文过大与信息截断。见 [2026 年比较文章](https://hub.qodo.ai/post/repomix-gitingest-alternatives/)，属商业厂商材料；本轮未实测。 |

上述五项是调研链路中的不同工具，并非同类排名或证明它们在 2026 年最受欢迎。仅 Exa 本轮用于检索；其余依据公开材料作候选。不要为凑齐工具而串接全部工具。

### 已有技能的关系

工作台 `wl-project-refactor` 已规定该重构流程仅以 `github-repo-explore` 作为外部 GitHub 调研入口；该专属边界仍优先。本机本轮未定位到该技能的可用安装位置，不视作已安装。其 [公开来源](https://github.com/microsoft/semantic-link-labs/blob/main/.claude/skills/github-repo-explore/SKILL.md)描述的是 Agent 调用 `gh search` 和本地源码阅读的流程，不是独立语义搜索引擎；使用前应先核实当前真实位置与适用规则，不自动安装或登录。它与本指南选择 Exa 作为一般研究的候选发现入口并不互相覆盖。

## 其他调研可复用的东西

| 研究 | 固定方法 | 渠道与限制 | 应保存的证据 |
| --- | --- | --- | --- |
| 用户问题 | 谁、什么处境、任务、现有做法、代价 | 访谈、观察、论坛、工单；公开评论有选择偏差 | 原话、时间、背景、来源；事实与假设分开 |
| 竞品 | 所有产品走同一条用户任务 | 实操、文档、定价、更新日志、评价；无权限标未验证 | 产品版本、账号条件、步骤、结果、时间 |
| 市场和购买 | 查目标群体、替代成本、真实采用或购买行为 | 公开价格、客户案例、访谈；宣传与意向不能证明付费 | 来源、样本与条件，缺数据标未知 |
| 技术复用 | 功能适配 → 源码/维护/依赖 → 许可证 → 必要最小实验 | 项目主页、包仓库、Issue、测试、发布记录 | 仓库链接、commit/版本、许可、验证过程、限制 |
| 反例复核 | 查最可能推翻结论的事实和遗漏候选 | 独立资料或独立执行者；不能把自查称独立复核 | 反例、处理结果、未解决风险 |

这些是待试用的方法，不代表任何平台都已验证可用。复用的是调查问题、筛选方法和证据要求，不是旧项目结论；每次均需核对时效和适用范围。

## 决策记录最小格式

在项目现有记录中保存：目标与范围；待决策问题；用户场景与原始证据；竞品及替代方案；开源候选与版本/许可/维护；自建、复用或暂缓及理由；实验结果、反例与未验证风险；来源链接和访问时间。标明事实、推断与假设，不复制敏感数据。

试运行后检查：能否快速决定要查什么；发现是否改变决策；是否说清自建/复用/暂缓；证据能否回溯；哪些步骤可删。一次成功不证明适用于全部项目。
