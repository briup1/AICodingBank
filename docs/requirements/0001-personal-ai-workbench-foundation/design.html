SEC 02 / 07

前后对比

新增控制骨架，不搬迁任何下层系统。

BEFORE

分别记忆 Skill 仓库、知识库、Goal、Personal Workbench 和项目的用途；面对多个 Skill 自行判断顺序。

SEC 03 / 07

接口与契约设计

调用者只需学习一个工作台入口，下层能力保持自治。

文件接口

文件职责不承担
README.md人类入口和工作台链接不复制阶段路由
WORKBENCH.md边界、系统地图、路由和组件职责不保存私人路径，不执行任务
WORKBENCH.local.example.md本地上下文字段模板不含真实资料
WORKBENCH.local.md本机偏好、项目指针和知识入口不保存密钥、转录、临时进度
AGENTS.md / CLAUDE.md加载工作台和可选本地上下文不复制工作台正文

阶段路由

理解事实？ --------> Observe / 观察
确认目标？ --------> Confirm / 确认
决定做法？ --------> Design / 设计
产生改动？ --------> Execute / 执行
证明正确？ --------> Verify / 验证
保存经验？ --------> Learn / 沉淀
阶段进入条件退出证据
Observe只要求理解现状基于真实文件、命令或来源的事实
Confirm目标、边界或验收未确认获批准需求或清晰小任务边界
Design目标稳定，做法未定获批准方案或获准最小方法
Execute方案和修改边界稳定实际改动与执行证据
Verify已有待检查产物实际测试、审查和验收证据
Learn已验证结论可跨会话复用写入适当记忆、知识库或项目文档
阶段不是流水线强制关卡。只读问题可在 Observe 结束；边界明确的操作可直接进入 Execute；任何阶段都不能伪造退出证据。

项目与隐私契约

  • 项目索引只保存路径、稳定用途、知识入口和真实文件入口。
  • 允许保存稳定沟通偏好；禁止保存密钥、会话原文、客户数据和临时任务状态。
  • 项目实现和命令始终以项目真实文件为准。

SEC 05 / 07

多方案并列

选择影响信息是否保持单一事实来源。

方案 A · 推荐

独立控制文档

新增 WORKBENCH.md 与本地模板，其他入口只保存短指针。

收益：路由只有一份；常驻上下文短；人和 Agent 使用同一地图。

代价：新增一个顶层文档。

方案 B

入口文件内嵌

README、AGENTS 和 CLAUDE 分别保存面向各自读者的路由。

收益：少一个顶层文件。

代价：路由重复三份、容易漂移，并增加常驻上下文。

推荐 A：删除该文档会迫使相同复杂度重新散回三个调用点，因此它提供了真实的局部性和复用价值。

SEC 07 / 07

最小验证

先证明文档路由足够，再考虑任何自动化。

最悬假设

只靠文档入口，能否让六类典型请求稳定落到唯一阶段，而不增加路由程序。
