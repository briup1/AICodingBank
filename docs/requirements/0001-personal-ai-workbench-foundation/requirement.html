个人 AI 工作台
最小骨架

0001DONE2026-09-03
SEC 01 / 04

需求重定义

不复制别人的工作台，先把自己的现有资产连成最小闭环。

原始诉求
参考 Brayness 中有启发的能力，将当前项目发展为个人 AI 工作台。
最终目标
让能力仓库、项目、个人偏好、知识和任务机制不再彼此孤立；每次工作都能明确工作台是什么、当前阶段、目标项目和下一类能力。
异议
不应复制 Brayness 的目录和完整运行时。当前系统真正缺少的是统一入口和清晰路由，首期应先验证最小骨架。
约束
  • 升级当前仓库，不另建平行工作台。
  • 首期只采用文档，不新增程序、服务、数据库或依赖。
  • 私人信息不进入共享版本库。
  • Skill 管理行为保持不变。
  • 不夹带工作区其他未提交改动。
确认后的需求
建立最小且可读的控制骨架，统一系统边界、工作阶段、项目入口和个人上下文，让现有组件沿同一条工作路径协作。
SEC 02 / 04

用户故事

每项能力都对应一个明确的使用价值。

As a 工作台使用者, I want 从统一入口看懂定位、组成和边界, so that 不必猜测每个组件的职责。
As a 任务发起者, I want 判断当前阶段及下一步, so that 不会跳过必要的确认和验证。
As an Agent, I want 获得明确且不重叠的阶段路由, so that 优先复用现有能力。
As a 跨项目开发者, I want 找到项目位置、用途、知识和工作入口, so that 快速进入正确上下文。
As a 个人用户, I want 在本地保存稳定偏好和私人资料, so that Agent 理解我而共享仓库不泄露隐私。
As a Skill 维护者, I want 保留能力控制面的现有规则, so that 工作台升级不破坏 Skill 供应链。
SEC 03 / 04

不做什么

首期只建立骨架，不把未来可能性提前做成负担。

不复制 Brayness 的目录、命名、脚本或完整 Harness。
不迁移现有项目，也不改变各项目的 Git 边界。
不统一 Pi 会话、模型配置、凭证及运行状态。
不开发 Web UI、任务看板后端、数据库或项目扫描服务。
不新增阶段 Skill，只组织和路由已有能力。
不重构安装器、登记格式、验证门禁或第三方依赖管理。
不自动批准完整开发流程或高风险操作。
不处理当前工作区已有的其他未提交内容。
SEC 04 / 04

验证方案

只接受可以从外部观察和复核的结果。

维度可观察的验收结果
统一入口两次跳转内找到定位、组成、路由、项目索引和个人上下文说明。
阶段路由六类典型请求均得到唯一当前阶段和明确下一步。
项目索引可找到项目路径、用途、知识入口和常用入口，并以项目真实文件为准。
个人上下文本地 Agent 可用，私人信息不出现在 Git 待提交内容中。
兼容性Skill 登记、安装、验证门禁和按需加载行为不变，原有检查通过。
可读性核心说明只有一个入口，详细能力继续按需读取。
工作区保护验收差异不包含本需求范围外的既有修改。
