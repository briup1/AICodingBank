SEC 1 / 7

现状

E01：本机 OpenCLI 1.8.8、扩展1.0.24。网页 Skill 要求独立会话，却无强制结束步骤。原生自建会话约10分钟空闲释放；借用用户页面不自动空闲释放。最后一个会话释放后可能保留空白复用容器；daemon 不随任务退出。

N01 接收网页任务
  ↓
N02 创建/使用浏览器会话
  ↓
N03 执行并报告结果
  ↓
N04 资源留存，依赖调用方或原生空闲回收

当前没有针对 OpenCLI 的统一任务收尾脚本；已有 browser-console 针对 agent-browser，不能当作同一工具。浏览器横幅、标签组、扩展图标不是同一个状态；本轮无原页面截图，不以源码冒充横幅实际可见状态。

SEC 2 / 7

需求重定义

最终目标是减少工作完成后的自动化遗留，同时不影响其他任务、普通Chrome或登录配置。只停止后台服务不能替代会话释放；按用户选定范围，先交付“可执行的会话收尾”，不把它包装成全部服务和容器已退出。

用户故事：As a 经常使用网页自动化的本机用户, I want 每个任务有明确归属、结束动作和真实状态, so that 不必手工猜测哪些浏览器资源可以关闭。

SEC 3 / 7

新旧变化

N01 接收网页任务（保持）
  ↓
N02 登记本任务独立会话（修改 D01）
  ↓
N03 执行并保留业务结果（保持）
  ↓
N04 结束或人工接手？（新增 D02）
  ├─ 结束 → 释放指定会话 → 回读租约状态 → 报告限制（新增 D03）
  └─ 接手 → 记录保留原因 → 人工继续 → 再结束（新增 D04）
差异 原来 → 目标 下游结果
D01 手写会话名 → 每任务随机登记会话 不复用未知历史会话
D02 报告即结束 → 报告前收尾；整任务脚本结束也执行收尾 成功、失败、可捕获终止均有结束路径
D03 凭关闭成功文案 → 原生释放应答和会话列表回读；物理关页另标未验证 不把租约级成功当全部浏览器退出
D04 页面无限保留或随意关闭 → 明确人工交接及恢复 交接状态可见；不承诺取消原生超时
SEC 4 / 7

范围与规则

  • R01：只处理新登记、本任务拥有的会话。借用页面须明确授权，结束只解绑，不删除页面或登录配置。
  • R02：业务失败码保留；收尾失败不能伪报成功。仍有在途请求、结果未知或锁冲突时停止自动释放并报告。
  • R03：普通交互 Agent 显式收尾；整任务脚本正常结束/失败/可捕获终止时尝试收尾。硬强杀/断电无法保证执行。
  • R04：结果分开报告租约释放、物理页面清理、原生空白容器和共享服务。没有物理关闭证据就写未独立验证。
  • R05：不自动清理未知历史任务，不批量杀Chrome或停止共享daemon。
SEC 5 / 7

本期不做

不启用用户级Pi扩展、全局shell拦截、后台回收器；不改OpenCLI或Chrome扩展；不强关最后空白容器，不证明跨宿主空闲后自动停服。原始诉求中的“所有标识消失、服务退出”只部分覆盖，作为明确未完成项保留，不因验收改写成全部完成。

SEC 6 / 7

用例与执行约定

用例v1：聚焦验证。只用本机无业务数据页面与mock夹具，不操作历史会话、不访问外部业务。独立核对只覆盖本次改动与直接原生契约；完成一次阻断修复及聚焦复核，无剩余已发现阻断，17项mock测试由验证者重跑通过。执行证据见 验证记录，不追溯声称用例基线在实现前已独立审查。

SEC 7 / 7

证据与局限

  • E01：已安装CLI与扩展源码的会话释放、空闲回收、daemon生命周期；版本为1.8.8 / 1.0.24。
  • E02：本轮本地HTTP夹具新建A/B，释放A后B仍可读标题，之后释放B。仅证明原生会话路径，不证明浏览器横幅消失或普通用户所有标签状态。
  • E03：原生释放会吞部分物理关页异常，租约消失与真实页关闭不能等同。结果必须带物理清理未独立验证。
  • 确认边界：本轮用户同意实现建议，明确排除宿主级启用。更彻底容器/服务退出需有可验证的跨调用方归属能力，不自动扩展。
