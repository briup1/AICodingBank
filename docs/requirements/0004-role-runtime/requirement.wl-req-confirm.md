# 岗位实例与可恢复工作记录

## 现状与目标

E01：基线 c2d3fc5。岗位手册已有职责和一层委派规则，但执行岗位是草稿；本机记录只有约定，尚无岗位任务恢复入口。

原链路：接单 → 人工组装委派提示 → Herdr 执行 → 当前对话回收结果。

目标链路：接单 → 登记任务包 → 按项目和岗位查找实例 → 复用空闲且身份吻合的实例或启动新实例 → 交接 → 记录交付/阻塞/下一步 → 项目经理验收 → 下次会话读摘要恢复。

最终目标是换会话后仍知道谁在做什么、依据是什么、接下来做什么。在已核验范围内采用按需实例即可满足目标，无需常驻全员。

## 差异与规则

| 差异 | 原来 → 目标 | 结果 |
| --- | --- | --- |
| D01 接单 | 临时提示 → 保存目标、非目标、范围、依据、完成标准 | 新会话可重建任务上下文 |
| D02 实例 | 手动辨认 → 按项目/岗位核验身份和空闲状态 | 不抢占别人的实例，不重复派单 |
| D03 交接 | 对话自述 → 留下交付、阻塞、证据和下一步 | 空闲不等于业务完成 |
| D04 验收 | 临时口头确认 → 项目经理保存验收说明 | 提交与验收分离 |
| D05 恢复 | 依赖旧对话 → 读取摘要并显式确认继续 | 不自动重放可能已经执行的任务 |

- R01：只有项目经理委派，执行岗位不得再次委派；Herdr + Pi + 显式 high 保持不变。这是职责约束，不宣称权限隔离。
- R02：只复用登记且身份吻合、项目相同、空闲的岗位实例；未结束任务不得被新任务覆盖。
- R03：失联、发送结果不明或启动中断须保留事实并标待核对；恢复先展示上下文，由项目经理确认继续，不自动重跑。
- R04：交付必须有证据引用；项目经理核验后才算验收。记录不替代项目产物。
- R05：本机记录被 Git 忽略，不保存凭证、完整对话或复制项目日志。

## 用户故事

- As a 项目经理, I want 按需找到可工作的岗位实例, so that 明确任务能被可靠接收。
- As a 执行岗位, I want 保存交付和阻塞, so that 交接不依赖当前对话。
- As a 下次接手的负责人, I want 读取证据与下一步, so that 可以核对后继续而非盲目重做。

## 验收范围

用例基线见 [验收用例](test-cases.md)。用户已批准本地实现及一个验证岗位实例；独立用例审查未执行，不冒充已完成。运行验证只使用本地受控任务，不对外部业务系统写入。

不包含：全员常驻、定时自动接单、模型切换、工具级权限隔离、完整会话复制或全局安装。复用只是同项目岗位的执行通道复用，不等于独立审查；独立审查另开实例。
