# 项目组与固定工位增量

批准：2026-10-19 用户在“具体修改哪些地方、两阶段测试”方案后明确要求“立即实现”。必要信息的详细加载范围留待讨论，本次只提供岗位身份、组目标及必要资料引用。

## 新旧链路

旧：任务 → 按项目＋岗位启动或复用 → 交付验收 → 保留实例。

新：需求 → 项目组 → 按预制岗位入组 → 加载身份并回执就绪 → 定向派单 → 交付验收 → 保存摘要 → 退组关闭。

默认：离场后需要同角色时创建新成员、新实例，读取组内交接摘要，不重放原成员完整对话。

用户追加确认：每个成员独占一个 Tab，不使用 pane split 创建小工位。先使用 Herdr tab create 在调用者所属工作区创建不抢焦点的独立 Tab，再对返回的根 pane 使用 herdr agent start。提示、等待和状态查询走 agent 命令。Tab 标注项目组与成员；退出前核验 Tab 没有混入其他 pane/成员，不能误关整个工作区。

## 修改节点与验收

| 节点 | 最小差异 | 验收 |
| --- | --- | --- |
| 项目组 | 同仓库两个需求不共用一个前端 | 跨组不复用、不串任务 |
| 入组 | 先收到身份，再接具体工作 | 三个真实工位分别确认就绪；未就绪不能派单 |
| 派单 | 从查岗位变为指定成员 | 任务归属明确，未验收任务不能被下一项覆盖 |
| 回收 | 验收后可保存摘要并关闭工位 | 未完成任务阻止退组；身份不符不关闭 |
| 再入组 | 旧工位关闭后，新人读取摘要 | 新实例有旧产物引用，不依赖旧对话 |

## 实现边界

扩展现有 role_runtime.py/state.json：增加 groups、members，任务绑定成员和项目组。兼容旧任务；旧project-role派发不自动采用组内工位。沿用文件锁、原子替换、事件记录和 Herdr/Pi/high。

成员身份引用真实名称、pane、session及项目；创建/发送/关闭前保存意图，失败不自动重放。关闭只针对登记且身份一致的自建工位，不关闭整个工作区。

不新增后台服务、全员常驻、权限隔离、自动经营或模型切换。岗位共用入组机制，不每个岗位新建启动Skill。

## 验证计划

程序：组隔离、重复入组、未就绪、忙碌、交付验收、多轮派单、发送不明、关闭失败、身份变化、重新入组摘要、跨进程和旧数据兼容。

拓扑补充：三个成员必须分别处于三个不同 Tab；入组调用不允许 pane split；不抢用户焦点，不能以当前 UI 聚焦的其他工作区代替调用者工作区。

真实：同一受控项目组三个岗位 UI/前端/测试，依次完成最小本地页面约定、实现与核对，项目经理验收后关闭本次自建工位。再以同角色新成员验证摘要接续。只操作本次登记的实例，不对已有用户会话注入故障。
