# 0006 测试用例 v1

## 范围与依据

需求：[0006 重启后可复用的 Playwright 测试登录](requirement.wl-req-confirm.md)。当前执行结论与证据统一见[验收记录](acceptance.md)，下文步骤是批准的预期，不复制第二份运行事实。现有 A→B 演示只作需求现状证据，不替代本版验收。

公共前提：真实环境仅 HGJ client / Beta，期望账号与企业由用户确认；测试数据不包括密码或 Token 原文。真实请求只作低频登录有效性检查。过期、错误身份和损坏数据使用本地受控夹具，不在公司系统撤权、切换身份或修改配置来造场景。无查价、无业务提交，结果中不得出现凭证原文。人工登录等待不计入自动运行耗时。

## A：首次授权与跨运行复用

### TC-A01：首次建立可复用登录
- Trace：D01、D02、D03；R01、R02、R03。
- 优先级：P0。
- 前置条件：本机没有该环境的可用保存状态；用户已授权私密保存。
- 测试数据：Beta 页面 `https://beta-smart-agent.hgj.com/query`，已确认的测试账号与企业。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | Agent 按工作台入口查找并调用登录准备能力 | 找到唯一入口，不依赖历史对话里的临时端口或外部项目路径 |
| 2 | 用户在专用窗口完成登录与企业选择 | 原窗口保持；真实身份成功且符合用户确认的身份 |
| 3 | 建立独立测试环境并恢复该登录 | 无需第二次登录；身份与企业一致，业务页可用 |
| 4 | 保存获准保留的登录状态 | 状态仅在本机私密位置；未写入仓库、输出或证据 |

- 后置条件：保留状态；只关闭本次创建且不再需要的资源。
- 状态：执行结果与限制见[验收记录](acceptance.md)。

### TC-A02：旧进程结束后的新进程恢复
- Trace：D02、D03、D05；R02、R03、R06、R07。
- 优先级：P0。
- 前置条件：TC-A01 通过，服务端登录仍有效。
- 测试数据：相同环境与预期身份，无旧调试端口依赖。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 结束上轮本任务浏览器和执行进程 | 不影响日常 Chrome 或其他任务 |
| 2 | 无本轮上下文的新 Agent 仅通过已登记固定入口恢复已有状态，不提供旧端口或临时脚本路径 | 无需旧进程和原临时端口，无需人工再次登录；分别记录旧进程退出和新进程身份成功证据 |
| 3 | 在新独立环境核对真实身份及页面 | 同账号同企业，页面无登录阻断；输出恢复耗时和明确通过结果 |

- 后置条件：保留获准状态；证据注明“新进程恢复”，不写“整机重启已测”。
- 状态：执行结果与限制见[验收记录](acceptance.md)。

### TC-A03：真实关机后恢复（人工后续确认）
- Trace：D02；R07。
- 优先级：P0。
- 前置条件：TC-A02 通过；用户自行关机开机；服务端登录未失效。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 用户重启后让新 Agent 使用固定入口 | 能发现能力，不要求记住旧进程或端口 |
| 2 | 执行登录恢复及只读页面检查 | 登录仍有效且无需人工再次登录、身份企业正确，才记为“整机重启免登恢复通过” |
| 3 | 若实际发现服务端登录已失效，按 TC-B01 处理 | 单独记为“失效分流通过/失败”；本条整机重启免登恢复保持未证实，不能合并为通过 |

- 后置条件：不由 Agent 擅自重启机器。
- 状态：待人工后续验证，交付时必须单独标记。

## B：失效、身份和隐私边界

### TC-B01：无状态、损坏或登录失效时不继续业务
- Trace：D03、D04；R02、R03、R04。
- 优先级：P0。
- 测试数据：本地受控的无状态、损坏状态、身份失效三个变体。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 调用准备能力 | 明确报告需要补登或状态不可用，不把文件存在当成已登录 |
| 2 | 用户取消或超过等待期限 | 不执行后续用例，不发消息，不无限尝试 |
| 3 | 允许场景下用户补登并通过独立恢复检查 | 只有验证成功后才可更新保存状态；失败不覆盖上一份已验证状态 |

- 状态：执行结果与限制见[验收记录](acceptance.md)。

### TC-B02：错误身份与服务异常分别阻断
- Trace：D03；R03、R04。
- 优先级：P0。
- 测试数据：本地夹具分别返回错误环境、错误账号、错误企业、预期身份缺失、业务成功但缺账号、业务成功但缺当前企业、响应无法解释、HTTP 200 但业务未认证、网络/服务不可用。每个变体单独记录。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 分别检查各变体 | 环境/账号/企业不符立即阻断；无法确定身份或预期缺失则记校验未完成并停止；未认证请求补登；服务异常报告环境问题，不自动要求反复登录 |
| 2 | 检查输出和后续调用 | 不泄露真实身份值或凭证；后续业务调用为零 |

- 状态：执行结果与限制见[验收记录](acceptance.md)。

### TC-B03：保存与读取不暴露或混用身份
- Trace：D01、D02、D03；R02、R03、R06。
- 优先级：P0。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 未确认或明确拒绝保存授权时调用准备能力 | 不新增持久认证状态；不能把访问 Beta、保留旧 profile 或允许内存复用当成此次保存授权 |
| 2 | 获准保存后检查位置、访问限制、站点范围及输出 | 只含获准业务/登录/身份服务必需状态；只供本机用户获准测试使用；仓库和日志无认证状态，不打印 Cookie/Token/密码 |
