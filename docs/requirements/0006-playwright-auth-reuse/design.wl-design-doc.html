Playwright 测试登录

来源：已批准需求 v1
用例：基线 v1
创建/更新：2026-10-20

目标与边界

关机后不需要保留浏览器进程。登录仍有效时，Agent 从固定入口恢复状态，在独立测试环境核对身份后运行指定用例；登录失效时才请求人工补登。采用共用 CLI 与 Playwright fixture，不新增后台服务或另一套浏览器驱动。

设计基线：制定方案时，运行中 A→独立 B 内存登录复用已通过，持久恢复待实现。交付更新：持久保存、源A退出后的新进程恢复及聚焦独立复核现已完成，实际结果与未覆盖项见验收记录。第一版只接 HGJ client / Beta，不发查价、不改网站或日常 Chrome。真正整机重启仍由用户后续验证，不用新进程证据冒充。

旧：找旧窗口/临时端口 → 内存传递 → 独立环境 → 验证身份
新：Agent 固定入口 → 本机获准状态 → 新独立环境
                       → 身份相符 → 指定用例 → 结果与收尾
                       → 无状态/失效 → 人工补登，再验证
                       → 身份不明/不符/环境故障 → 停止

场景 A：登录一次，之后恢复

最小例子：今天用户登录 Beta 并确认企业，获准状态保存到本机；结束本轮测试进程，下一轮 Agent 不提供旧端口也能恢复同身份。现有 profile 曾重启恢复失败且根因未定，因此不把整份 profile 当作已验证持久化协议。

业务流程〔设计目标〕
接到获准登录准备请求
  → 读取获准环境与预期身份
  → 验证现有状态
      ├─ 有效：直接交给独立测试环境
      ├─ 无状态/失效：专用窗口人工登录
      │    → 原窗口保持 → 独立环境验证 → 保存成功状态
      └─ 服务异常/身份不符/缺标识：停止，不覆盖旧状态

技术承接：共用程序在 tools/integrations/playwright-auth/；运行时位置放仓库外配置，避免硬编码其他业务项目的 node_modules。先使用本机已有匹配的 Playwright 1.63.0 / Chromium 1243，启动能力实施前最小验证，不下载依赖。

login / 当前获准 A 的一次导入
  → 观察真实业务身份响应，确认账号/企业
  → storageState（Cookie + 本任务 origin 存储）
  → 新 Context 验证恢复
  → 原子保存至本机私密目录，身份预期单独受限保存

check（新进程）
  → 校验保存授权、文件归属/权限/非软链接
  → 读取状态，启动新浏览器，无旧 CDP 依赖
  → 业务身份 code/data + 预期账号/企业比较
  → 输出脱敏状态与耗时；关闭自己创建的资源

保存边界：认证状态与预期身份在本机用户私密目录，目录 0700 / 文件 0600；拒绝软链接与不安全权限，失败不覆盖旧有效状态。不设计额外密钥服务。本机同一系统账号下的其他程序仍可能读取，不能称为加密保险箱。只保存获准 app/login/identity 所需状态，密码不读取、不保存，Token/Cookie 不进入报告与 Git。

已存在的 A 只用于首次迁入；固定 check/run 不依赖它。授权撤回后拒绝读状态；删除需另行确认。网络异常不当作失效强迫重登，缺身份字段也不放行。

场景 B：交给真正的测试用例

最小例子：Agent 调用固定 run 入口执行一条引用共用 fixture 的登录只读用例。准备环境通过才提供 page；若企业不符，用例正文不开始。

业务流程〔设计目标〕
指定测试用例与本次操作授权
  → 准备独立环境
  → 验证登录、账号、企业
      ├─ 通过 → 执行用例 → 记录结果 → 关闭本次 Context
      └─ 失败 → 返回具体阻断 → 不进入用例正文
run → 已配置 Playwright Test 原生 runner
       → 共用 fixture 载入本机状态
       → 新独立 Context + 业务身份门禁
       → 将 page 交给 spec
       → 最终释放 Context / browser

连续/2路并发身份验证
  → 各自新 Context，不共享页面导航
  → 每个环境只核对身份与页面可用
  → 分别收尾；不产生查价或提交

现有项目 spec 需要显式引用 fixture，不能声称所有旧用例自动获得保护。第一版提供一条只读示例及调用方式，不拦截或改写项目的全部测试。连续与并发仅证明登录只读检查，不证明业务写入可并行。

专项、依赖与取舍

专项结论与对应边界
数据与隐私涉及：本机持久状态、原子写、最小域过滤、权限检查、撤回授权拒绝读取。无凭证日志或截图。
接口与协作涉及：login/check/run、fixture；明确 AUTH_REQUIRED / IDENTITY_MISMATCH / IDENTITY_UNVERIFIABLE / ENVIRONMENT_ERROR / RUNTIME_UNAVAILABLE 等失败分类。
并发涉及：Context 独立，只读 2 路验证；共享 profile 不供并发使用，保存写入不互相覆盖。
性能无固定 SLA：记录实际恢复耗时，不把旧演示约 5 秒当目标保证。
外部依赖涉及：本机已装 runner/缓存。路径仅本机配置；若缓存被清理，明确依赖缺失，禁止自动安装。无常驻服务。
发布与迁移不涉及线上发布、数据库或业务迁移；只增工作台接入及发现指针，不替换旧登录工具。

选择理由：复用官方 storageState 和 Context/Test runner，不维护自制浏览器协议。接受依赖本机已安装运行时及服务端登录有效期的限制。工具包源码负责方法，本机配置负责路径，私密状态负责当前身份，不互相复制。

实施边界与验收

实现只新增 tools/integrations/playwright-auth/ 的入口、fixture、示例及最小自测；现有工具接入导航/工作台本机指针按需增加引用，不改 at-test 或 hgj-session 的既有默认行为，不新增同类 Skill。

完整预期引用 用例 v1，不复制第二份用例。技术验证为文件访问安全、原子保存、身份校验 fail-closed、环境与过期错误分流，以及 fixture 拒绝时用例正文不执行。

  • 真实验证：保存当前获准身份，独立新进程恢复，连续三次与两路并发只读验证，报告身份相等与资源退出。
  • 本地夹具：无授权、损坏状态、账号/企业/环境错误、身份字段缺失、服务故障；不对真实环境撤权或造数。
  • 整机重启、其他站点/admin 与业务查价均不在本轮通过声明内。
  • 缺运行时、身份状态或关键安全证据即停止相关步骤，不自动安装或扩大权限。
