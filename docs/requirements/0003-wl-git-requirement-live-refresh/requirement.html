需求 0003：需求开发看板轻量实时刷新

需求重定义

原始诉求：希望在 HTML 看板中点击按钮即可重新扫描 Git 并看到最新状态，而不需要回终端运行命令再手工刷新浏览器。

最终目标：为现有用户级需求开发看板增加仅监听 localhost 的前台服务，使页面可以显式刷新 Git 事实，并可选择临时自动刷新；保持静态 HTML 降级模式，且不把看板扩展成 Agent 启动器、项目管理平台或常驻服务。

用户故事

  1. As a 并行需求开发者, I want 点击“刷新状态”后看到最新分支、Worktree 和合并状态, so that 我不需要回终端执行 refresh 和 Command+R。
  2. As a 看板使用者, I want 明确知道当前是实时模式还是静态快照, so that 我不会把旧数据误认为实时数据。
  3. As a 持续观察者, I want 可选 15/30/60 秒自动刷新且默认关闭, so that 临时监控时省事，正常阅读时不被打断。
  4. As a 安全敏感用户, I want 服务只监听本机且只提供只读扫描接口, so that 页面不能执行 merge、push、删除、发布或启动 Agent。
  5. As a 现有用户, I want 原来的静态 HTML、refresh/open/watch 命令继续工作, so that新增实时模式不会破坏降级路径。

约束

  • 服务固定绑定 127.0.0.1，默认使用随机空闲端口。
  • 服务以前台方式运行，Ctrl+C 停止；不创建守护进程、PID 服务或开机启动。
  • 页面不启动或控制任何编码 Agent、终端、容器或外部任务。
  • 刷新接口只执行现有 GIT_OPTIONAL_LOCKS=0 的只读扫描和用户级状态/HTML更新。
  • 不开放 CORS，不监听 0.0.0.0，不提供局域网或公网分享。
  • 使用随机会话 Token；刷新仅允许同源 POST，拒绝 GET 和无效 Token。
  • 自动刷新默认关闭；页面不可见时暂停，已有刷新未完成时不重复请求。
  • 实时更新不得清空搜索、项目筛选、状态筛选、视图模式、滚动位置和分支展开状态。
  • 静态 file:// 模式不得伪装成实时扫描，只能重新加载已有快照并提示如何进入实时模式。
  • 使用 Python 标准库，不新增运行时第三方依赖。

不做什么

  • 不在看板中启动 Claude、Codex、Herdr 或其他 Agent。
  • 不增加任务下发、Prompt、终端、diff 编辑器或 PR 创建能力。
  • 不执行 Git 写操作、环境发布或 TAPD 写入。
  • 不做多人协作、登录系统、数据库、常驻后台服务或网络分享。
  • 不替代现有 wl-git-requirement-flow 生命周期命令。

验收标准

  1. dashboard serve --open 启动前台 localhost 服务并打开浏览器，Ctrl+C 后端口关闭。
  2. 页面显示“本地实时模式”、服务地址、最后刷新时间和“刷新状态”按钮。
  3. 点击按钮触发一次真实 Git 扫描，页面原地更新，不整页重载。
  4. 刷新过程显示项目数/状态，按钮防重复；成功与失败均给出明确反馈。
  5. 自动刷新默认关闭，可选 15/30/60 秒；隐藏标签页停止自动扫描。
  6. 静态 HTML 显示“静态快照”，按钮仅重新加载页面，并提示使用 dashboard serve --open。
  7. 无 Token、错误 Token、错误 Origin、GET refresh 均不能触发扫描。
  8. 服务只监听 127.0.0.1；无外部资源、CORS 或 Git 写接口。
  9. 页面刷新后保留全部筛选、视图、滚动和 <details> 展开状态。
  10. 现有静态命令和 0002 测试全部继续通过。
