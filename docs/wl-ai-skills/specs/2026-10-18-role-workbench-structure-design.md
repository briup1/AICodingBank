# 岗位制工作台：目录骨架与迁移边界

> 历史阶段说明：以下保留最初骨架阶段的批准范围与证据。用户随后明确要求迁移 Skill、历史最佳实践并形成规范；当前路径和进展见 [2026-10-18 迁移记录](../../migrations/2026-10-18-role-workbench-migration.md)，不再以本文“尚未迁移”描述当前状态。

本批准只覆盖结构与说明骨架，不批准后续自动调度、能力/权限隔离、模型切换、全局安装或旧资料删除。岗位文本是 draft、enabled: false；目录存在不等于运行能力已验证。

## 目标与现状

现状：WORKBENCH 定位任务 → 当前 Agent 选择 Skill → 必要时通过现有 Herdr 规则委派 → 项目中留证据。岗位、执行配置和个人业务背景尚无独立结构。

目标：董事长资料提供背景与方向 → 项目经理明确任务 → 从名册按需选择岗位 → 岗位引用能力和执行配置 → 实例接单、执行、交接 → 核验与记录。此目标链尚未实现运行自动化。

新旧差异：

| 节点 | 原来 → 本轮结果 | 后续影响 |
| --- | --- | --- |
| 个人入口 | 偏好集中在本机上下文 → 增加 personal 入口与本机画像 | 真实用户与 AI 岗位区分，旧偏好不重复 |
| 协作岗位 | 临时组装为主 → 增加六个岗位草稿与名册 | 明确职责、接单和交接，不启用调度 |
| 岗位组织 | 无岗位分组 → 技术工程/媒体内容/共享支持 | 分组只是导航，不增加部门经理 |
| 工具组织 | 根 skills 等既有布局 → 新 tools 分类骨架 | 提供迁入落点，现用能力路径不变 |
| 执行者 | 岗位和 Agent 易混淆 → execution-profiles 独立说明 | 职责与工具/模型不复制，尚无真实绑定 |
| 记录 | 已有项目事实 → 新本机摘要索引约定 | 引用项目证据，不创建平行权威状态 |

例子：按钮小调整不召集全员；未确定交互的页面先明确决策再开发；角色说“完成”只代表提交交付，仍需核验。上述是后续运行验收方向，本轮不声称已跑通。

## 已定结构与唯一正文

- [roles](../../../roles/README.md)：项目经理；技术工程组的架构、开发、测试；媒体内容组的编辑；共享支持的调研。岗位职责只在各 ROLE.md 维护。
- [personal](../../../personal/README.md)：真实董事长资料入口；profile.local.md 是本机事实，不提交；已有工程偏好仍引用 WORKBENCH.local.md。
- [tools](../../../tools/README.md)：Skill、执行配置、接入说明、公用脚本与通用模板。Skill 分类按主要用途，仅一个实体归宿，多用途通过标签表达。
- [.local](../../../.local/README.md)：版本化记录约定，其他运行内容忽略；项目记录仍是事实源。
- docs/tests 与根能力登记、安装器、CATALOG、vendor 保持职责不变。知识正文、业务代码与创作产物不迁入工作台。

使用小写英文稳定路径，中文标题面向阅读；项目经理使用 project-manager，不保留 steward 别名。没有真实共用需求不填充公共脚本或模板。

## 本轮交付与非目标

交付岗位与分类 README、六个 ROLE.md、个人结构示例/本机画像、记录约定、入口导航、针对结构/链接/忽略边界的最小检查。

不做：创建或控制 Agent、安装/更新 Skill、迁移现用能力、改模型参数、权限隔离实现、重建知识库、删除旧目录、修改其他项目、提交或推送。不得将文件说明检查称为真实协作、独立 Review 或安全隔离验证。

## 兼容与迁移

根 skills 仍是自研 Skill 现用归宿。tools/skills 暂只含分类说明，不接收 SKILL.md。现有全局规则、登记和宿主链接不变；目录/岗位草稿不自动加载。后续迁移前须同步修订路径规则、登记、文档、测试和宿主链接，不创建两份正文。

分批顺序：

1. 本轮完成骨架并检查；旧文件不动。
2. 给旧内容逐项标记迁入、保留、待确认或建议删除，评估角色候选与独有方法。
3. 确认一批后移动而非复制，核对登记、引用和直接受影响能力；迁移到正式归宿需相应规则变更与安装授权。
4. 遗留在外的内容不自动删除；按清单确认后再清理。已有 Git 基线提供版本恢复，不新建备份副本。
5. 岗位/能力/执行配置与开工、接单、恢复机制另行设计并验证后再启用。

当前原目录直接切分支，无 Worktree；宿主软链接仍指向本目录。骨架不改变现用 Skill，后续修改现用能力会影响其他会话，不能将 Git 分支称为运行隔离。

## 验证与局限

本轮完成标准：六份岗位均草稿未启用；新分类无 Skill 副本；文档引用可达；私人资料与运行数据被忽略；根能力登记、安装器和现用 Skill 不变。结构测试只能证明这些静态约束，不能证明岗位分工一定合理、自动开工、模型选择或工具权限隔离成立。

保留隐私/授权边界：本机画像不是公开简介或长期操作许可；内部背景不自动传给所有实例；记录不得保存凭证或敏感业务资料。增加角色不授予权限。既有子 Agent 通过 Herdr/Pi/high 约束仍生效。

后续运行机制启用前再确认：任务/实例身份与就绪、重复启动防护、能力加载与实际执行限制、可用模型及升级条件、并行写冲突与失败恢复、记录责任和清理生命周期。没有将这些未定事项写成已运行配置。
