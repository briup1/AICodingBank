# 岗位与协作

本文件供PM选岗和维护者管理岗位，不是执行者接单前必须通读的前言。PM职责与派单见[PM手册](project-manager/ROLE.md)；执行者直接读本次工作说明及对应ROLE.md，就应知道如何工作、交付和返回问题。

当前架构、开发、内容编辑仍为草稿；UI、前端、测试仅验证了独立Tab的最小协作链，调研验证了按需实例与记录恢复。真实启用范围以各ROLE.md的frontmatter为准，读取或重写手册不扩大启用范围，不代表专业能力已全面验收，也不提供工具级权限隔离。

## 岗位名册

| 岗位 | 何时需要 | 对什么结果负责 |
| --- | --- | --- |
| [项目经理](project-manager/ROLE.md) | 接单与组织交付 | 目标、分工、推进、核验与最终交付 |
| [架构](engineering/architect/ROLE.md) | 有技术决策缺口 | 有依据且可实施的技术决定 |
| [开发](engineering/developer/ROLE.md) | 通用或跨栈实现 | 最小实现与直接验证 |
| [前端](engineering/frontend/ROLE.md) | 页面与组件实现 | 用户操作、页面状态与接口一致 |
| [UI](engineering/ui/ROLE.md) | 交互与布局需要决定 | 前端可落实的页面行为约定 |
| [测试](engineering/tester/ROLE.md) | 生成用例或核验行为 | 有证据的通过、失败、阻塞与未覆盖结论 |
| [调研](shared/researcher/ROLE.md) | 缺少事实或来源依据 | 有来源和适用条件的问题答案 |
| [内容编辑](media/editor/ROLE.md) | 从素材形成内容 | 面向目标读者的可靠成稿 |

名册用于导航，不代替实际状态查询。组只作归类，不设中间调度层；是否召集由任务缺口决定，不自动全员开工。

## 手册与 Skill 的责任

- ROLE.md写稳定职责、本岗位的完成链、交付与停止标准、协作边界。只读本手册应能理解基本工作，不靠多层引用拼职责。
- “工作方法”内按需引用专业Skill并注明触发条件，不复制完整工具流程，也不因岗位绑定就全量加载。没有专用Skill不等于不能执行；必要事实、能力或授权缺失才返回PM。
- 专业Skill决定对应方法和产物细节，本次派单决定范围及成功标准。手册给岗位级交付要求，不另造重复报告或强制模板；方法不扩大授权。
- 同一角色的专业流程各不相同，不套用PM的组织能力。最小协作底线直接写入各手册，避免为去重而强制多一次文档跳转。

## 共用岗位约定

以下是维护时检查的底线，已直接写入各执行手册，不要求每次另读本节：按派单范围和目标项目规则执行，不覆盖他人工作；关键条件不足、需要越界或阻塞时带证据返回PM；不再次委派，未验证不报通过，工具可用不代表已授权。自己换身份不构成独立验证，提交结果不等于PM验收。

## 临时职责与交付

没有匹配岗位时，PM可在派单中直接定义职责、背景、边界和交付要求，不要求先有 ROLE.md；角色称谓不创造专业能力或权限。临时职责不自动写入岗位名册，不启用正式草稿岗位，不能改称临时角色来绕过其启用前提。长期复用时按[岗位拓展规则](../EXTENDING.md#12-岗位与角色)维护并验证。

派单方式与常用命令只维护在[PM手册](project-manager/ROLE.md)。临时执行者同样接收完整协作边界，不靠虚构手册路径补齐。

## 按需运行工作链

普通任务直接派单；只有长期项目组、跨会话恢复或继续已有台账任务时才进入[运行入口](../tools/execution-profiles/role-runtime.md)，遵守原记录，不重复创建。持久台账的实际schema未因此改变，不宣称已支持内联岗位手册。执行者不自行创建或调度其他Agent，交付后默认保留工位供观察，不自动回收。

## 记录与变更

岗位是工作方式，不是Skill，不登记skills.yaml。维护正式岗位时写最小手册，新增默认draft/enabled:false；启用须核对实际能力、工具和最小验证，不因文档改写自动启用。

任务状态和证据留在目标项目或适用的[本机记录](../.local/README.md)，不复制完整会话；真实可复用经验按[最佳实践规范](../best_practices/STANDARD.md)沉淀，不把单次成功直接当成能力验证。身份与个人背景按[个人入口](../personal/README.md)限需读取，不随派单转发私人画像。
