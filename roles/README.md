# 岗位与协作

状态：项目经理负责接单和一层委派；UI、前端、测试已验证独立Tab入组、派单、交付、退组，调研已验证按需实例和记录恢复；架构、通用开发、内容编辑仍为草稿。共用[岗位运行入口](../tools/execution-profiles/role-runtime.md)已可用，没有全员自动开工或权限隔离。验证范围是最小运行链，不代表所有专业任务均已验收。

岗位定义身份职责、必要背景、边界与协作，Skill 定义方法与产物，执行配置定义 Agent 工具与模型，会话承载一次具体工作；它们不互相复制。

## 手册与 Skill 的责任

- 每份岗位手册只保留影响实际工作的必要内容，不编造履历或追求大而全；真实任务暴露缺口后再补充。
- 手册的“工作方法”是本岗位绑定 Skill 的唯一位置：直接引用实际文件，并说明使用条件。多个 Skill 是并列能力，不要求固定一个主 Skill，也不因绑定而全量加载。
- 初始化只读取岗位身份及必要资料，认识方法入口；收到任务后按问题选择一个或多个 Skill，核对登记状态和前置条件后再读正文。执行顺序取决于本次任务依赖，不按表格顺序自动串行。
- 产物、格式和完成要求以本次选用的 Skill 为准，岗位不另设模板、报告或重复清单。多个方法共同完成同一任务时引用已有产物，不为交接另写一份报告。
- 交接只回执产物位置、执行状态和阻塞；执行成员使用任务包的 checkpoint，仅更新自身任务，提交不等于PM验收。没有适用 Skill 时依已确认任务约定处理；缺少方法或产物约定就反馈PM，不在手册临时补造标准。
- Skill 不改变岗位权限、用户授权和一层委派约束。发现冲突时明确指出，调度交PM；无法在边界内执行则返回缺口，不能声称完整执行了该Skill。不得以产物要求为由自动提交、发布、扩大任务或再次委派。
- 共享方法直接引用唯一正文；自研引用 tools 中正文，第三方引用登记对应的 vendor 缓存。文件缺失时报告，不复制维护、不自动安装。绑定不等于已安装或已验证该岗位的专业能力。

## 岗位名册

| 归属 | 岗位 | 何时需要 |

| 统筹 | [项目经理](project-manager/ROLE.md) | 明确目标、分配责任、安排依赖、回收结果 |

| 技术工程组 | [开发](engineering/developer/ROLE.md) | 目标与做法已明确，需要实现软件行为 |
| 技术工程组 | [UI](engineering/ui/ROLE.md) | 需要确定页面布局、交互与关键状态 |
| 技术工程组 | [前端](engineering/frontend/ROLE.md) | 按已确认约定实现前端页面和交互 |
| 技术工程组 | [测试](engineering/tester/ROLE.md) | 需要核验行为，或存在独立验证缺口 |
| 媒体内容组 | [内容编辑](media/editor/ROLE.md) | 从允许使用的素材形成面向读者的内容 |

组只用于归类，不新增组长、审批层级或部门 Agent。岗位长期存在，但会话按需启动；调研等岗位可采用临时会话。一个岗位可有多个任务实例，一个实例的任务范围和状态必须独立。

## 共用岗位约定

- 每个岗位首次初始化时读取本共用约定；已在当前上下文完整读取且未变化时不重复加载。手册frontmatter表示启用状态，draft/enabled:false不得因读取而自动启用；已启用岗位也不自动开工。
- PM由当前负责人担任；执行成员统一引用[执行配置](../tools/execution-profiles/delegation.md)及[岗位运行入口](../tools/execution-profiles/role-runtime.md)，不在各岗位重复绑定模型、启动方式或恢复流程。
- 采用一层委派：项目经理 → 执行岗位。仅项目经理可使用 wl-herdrs 创建子 Agent；执行岗位不得再次委派或切换身份绕过此限制。
- 执行岗位需要其他岗位协助、扩大范围或缺少能力时，返回问题、证据、所需协作及影响，由项目经理决定后续安排。
- 当前负责人可承担项目经理职责，简单任务直接完成，不为凑齐岗位启动实例。此处是职责约束，尚未实现或验证工具级权限隔离。

- 接单至少明确任务标识、目标、非目标、项目/资料位置、已确认依据、允许操作、交付标准与依赖。缺关键条件则退回澄清。
- 能力入口是候选引用，不是授权白名单。只加载本次必要且已核实状态的 Skill，不读取所有岗位手册。
- 岗位配置不能增加工具权限或替代真实授权；隐藏 Skill 不等于阻止终端执行。工具可用不等于已授权使用。
- 项目规则及现有全局授权/委派约束优先。手册中“交接”只描述目标协作方式，未启用前不自动创建 Agent。
- 角色档案不要求成为启动 cwd；执行软件任务必须核对目标项目目录、分支及其规则，不能因在岗位目录启动而漏读。
- 一个会话换身份不构成独立验证。需要独立判断时必须使用满足现有规则的独立执行者。

## 按需运行工作链

固定工位采用“一个项目组成员一个独立 Tab”，不拆分小 pane。项目经理先组队并完成入组就绪，再派具体任务；同需求可多轮派单。交付后默认保留工位供观察，不自动退组。用户明确要求关闭指定成员时才保存摘要并退组；已退组成员不能复活。

开工：项目经理读取名册与能力摘要，核对现有会话，不重复启动；不唤醒全员。

接任务 → 判断结果与缺口 → 按需召集 → 加载岗位/项目/任务信息 → 确认接单 → 按依赖并行或串行 → 提交证据 → 核验/返工 → 记录与恢复。

简单任务允许直接完成；多人参与依据真实贡献或验证缺口，不按任务关键词固定组队。通过运行入口登记身份、检查点与恢复摘要；先读未完成任务再决定是否派单，不把闲置实例当作已验收任务。

## 记录与变更

在接单、重要交接/阻塞和交付状态变化时，按下方记录约定保存必要摘要及项目证据指针，不复制日志或完整会话，不把本机索引当作项目事实来源。

记录约定见 [本机记录说明](../.local/README.md)，个人资料见 [个人入口](../personal/README.md)，执行配置见 [执行配置说明](../tools/execution-profiles/README.md)。新增岗位先说明独立职责；前端、后端、UI、数据库等按实际需要扩展，不预设必须拆分。

岗位是工作方式，不是 Skill，不使用 SKILL.md 或登记为已验证能力。修改手册后仍不自动启用；启用需另行确认实际能力配置、工具支持和最小验证。

需要解决新问题时先查 [最佳实践记录](../best_practices/README.md)。执行岗位识别值得保留的真实尝试与证据，项目经理/当前任务负责人核对同题和事实，再按 [统一规范](../best_practices/STANDARD.md)沉淀；不是每次任务都建案例，不把一次成功直接升级成 Skill。进度留工作记录，方法与失败路径留最佳实践。
