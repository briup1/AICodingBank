# 已有项目的现状与改动分析

先确认目标项目、需求和工作副本，遵循项目自己的入口。按要回答的问题选择深度，不按仓库年龄启动整套流程。

- **只查现状或局部影响**：从一个具体用户操作出发，沿入口、调用方和现有测试查证。答清当前行为、受影响的位置、证据与未知就停。无需先找竞品、补写 PRD 或召集多个角色。
- **已有 PRD，需要完整需求分析**：优先读本次需求正文，区分预期与当前实现。需要核对跨端差距、需求漏洞、影响面和验收时，可选用 `sun-requirement-analysis`。本机来源见 `本机资料/需求分析技能.local.md`；索引缺失或文件不可读时报告缺项，不猜地址。正式分析须具备可读的 PRD；按原方法需真实的前端、后端、测试角色交叉讨论，产出规格与计划，涉及页面还需逐页说明。不能用单人走查冒充完整执行。
- **还在决定功能值不值得做**：即使是在老项目里，也走[新产品与新功能调研](新产品与新功能调研.md)。

例：「这版审批改动会不会影响旧单？」先查旧单当前走哪条规则及其测试；若还要按新版 PRD 给出完整改动与验收方案，再进入正式需求分析。

导出包中的项目约定和数据库授权不跨项目继承；按当次授权使用工具，不因选择分析而启动编码、查库或发布。
