# 工单执行（wl_ticket-run）

开发流程的第三阶段。目标：方案批准之后，把活拆成工单，自动执行到验收，中途不无故停下问人。

**前置条件**：`design.md` 状态为 `approved`，且多方案场景下用户已选定方案（`chosen`）。

## 第一步：拆工单

产出 `docs/requirements/NNNN-slug/tickets/NN-xxx.md`，一单一文件。

**拆单规则：**

- **垂直切片**（tracer bullet）：每张工单贯穿全部层（如后端查询→接口，或页面→调真接口），做完即可独立验证。禁止按层横切（"先写完全部后端"这类工单是禁止的）
- 每张工单声明 **blocking edges**（被哪些工单阻塞）；无阻塞者可立即开工
- 每张工单注明**"本工单不含什么"**，防范围蔓延
- 大小：一张工单能装进一个全新上下文窗口
- **宽重构例外**：一处改动波及全库的重构不做垂直切片，走 expand–migrate–contract（先新旧并存 → 分批迁移（每批一张工单）→ 最后删旧形态）

**验收标准用 G/W/T**（Given/When/Then）——它同时是完工审计员的核对清单，必须无歧义、可机器或肉眼验证：

```
- [ ] Given <前置状态>, When <动作>, Then <可观察结果>
```

技巧：需求里的约束也要变成验收项。例：需求要求"不影响运行链路" → 验收项"Given 任意请求, When 统计接口执行, Then 运行链路代码与表结构未被改动（git diff 证明）"；Out of Scope 清单 → 末张工单的"无越界功能"验收项。

**拆完后向用户确认粒度再开工**（太粗/太细/该合并/该再拆）。

## 第二步：并行调度

- 工单进 `/list` 池；**跨工单并行**（阻塞者全完成的工单即可认领）
- **工单内串行**——多个实现者同时改同一工单必然冲突，禁止
- 审查层可并行（多个审查视角同时跑）

## 第三步：单工单执行（每张工单一个 /goal）

goal 的目标文本 = 工单内容；验收契约 = 工单的 G/W/T 清单。**强制审计**：完工时审计员逐条核对 G/W/T，防虚报完工。

执行纪律（裁剪版 Superpowers）：

1. **台账**：工单目录下 `progress.md`，做完一件事记一行（含 commit 号）。上下文压缩后信台账和 git log，不信自己的记忆
2. **熔断**：同一问题连续修 3 次不过，强制暂停上报——不许无限重试烧 token
3. **停机**：只允许四类原因停下问人——不可逆操作、安全敏感动作、仓库外的副作用、计划烂到每条路都是猜。其余歧义自己做主，把决定记进台账（`Ruling: 决定了什么 — 为什么 — 错了的代价`），继续干
4. 小任务同形状的批量修改合并成一次派发，不要一任务一子 agent

## 第四步：收尾

- 声称完成前：实际运行验证命令，把输出贴出来（禁止"应该过了"）
- 跑全量测试
- 合并前过 code review
- 全部工单完成后：需求文档状态置为 `done`，回写总览

## 禁止事项

- 跳过 G/W/T 直接开工
- 工单内并行实现
- 无台账执行长工单
- 熔断后继续重试
- 虚报完工（说"完成"但没有验证输出）
