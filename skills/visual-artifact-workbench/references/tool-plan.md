# 个人可视化文档工具统一方案

本文是完整工具的建设设计；目前仅有白名单只读服务辅助脚本，实际操作见 [分享操作](sharing-operations.md)，其余能力不视为已实现。通用行为规则以 [SKILL.md](../SKILL.md) 为准；项目业务事实不进入此方案。

## 分类结论与现有能力衔接

这类任务属于**本机个人工具使用 / 跨项目文档交付**，不是任何一个业务项目的功能，也不是另建完整协作平台的理由。

- 工作台已有 Skill 登记、验证、目录与安装机制：继续用 skills.yaml、CATALOG.md、install.py，不增加第二套能力注册中心。
- 已登记的 diagram、excalidraw-diagram-generator 等能力负责绘图，各有产物边界；是否可加载仍取决于验证与实际安装状态。它们不替代证据映射、审核版本或分享生命周期管理。
- 优先复用实际可用的 HTML 制作能力；本策略是其上层工作规则，不复制实现或强制安装另一款绘图工具。
- WORKBENCH.local.md 只放个人选择和配置入口，不保存业务内容、动态 IP、在线状态或审核进度。

## 一条跨项目链路

```text
项目原文和既有工作稿
    → 选择合适的图 / 页面
    → 建立路径、证据与版本
    → 在项目内验证
    → 显式选择分享文件
    → 统一发布目录 + 文档入口
    → 审核者查看 / 导出意见
    → 人确认修改，回填项目原文
    → 发布新版，受影响路径重新审核
```

图的业务分类按各项目决定；复用的是编号、证据、交互、验证和发布机制，不是固定业务分类模板。

## 分清三类位置

| 位置 | 唯一职责 | 不应存放 |
| --- | --- | --- |
| AICodingBank 的 Skill 目录 | 统一策略；将来实际实现的模板或确定性工具 | 公司需求正文、私密截图、发布副本 |
| 本机工具配置和运行目录（实施时确定） | 发布位置、监听配置、运行标识、索引及发布副本 | 业务源码库整体镜像、密钥的副本 |
| 各项目原有文档目录 | 原文、可视工作稿、项目审核证据 | 复制的服务器或工具安装配置 |

实际分享任务先发现本机已有配置和发布目录；没有时在分享授权范围内确定一个本机统一位置，不能每个项目另建服务。工作台个人上下文记录配置文件指针，不复制其内容或运行状态。

## 完整工具能力边界

下表是完整能力目标，不是可以直接执行的命令；当前 `serve.py` 只提供白名单文件服务、状态检查和停止，发布登记与撤下仍需人工核对文件和配置：

| 动作 | 最小行为 |
| --- | --- |
| 校验 | 检查显式文件清单、资源依赖、编号与证据，报告未执行的浏览器检查 |
| 发布 | 从批准的文件清单创建独立版本，校验内容哈希；成功后才更新当前版本入口 |
| 列表 / 打开 | 显示已登记文档和已发布版本，不扫描并展示整个工作区 |
| 状态 / 启停 | 管理同一个工具实例；从真实进程与监听判断状态，不凭旧记录猜测 |
| 撤下 | 移除指定在线入口与约定发布副本，不删除项目原文；历史保留策略单独确定 |

发布项最少关联：项目标识、文档标识、标题、发布版本、发布时间、所选文件及哈希、原文版本/哈希。稳定标识不以可能变化的本机绝对路径代替。

工作区路径和配置定位只供本地管理使用，不写入给同事看的首页。统一首页仅展示已批准共享的项目/文档元信息。

## 页面和记录契约

- 页面展示文档标题、发布版本和来源版本，避免多人审核时谈论不同副本却不自知。
- 相同规则路径保留 ID；改变判断条件、公式、结果或证据有效性时，更新路径规则版本并记录影响范围。
- 审核记录至少绑定“文档 + 发布版本 + 路径 ID + 路径规则版本”，并包含审核状态、备注和记录时间。
- 本地模式：每人各自记录并导出，不能显示虚假的实时协作状态；版本变化后保留旧意见，但须明确复核才可带入新版本。
- 在线收集是后续能力：需先设计身份、访问权限、修改冲突、审计、备份与保留期限。不能仅把 localStorage 换成接口便宣称完成多人审核。

## 分阶段建设，不一次做成平台

### 阶段一：统一个人使用方法

基础落点是策略、入口与登记；只读分享辅助脚本不等于完整发布工具已经建成。用既有文档对照分类、证据和版本规则；保持 verified 为空，直到新 Skill 在目标场景真实验证通过。

### 阶段二：最小本机发布工具

用户明确要求建设后，再实现一套共用工具及少量模板。先完成单机预览、受控发布、首页、版本、启停和撤下。使用本机现有工具链，具体服务技术和参数现场核实；不在本文预定某个软件、固定端口或硬编码 IP。

局域网分享应在完成文件范围检查、访问范围确认和必要访问控制后开启。个人电脑只是初期承载位置；长期团队共享可以另行评估固定内网主机，不自动升级为团队基础设施项目。

### 阶段三：确有需要再增加在线审核

多个审核者确实需要共同记录、状态同步或长期历史时再设计服务端。账号、数据库、评论流和自动回填不属于前两阶段的默认范围。

## 正式启用前的最小验收

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 两个不同项目接入 | 只新增文档内容和登记，不复制工具、不额外起第二套服务 |
| 同名文档跨项目发布 | 地址、版本与审核记录不冲突 |
| 修改草稿 | 已发布页面不变；显式发布才切换入口 |
| 发布失败 | 不损坏旧版，不产生指向半成品的当前入口 |
| 规则实质改变 | 受影响路径待重审，旧记录可追溯；不能沿用旧批准 |
| 浏览器/地址迁移 | 能说明审核记录的迁移方式与限制，不承诺自动同步 |
| 请求未发布文件或越界路径 | 无法访问仓库、个人配置、软链接目标或清单外文件 |
| 第二台局域网设备访问 | 实测能打开目标版本；仅本机访问成功不算局域网验收 |
| 停止 / 撤下 | 仅影响本工具或指定文档；其他项目服务和源文件不受影响 |

未完成的场景注明未验证。结构检查和安装器测试只能证明登记与控制面行为，不能填补分享端到端验证。
