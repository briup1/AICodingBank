# 测试用例生成

这是 `softaworks/agent-toolkit` 的 `qa-test-planner` 的个人精简策略入口，不是上游改名副本。只复用上游测试用例模板，不加载整个 QA 工作流。

## 来源与按需加载

- 上游：https://github.com/softaworks/agent-toolkit/tree/main/skills/qa-test-planner
- 上游登记：工作台根目录 `skills-lock.json` 中的 `qa-test-planner`。
- 模板：`../../vendor/softaworks__agent-toolkit/skills/qa-test-planner/references/test_case_templates.md`（相对本 Skill 目录）。
- 生成前只读取模板中与本次需求相关的章节；按下述范围和字段生成，不照搬整个上游计划。
- 模板缺失时明确说明，使用下方最小格式继续，不声称已读取上游。不要自动安装依赖或同步仓库。
- 不加载上游 `SKILL.md`、Bug/Figma/回归指南，不调用上游脚本；不依赖其他 Skill。

## 输入与范围

需要需求或用户故事、验收标准，以及已提供的角色、环境、数据限制。可以接收界面说明、接口契约和已有用例。

只覆盖本次需求及直接受影响的最小回归路径。只追问会改变测试步骤或通过条件的关键问题；其他缺口明确标为待确认。不得编造金额、状态码、接口路径、时限、权限规则或页面行为。

## 执行链路

1. 列出已确认需求与测试范围。沿用原始需求 ID；没有 ID 时分配 R-001 等标签并附原文摘要。区分事实与假设。
2. 按实际规则拆分正向、异常、边界和状态变化场景；适用时采用等价类、边界值。规则未知的边界值标为待确认。
3. 按业务影响设置 P0/P1/P2；相同触发条件、动作和预期的场景合并，数据差异可参数化。不要凑用例数量。
4. 为每个场景写出前置条件、具体测试数据、逐步操作和可观察、可判定的逐步预期。需要恢复数据时注明清理要求，不实际执行写操作。
5. 对照每条需求检查覆盖和遗漏；直接影响的旧行为只保留必要回归用例。未知预期标为阻塞/待确认，不写成确定事实。

## 默认输出

使用中文 Markdown，用户指定其他格式时按要求输出。不新装导出工具。

### 1. 范围与依据

列出本次覆盖、不覆盖、需求标签与已确认资料。附需求正文链接及版本、用例基线版本；需求 HTML 可只放本用例文档的整体链接，不要求逐条双向对应。具体数据、操作和预期在本用例文档只维护一次；已有历史 AC 可原位引用，不再复制 AC/TC 两份正文。

### 2. 测试用例

按业务部分分组（如 A：查询、B：导出），组内每条仍使用以下格式；不按技术层或优先级替代业务分组。

```markdown
### TC-001：用例标题
- Trace：R-001
- 优先级：P0/P1/P2（简述原因）
- 前置条件：角色、状态、环境
- 测试数据：具体输入；未知项明确待确认

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 具体动作 | 可观察且可判定的结果 |

- 后置条件/清理：适用时填写
- 状态：未执行 / 待确认（附原因）
```

### 3. 覆盖与缺口

列出 `需求 → 用例 ID → 正向/异常/边界或不适用原因`，以及未覆盖项、假设和待确认问题。按 Trace 反查 `用例 → 需求/直接回归依据` 防越界，操作和预期是否可执行、重复场景是否合并仍按原有五步自检。

交接时注明用例基线版本、整体链接、待确认项及审查/确认状态；生成不等于独立审查、人工确认或执行通过。独立审查调度与规则变更回流由调用方负责，不作为本 Skill 的新增生成步骤，也不依赖总流程私有文件。

## 交付自检与停止

- 每条用例能追踪到需求或直接回归依据，有优先级、数据、步骤和明确预期。
- 已考虑相关正向、异常、边界；不适用或信息缺失时说明原因。
- 没有重复场景，没有把未执行用例写成通过，没有用猜测填补业务规则。
- 不输出测试排期、发布门禁、Bug 报告、Figma 对照或自动化代码；不执行测试、脚本或业务写操作。
- 用例与缺口交付后停止。需要实际执行或其他能力时另按用户请求处理。
