# 专家评审技能

> 状态：草案（待人工确认）

## 概述
重大变更（新领域、核心链路改造、并发/资金相关）在代码审查之上再加一层的深度评审。

## 触发条件
- 用户明确要求评审；或变更触及核心链路（{待填：如订单、支付、库存}）；或引入新技术/新中间件。

## 评审重点

### 1. 领域驱动设计（DDD）符合度
- 领域边界是否清晰？跨域调用是否走了明确接口？
- 命名与 `wiki/领域术语.md` 是否一致？

### 2. 并发与一致性
- 并发场景：幂等、防重、乐观锁/悲观锁选择是否恰当？
- 分布式一致性：缓存与 DB 的一致性策略、消息最终一致性是否成立？

### 3. 扩展性考量
- 本次方案三个月后最可能怎么变？变更成本是否可接受？
- 有没有"为了不存在的需求"做的过度设计？（有就删掉）

### 4. 技术债评估
- 本次变更是还债还是欠债？欠债必须显式记录并给出偿还路径。

## 输出
- 评审意见：阻断性问题 / 建议改进 / 认可通过，附理由。
