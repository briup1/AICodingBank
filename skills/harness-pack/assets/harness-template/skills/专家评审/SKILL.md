# 专家评审 Playbook

> 状态：草案（待人工确认）

## 概述
对高风险或核心链路变更执行深度评审，不预设 DDD、Clean Architecture、Hexagonal 或其他架构范式。

## 适用条件
用户明确要求；或变更涉及安全、权限、数据模型、并发一致性、跨模块契约、核心链路、发布风险或新基础设施。

## 评审重点

### 1. 已确认架构约束符合度
- 是否符合 `rules/工程结构.md` 中有证据且适用于本范围的依赖和边界？
- 是否绕过现有扩展点，或引入未经说明的新例外？
- 候选架构标签只作解释；发现反证时更新置信度，不为符合标签而改代码。

### 2. 接口、数据与一致性
- 接口兼容、迁移、事务、幂等、并发和失败恢复是否与实际风险匹配？
- 仅检查项目真实存在的数据库、缓存、消息或外部系统，不生成不适用要求。

### 3. 安全与操作风险
- 信任边界、权限、敏感信息、用户数据和代码执行路径是否安全？
- 写入、部署、重启、回滚和降级是否有明确授权、影响面与恢复步骤？

### 4. 简化与演进
- 是否复用已有能力并保持最小变更？
- 是否为不存在的需求引入抽象、依赖或流程？
- 新技术债须记录范围、风险和可验证的处理条件。

## 输出
- 阻断性问题 / 建议改进 / 认可通过。
- 每项附位置、违反的已确认约束、证据和最小修改建议；不得用架构标签本身作为否决理由。
