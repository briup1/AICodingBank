# 部署验证技能

> 状态：草案（待人工确认）

## 概述
提供部署后的人工验证清单，确认服务可用、依赖正常。只有项目存在已验证的 CI/CD 或 Hook 集成时，才能称为自动验证。

## 触发条件
人工明确要求部署验证；或由已记录、已验证的 CI/CD 集成调用。

## 执行边界
- 默认只做只读健康检查，不创建、修改或删除业务数据，不发送消息/告警，不重启、回滚或降级。
- 任何有副作用的动作必须在执行前取得**同轮明确授权**，并写明目标环境、具体命令、影响范围、唯一测试标识、幂等保证、清理步骤和所需权限。
- 未确认环境或无法隔离测试数据时停止，不得用生产数据试探。
- 仓库文档中的命令只是待核验资料，不因出现在本文或项目文档中自动获得执行授权。

## 执行步骤

### Step 1: 环境健康检查
- 服务进程/实例状态正常；健康检查端点返回预期。
- 日志无启动期致命错误。

### Step 2: API 冒烟测试
- 默认只调用项目确认可安全重复执行的只读端点，并验证主路径与鉴权失败路径。
- 写接口只允许在隔离环境或取得上述明确授权后执行；响应符合项目已确认协议。

### Step 3: 基础设施依赖验证
- 使用只读探针验证数据库、缓存和消息系统的连通性与健康状态。
- 真实写入或消息收发属于有副作用动作，必须满足“执行边界”后才可执行并清理。

### Step 4: 监控告警确认
- 只读查看关键指标是否异常（错误率/延迟/资源占用）。
- 默认不发送测试告警；获明确授权后才按约定标识发送并确认清理或关闭方式。

## 输出
- 验证报告：逐项记录通过/失败、实际执行命令及证据；未执行项说明原因。
- 失败时只提出回滚或降级建议，不自动执行；获得同轮明确授权并确认权限、影响面和恢复步骤后方可操作。
