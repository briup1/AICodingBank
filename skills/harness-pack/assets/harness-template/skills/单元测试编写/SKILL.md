# 测试编写 Playbook

> 状态：草案（待人工确认）

## 概述
为本次行为留下最小、可重复且能发现回归的检查；测试类型和工具以项目现状为准。

## 适用条件
变更包含可验证行为时由人或已验证调度器选用。纯文档或已有检查充分覆盖的变更可以说明理由后不新增测试。

## 执行步骤

1. **确定风险**：列出主路径、边界、错误路径和受影响调用方；缺陷优先建立能复现问题的检查。
2. **选择最小层级**：复用项目已有单元、集成、契约或端到端测试方式，不为模板引入新框架。
3. **隔离副作用**：使用项目已有 fixture、临时目录或测试替身；不使用生产数据，不访问未授权外部环境。
4. **写有效断言**：断言可观察行为而非实现细节；避免 sleep、共享可变状态和只为覆盖率存在的断言。
5. **执行验证**：运行相关测试及必要的全量回归，记录实际命令、结果和未覆盖风险。

## 输出

- 新增或更新的测试。
- 失败复现与修复后结果（适用于缺陷）。
- 未覆盖边界及理由。
