# 编码实现技能

> 状态：草案（待人工确认）

## 概述
按标准流程实现功能编码，确保架构合规、红线零违反。

## 触发条件
需求分析已确认、进入编码阶段时激活。

## 前置条件
- 已读 `CLAUDE.md`（红线）与 `rules/` 相关章节。
- 已读本次任务相关的 `wiki/`（业务模型/接口协议/数据模型）。

## 后端编码步骤（顺序执行）

### Step 1: Model
- 定义/修改实体、DTO、VO；金额等敏感字段按红线处理。

### Step 2: Repository
- 数据访问接口与查询实现；查询注意索引与分页。

### Step 3: Service
- 业务逻辑 + 事务（显式回滚范围）；异常封装为业务异常体系。

### Step 4: MQ（如涉及）
- 生产者：Topic 命名规范、traceId、失败处理。
- 消费者：幂等判重后再处理。

### Step 5: Controller
- 路由 + 参数校验 + 统一响应结构；禁止业务逻辑。

### Step 6: 异常与日志
- 边界条件全覆盖；日志带 traceId，关键操作可审计。

## 前端编码步骤（顺序执行）

### Step 1: API 定义
- 按 `wiki/接口协议.md` 在 API 层新增封装，类型对齐响应结构。

### Step 2: 类型定义
- `types/` 中定义请求/响应类型。

### Step 3: 组件实现
- 页面组件组装子组件；业务逻辑下沉 composables/stores；遵守语法红线。

### Step 4: 测试与验证
- 自测主路径 + 错误路径；准备单元测试素材。

## 输出
- 代码 + 自测记录 + 对 wiki/rules 的疑似更新点（交给 harness-sync）。
