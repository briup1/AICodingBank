# 代码审查 Playbook

> 状态：草案（待人工确认）

## 概述
按本次变更范围审查已确认规范、正确性和可维护性；存量债务只阻断新增或扩大。

## 适用条件
代码完成、提交或提 PR 前，由人或已验证的调度器选用；仅在项目存在已验证 Hook/CI 时才构成自动门禁。

## 审查维度

### 1. 阻断项
- 检查本次新增代码是否违反适用范围内的**已确认规范**，尤其安全、权限、数据完整性和接口兼容要求。
- 提议不作为阻断项；事实只用于核对行为；技术债按稳定基线检查是否新增或扩大。
- 每个阻断项必须给出规则 ID、代码位置和验证证据，不能用架构标签或模板示例直接否决。

### 2. 正确性与影响面
- 验收标准、调用方、边界条件、错误路径、并发和迁移是否完整。
- 是否复用已有扩展点，是否引入跨模块耦合或与现有契约冲突。

### 3. 简化与质量
- 删除重复、无用抽象、死代码和无依据配置。
- 执行项目真实存在且与变更相关的测试、lint、类型检查或构建命令；未执行项说明原因。

## 输出
- 通过 / 阻断 / 建议。
- 每项包含位置、规则或需求来源、证据和最小修改建议。
