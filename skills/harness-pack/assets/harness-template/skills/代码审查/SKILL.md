# 代码审查技能

> 状态：草案（待人工确认）

## 概述
提交前的强制自查/互查，三个维度：红线、规范、坏味道。

## 触发条件
代码完成、提交或提 PR 前自动激活。

## 审查维度

### 1. 安全红线检查（一票否决）
- 逐条对照项目根 `CLAUDE.md` 红线：金额精度、缓存键前缀、消息幂等、异常封装、依赖注入、事务回滚、前端语法、响应结构。
- 任何一条违反 → 打回，不进入下一维度。

### 2. 性能与规范检查
- 对照 `rules/编码规范.md`：命名、空值、魔法值、SQL 索引、缓存 TTL、MQ traceId。
- API 响应结构是否与 `wiki/接口协议.md` 一致。

### 3. 代码坏味道检查
- 重复代码、超长函数、深层嵌套、注释掉的死代码、模糊命名。
- 发现坏味道优先简化，而不是加注释解释。

## 输出
- 审查结论：通过 / 打回（附问题清单：位置 + 违反条款 + 修改建议）。
