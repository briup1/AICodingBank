# changes/ — Harness 变更证据

仅当规范体系发生实际增量时创建记录：

```text
NNNN-YYYYMMDD-<主题>.md
```

每条记录至少包含：

```markdown
# <主题>

## 同步基准
- 日期：<ISO 日期时间与时区>
- 触发来源：<任务/需求>
- 分支：<branch>
- base_ref：<完整提交 SHA>
- head_ref：<完整提交 SHA>
- tracked_diff_sha256：<无未提交改动则写 clean>
- untracked_paths：<仅列路径；无则写 none>

## 补丁与裁决
| 规则/条目 ID | 唯一事实源 | 类型 | 变更 | 作用范围 | 裁决与理由 |
|--------------|------------|------|------|----------|------------|

## 验证
- 命令/检查：<实际执行>
- 结果：<通过/失败及证据>
- 残余风险：<无则写 none>
```

规则：

- `base_ref` 与 `head_ref` 必须可解析且能重现本次检查范围；基准不明确时不得同步。
- 同一规则只在唯一事实源定义，记录中使用稳定 ID 引用。
- 提议不得伪装为已确认规范；存量技术债须记录基线及是否扩大。
- 空同步不创建记录。记录与批准的文档补丁必须一同通过校验，避免半同步状态。

第一条记录由 bootstrap 启用时创建：`0001-YYYYMMDD-初始化-harness.md`。
