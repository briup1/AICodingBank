# 开发流程规范

> 状态：草案（待人工确认）
> 流程按变更风险选择；Markdown 只描述 playbook，不自动获得审批或执行能力。

## 1. 风险分级

| 等级 | 典型影响 | 最小流程 |
|------|----------|----------|
| 低 | 文档、注释、局部无行为变更 | 读取相关规则 → 修改 → 最小验证 |
| 中 | 单模块行为、接口实现、常规缺陷 | 影响分析 → 测试/复现 → 实现 → 审查 → 验证 |
| 高 | 安全、权限、数据模型、跨模块契约、发布或不可逆操作 | 需求确认 → 方案与回滚评审 → 实现 → 独立审查 → 完整验证 → 明确发布授权 |

风险示例只作路由参考；以实际影响面、可逆性和项目约束为准。

## 2. 需求与方案

- 明确验收标准、影响模块、接口/数据契约、风险和不做什么。
- 先查项目已有扩展点与实现模式；实现顺序依据 `rules/工程结构.md` 中已确认的依赖图，不使用固定技术栈顺序。
- 未实现设计只能标为提议，不得写成当前事实。

## 3. 实现与评审

- 使用 `skills/编码实现/SKILL.md`；缺陷先留下可复现检查。
- 使用 `skills/代码审查/SKILL.md` 检查本次新增违反和存量债务是否扩大。
- 高风险变更再使用 `skills/专家评审/SKILL.md`，评审已确认项目架构、安全、数据、一致性和回滚约束；不固定评审 DDD 或其他模式。

## 4. 测试与自动化

- 执行项目已记录且与变更相关的最小测试、静态检查和构建命令。
- `skills/单元测试CI/SKILL.md` 默认是人工 playbook；只有存在已验证 CI 配置时才称为强制门禁。
- 覆盖率、性能等阈值必须来自项目证据或用户决策；未接入测量工具时不得宣称数字门禁生效。

## 5. 部署与高风险动作

- 使用 `skills/部署验证/SKILL.md`，默认只读验证。
- 数据写入、消息/告警、重启、回滚或降级必须取得同轮明确授权，并确认环境、影响面、清理和恢复步骤。

## 6. 收尾与同步

- 仅当本次变更产生了新的稳定事实、已确认决策、接口/数据变更或债务基线变化时执行 `harness-sync`。
- 没有规范增量时记录“无需同步”即可，不强制创建 changes 条目。
