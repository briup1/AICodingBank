# 编码规范

> 状态：草案（待人工确认）
> 本文件是 AI 生成代码的评判标准；项目根 `CLAUDE.md` 红线的细则在这里展开。

## 一、通用规范

### 1. 命名规范
- 类/接口：大驼峰；函数/方法：小驼峰；常量：全大写下划线；数据库表/字段：小写下划线。
- 命名必须来自 `wiki/领域术语.md`，禁止自造同义词。

### 2. 代码格式
- 遵循项目已配置的 formatter（{待填}），提交前必须格式化。
- 单函数不超过 {待填} 行，超过即考虑拆分。

### 3. 魔法值
- 禁止裸写魔法数字/字符串；必须提取为有名常量或枚举，并说明业务含义。

### 4. 空值处理
- 入参在信任边界（API 入口、外部数据）必须校验；空值有明确的失败或降级路径，禁止静默吞掉。

## 二、后端规范（{后端技术栈}）

### 1. Controller 层
- 只做路由、参数校验、调用 Service、构造响应；**禁止业务逻辑**。
- API 响应必须遵循 `{code, message, data}` 统一结构。

### 2. Service 层
- 业务逻辑唯一归属地；事务在此层控制，必须显式声明回滚范围。
- 禁止反向依赖 Controller / 直接持有 HTTP 上下文。

### 3. 异常处理
- 一律封装为业务异常体系（{待填具体类名}）；禁止底层异常透出到 API 层。
- 异常信息面向用户要友好，面向排查要带上下文（traceId/关键参数）。

### 4. 数据访问
- 数据库字段与实体一一对应；金额等精度敏感字段按红线处理。
- 查询必须走索引意识：列表查询禁止全表扫描，大数据量分页。

### 5. 中间件规范

#### 缓存（{缓存组件}）
- Key 统一前缀 `{前缀}:`，结构 `{前缀}:{模块}:{业务}:{标识}`。
- **必须设置 TTL**，禁止永久 Key。
- 缓存更新策略：先写数据库，再删缓存。
- 禁止危险命令（如 `KEYS *`），扫描用 `SCAN` 类命令。
- 序列化使用 {待填}，禁止 JDK 原生序列化。

#### 消息队列（{MQ 组件}）
- 消费者**必须幂等**：以业务唯一键判重，处理过即跳过。
- 消息体必须携带 `traceId` 用于链路追踪。
- Topic/队列命名：`{前缀}-{模块}-{事件}`。
- 生产者必须处理发送失败（重试或落盘记录）。

## 三、前端规范（{前端技术栈}）

### 1. 语法规范
- 必须使用项目选定语法（{待填}），禁止混用旧式写法。

### 2. API 层
- 所有请求走统一封装：处理鉴权头、错误码、loading/错误提示。
- 响应类型必须与 `wiki/接口协议.md` 的结构对齐。

### 3. 组件规范
- 组件单一职责；页面组件组装子组件，业务逻辑下沉到 composables/stores。
- props 必须声明类型；跨组件通信禁止乱用全局事件总线。

### 4. 样式规范
- 全局样式集中管理；组件样式隔离，禁止污染全局。
- 尺寸/颜色用项目设计变量，禁止散写硬编码色值。

## 四、测试规范（与 skills/单元测试编写 联动）
- 新功能必须带单元测试；修复 bug 先写复现测试。
- Mock 外部依赖（DB/缓存/第三方接口），测试可重复、无环境依赖。
