# 编码规范

> 状态：草案（待人工确认）
> 目标：指导当前项目中的新增和修改代码。正文按真实语言、运行单元和模块组织；配置事实与样本统计放在末尾依据表。

## 1. 规则强度

- **已确认规范**：必须遵守；来源是项目指令、自动门禁或用户明确批准。
- **默认实践**：从稳定实现和既有扩展点归纳；新增代码默认遵循，确需偏离时说明理由和影响。
- **事实/技术债/提议**：分别描述现状、存量违反和待决策方案，不冒充开发门禁。

## 4. 接口与协议实现

- 新增或修改接口时同步 `wiki/接口协议*` 与权威 schema/文档。
- 调用方、提供方、请求/响应、错误、安全、副作用、兼容和测试必须成套修改。
- 生成代码只通过项目既有生成流程更新；手写边界以项目证据为准。
- 事件、消息或流式协议必须写明方向、顺序、关联 ID、路由键和迟到/重复处理。

## 5. 测试代码规范

- 缺陷先留下稳定失败复现；新行为先明确可执行验收。
- 优先扩展共享 fixture、fake、builder 和测试 helper，不复制协议样本。
- 断言可观察行为和边界，不绑定无关实现细节。
- 覆盖与变更最近的错误、并发、权限、清理或断线场景；不使用未授权外部环境或生产数据。
