# 新项目 Harness 正向生成

## 概述

与逆向生成的本质区别：**新项目没有代码可观察，每一层内容都来自"提问→用户决策"**。红线只能来自用户点头，AI 的职责是提供参照选项，不是替用户决定。

先完整读取共享参考（相对本文件：`../../references/`）：

- [shared-protocol.md](../../references/shared-protocol.md)：输出位置、信息类型、双确认、启用动作；
- [content-standard.md](../../references/content-standard.md)：各类文档的内容深度和任务型验收。

## 执行流程

### Step 1：需求解析与目标检查
读原始需求（文档/口述/票据），输出一页纸理解：业务目标、用户角色、核心流程、边界假设。**先与用户确认理解无误再往下。**
**护栏**：若 `<项目根>/docs/harness/` 已存在，停下问用户：覆盖重来 / 在现有基础上合并 / 改走 harness-sync 增量更新——不得静默覆盖（会毁掉 changes/ 历史和 sync 沉淀）。

### Step 2：分层提问（核心步骤）
按以下顺序逐层提问，每层给出参照模板里的选项 + 推荐及理由，让用户选或改：

| 层 | 要问什么 | 输出物 |
|----|----------|--------|
| 技术栈 | 语言/框架/存储/中间件，及其选型理由 | CLAUDE.md 技术栈表 |
| 模块边界 | 计划职责、依赖方向、运行时协作、扩展点和常见变更落点；不强求标准架构名称 | rules/工程结构.md |
| 强约束候选 | 只询问安全、数据完整性、接口兼容等当前项目适用的约束；不按技术栈出示案例红线 | 根入口的规则索引 |
| 编码规范 | 各语言/模块的落点、默认实现、错误/并发/清理、formatter/lint/type/test 和有依据的阈值 | rules/编码规范.md |
| 业务知识 | 核心能力、术语、数据/状态所有权及主路径；只有用户明确采用领域建模时才使用“领域”标签 | 适用的 wiki 文件 |
| 接口契约 | 每个拟公开接口/消息的请求、响应、错误、安全、副作用、兼容与验证 | wiki/接口协议.md 或子目录 |
| 流程 | 按风险分级的评审、测试、部署与授权边界 | rules/开发流程规范.md |

原则：**一次问一层**，用户答完再进下一层。只问当前项目适用并影响实施的事项；用户说“你定”时，AI 建议仍标为提议，不因推荐而成为门禁。不存在的缓存、消息、数据库、REST、分支或部署能力不提问、不生成。

### Step 3：生成草案
以 `../../assets/harness-template/` 为可删减菜单，按 content-standard 生成能指导实现的工程手册：结构包含模块内部导航、协作链路和变更地图；编码规范按模块描述具体写法；Wiki 连接能力、接口、状态、术语和验证。提议和待决策不进入门禁；安全、权限、数据破坏、发布和回滚类关键决策未解决时，相关流程保持禁用。

无代码时，已确认的目标契约标 `proposed`，可以写完整设计，但不能声称已有实现或测试。`stack-variants.md` 只用于发现需要确认的问题，不提供默认分层、响应结构或架构标签。删除不适用章节。草案文件头部标注：`> 状态：草案（待人工确认）`。
注意：宪法 CLAUDE.md 的草案稿写入 `docs/harness/CLAUDE.md` 暂存，**确认通过前不动项目根**；启用时才融合进项目根（见 shared-protocol「宪法文件的位置与融合规则」）。

### Step 4：生成后自检
按 shared-protocol 与 content-standard 检查用户决策完整性、接口/状态设计闭合、内部一致性、引用、能力声明、模板残留和三类任务静态推演。没有代码时不得执行或声称完成实体、接口、表、枚举等事实反查。

### Step 5：双确认
按 shared-protocol：先呈结构（文件清单+技术栈+红线清单+自检结果），再逐文件走查。重点核对：红线是否为 Step 2 用户亲口确认的版本。

### Step 6：启用
按 shared-protocol：宪法融合落位到项目根 CLAUDE.md（已有则融合不覆盖）、去草案标识、写 changes/0001 变更记录。

## 边界

- 只生成 `docs/harness/` 规范体系；**不生成业务代码、不搭脚手架**（用户另下指令再说）。
- 需求信息不足时问，不猜；用户拒绝回答的项标为不参与门禁的待决策。只有其直接影响安全、数据或不可逆操作时才阻塞对应工作。
- 项目实际已有代码（哪怕一点点），说明这是"老项目伪装成新项目"，改走 harness-bootstrap-legacy。
- 模板（`../../assets/`）或共享 references（`../../references/`）**缺失或不可读时，立即停下报告用户**，禁止即兴编造生成物结构。
