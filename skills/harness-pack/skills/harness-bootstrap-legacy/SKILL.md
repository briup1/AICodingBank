# 老项目 Harness 逆向生成

## 概述

把老项目**已经存在的事实**（技术栈、结构、惯例）反推成一套 `docs/harness/` 规范体系，让 AI 从此按规范作业。核心是"观察→归纳→人确认"，不是发明新规则。

先读两个共享参考（相对本文件：`../../references/`）：

- [shared-protocol.md](../../references/shared-protocol.md) — 输出位置、红线三分类、双确认、启用动作
- [probe-guide.md](../../references/probe-guide.md) — 探查清单、grep 模式、**多目标并发子 Agent 协调方式**

## 执行流程

### Step 1：确定目标与范围
向用户确认：目标项目路径；是否有多个探查目标（前后端分离、monorepo、异构栈）——有则按 probe-guide 第五节拆子 Agent 并发探查（宿主不支持子 Agent 则串行逐目标）。
**护栏**：若 `<项目根>/docs/harness/` 已存在，停下问用户：覆盖重来 / 在现有基础上合并 / 改走 harness-sync 增量更新——不得静默覆盖（会毁掉 changes/ 历史和 sync 沉淀）。

### Step 2：项目探查（只读）
按 probe-guide 清单执行，产出四层事实：技术栈 / 工程结构 / 编码惯例 / 红线候选（每条标注 ✅已遵守 / ⚠️现状违反 / ❓新提议，附文件证据）。

### Step 3：提炼与冲突标注
合并探查结果：统一技术栈表；归并同类红线；同一模式在不同模块结论冲突时，保留冲突、标注来源，交用户在确认阶段裁决。**不得替用户拍板。**

随后按 shared-protocol 的**决策项清单**处理 `{待填}` 来源："探查可得"项已齐；"必须提问"项（覆盖率门槛、错误码区间、鉴权方式等代码反推不出的决策）一次性向用户收集，逐项销项；用户拒答的标 ❓ 待决策；"可给缺省"项直接填缺省值。

### Step 4：生成草案
以 `../../assets/harness-template/` 为骨架（结构与细粒度照抄），把 Step 3 的事实填进去，写入 `<项目根>/docs/harness/`。注意：
- 模板中示例红线是 Java/Spring 视角的**参照**，必须**按本项目技术栈裁剪**——只保留与当前栈相关的红线类型，再填项目实际内容；不适用项删除，不向用户出示。
- 模板技能中的分层名/步骤名（如 `编码实现` 的 Model→Repository→Service→Controller）**按技术栈适配**：参照 `../../references/stack-variants.md` 选用对应变体（Java / Python-FastAPI / TS），只写一套进项目；删除栈不适用的小节（纯前端删后端步骤、无 MQ 删 MQ 步）。
- 销项后的内容填入，不留 `{待填}` 占位符；用户拒答项写 `> 待决策：{项}（❓ 开发前必须补齐）`。草案文件头部状态标注：`> 状态：草案（待人工确认）`。
注意：宪法 CLAUDE.md 的草案稿写入 `docs/harness/CLAUDE.md` 暂存，**确认通过前不动项目根**；启用时才融合进项目根（见 shared-protocol「宪法文件的位置与融合规则」）。

### Step 5：生成后自检
按 shared-protocol 的「生成后自检」清单逐项执行——重点：**wiki 状态机/枚举逐个值与代码核对**、**红线证据逐条复核**（修掉"全表遵守"类以偏概全）、引用完整性、占位符清点。未过项先修，自检结果附进下一步的结构确认报告。

### Step 6：双确认
按 shared-protocol 执行：先呈结构（文件清单+技术栈+红线清单+债务摘要+自检结果），用户点头后逐文件走查内容。循环修改直到用户确认。

### Step 7：启用
按 shared-protocol 执行：宪法融合落位到项目根 CLAUDE.md、去草案标识、写 changes/0001 变更记录。

## 边界

- **只读探查 + 只写 `docs/harness/`**；不碰业务代码，不重构，不"顺手修"探查中发现的债务（只记录）。
- 红线只能来自观察到的证据或用户明确提议，禁止凭空发明。
- 模板（`../../assets/`）或共享 references（`../../references/`）**缺失或不可读时，立即停下报告用户**，禁止即兴编造生成物结构（缺模板产出的规范体系必然缺文件、走形）。
- 用户中途喊停，草案保留在 `docs/harness/` 供下次继续，不留半截修改。
