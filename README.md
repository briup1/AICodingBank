# AICodingBank

个人跨项目工作台。你定目标、做决定、查结果；工作台找回项目、方法和原始证据，不另建一份项目台账。

## 从你要办的事开始

| 你要做什么 | 从哪里进入 |
| --- | --- |
| 今日总览：「什么等我决定？」 | [查进展或结果](AGENTS.md#查进展或结果只读)。按需回读已有记录，不是实时监控；未覆盖的项目不算无异常。 |
| 开始或接续：「继续上次的需求」 | [定位项目和任务副本](AGENTS.md#找项目或接续任务)，以项目现有记录接续。 |
| 抽查：「这次验过没有？」 | [只读查证](AGENTS.md#查进展或结果只读)。确定要新跑，再看[开发与验收](工作方法/开发与验收.md#验收-sop)。 |
| 复用：「下次怎么做？」 | 按问题选择[新产品与新功能调研](工作方法/新产品与新功能调研.md)、[已有项目的现状与改动分析](工作方法/已有项目的现状与改动分析.md)或[开发与验收](工作方法/开发与验收.md)，或按任务找[岗位、技能、提示词](AGENTS.md#做事或复用方法)。 |
| 管理：「新东西放哪里？」 | [按用途和维护责任归档](EXTENDING.md)；查完整结构才看[目录地图](工作台文档/参考资料/工作台目录地图.md)。 |

## 设计理念

- **四层分离**：岗位定义职责，Skill 定义方法，执行配置定义模型与工具，会话承载一次具体工作；四层互不复制。见[岗位名册](岗位手册/README.md)、[能力目录](CATALOG.md)、[执行配置说明](tools/execution-profiles/README.md)。
- **单点控制面**：能力只有一份正文、一次登记（`skills.yaml` / `skills-lock.json`），由 `install.py` 软链装配到各宿主；登记、验证、安装、停用都可核对。
- **留痕契约**：结构变动写[迁移记录](工作台文档/迁移记录/)，目录与引用由测试锁定；不靠记忆和口头约定。

工作台资源入口见 [AGENTS.md](AGENTS.md)；每个目录的中文注解见[目录中文地图](工作台文档/参考资料/工作台目录地图.md)。

## 常用命令

```bash
python3 install.py --catalog-only   # 刷新 CATALOG.md，不联网、不安装
python3 install.py                  # 同步第三方上游 + 安装已验证 Skill（需授权）
```

- 添加/更新 Skill、收藏第三方、写最佳实践：完整步骤见 [EXTENDING.md](EXTENDING.md)。
- 本机临时停用某个 Skill：写入 Git 忽略的 `skills.local.yaml` 后重跑安装器，不改共享验证状态。

## 换机与本机恢复

1. Clone 工作台和实际需要的项目。恢复或手工重建 Git 忽略的 `本机资料/projects.local.md`：每项记项目名、用途、主仓库绝对路径；可另记统一 Worktree 根目录，不录临时 Worktree、分支或凭证。账号、密钥、登录态按各工具规范单独恢复。
2. 从工作台根目录开新会话。Pi、Codex 等以 [AGENTS.md](AGENTS.md) 为工作台入口；Claude Code 从 [CLAUDE.md](CLAUDE.md) 转过去。Pi 的用户级按需索引和 [`/pm`](tools/integrations/pi-pm/README.md) 都是可选接入：有用到才恢复，核对本机路径与模板链接；装 Skill 不会替你恢复这些入口。
3. **先只读检查**：在工作台根目录运行 `git check-ignore 本机资料/projects.local.md`；从索引抽一个项目，确认主仓库可访问，再将变量 `repo` 设为其绝对路径，运行 `git -C "$repo" worktree list --porcelain`，核对 Git 登记的副本和选中的项目入口是否可读。若使用了软链，用 `ls -l` 看目标，再用 `test -r` 检查是否可读。开新会话请宿主回报它实际读到的工作台入口；不要把文件存在当成自动加载成功。
4. 只有要装配已验证 Skill 且获得当前授权时，才执行上面的安装命令。缺项目、宿主入口或本机配置时报告缺项；不为验证入口顺带安装、登录或发业务请求。
