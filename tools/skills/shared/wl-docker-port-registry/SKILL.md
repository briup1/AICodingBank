# Docker 端口分配与登记

本机 Docker 服务会越装越多，默认端口必然相撞（AIHOT 与 langfuse 都默认 3000 是实例）。本 Skill 固定两件事：**怎么查清谁占了端口**，**冲突时按什么规则取新端口并记录**。

台账唯一落点：`WORKBENCH.local.md` 的《Docker 端口分配台账》节。台账只记**分配决策**（谁分到哪个槽），实时占用状态不落盘，用时按下面方法查。

## 1. 查占用：三板斧交叉，单看一个会误判

```bash
# ① 本机进程（谁在听这个端口）
lsof -nP -iTCP:<port> -sTCP:LISTEN

# ② 容器发布端口（权威：Docker 真身）
docker ps --format '{{.Names}}\t{{.Ports}}' | grep <port>

# ③ 实测谁在应答（拿到服务名）
curl -s -m 3 http://127.0.0.1:<port> -o /dev/null -w '%{http_code}\n'
```

**已知坑**：本机 Docker 跑在 colima 里，宿主端口由 colima 的 `ssh -L` 进程转发，`lsof` 会把占用者显示成 `ssh` 进程（2026-10-03 实测 3000、9090 均如此）。所以结论必须以 `docker ps` + `curl` 为准，`lsof` 只用来判断"端口是否已被占"。

## 2. 分配规则：3000-3099 段，每服务一个 10 位槽

- Web/自托管服务的宿主端口统一取 `3000 + 10×k`（3000、3010、3020 … 3090），一个槽位内留足偏移空间给服务内部多端口。
- 取**最小空闲槽**：台账没有登记 **且** 三板斧实测没人听。
- 段外端口（如控制台 9090）不参与槽位递增，但必须照样登记。
- 段内用尽或服务需要特殊端口时，另开新段并在台账注明段用途。
- **禁用镜像/compose 默认端口**：默认值是最容易被忘的隐式状态，分配结果必须显式写进该项目 `.env`（如 `PORT=3010`），再启动。

## 3. 登记流程（缺一不可）

```text
分配前：三板斧查占用 + 查台账
   -> 取最小空闲槽（例：3010）
   -> 写入项目 .env（显式端口，启动命令带上 env）
   -> 写入台账（端口 | 服务 | 项目路径 | 状态：预留/在用）
   -> 启动前探测：lsof + curl 仍空闲才 docker compose up
   -> 启动后 curl 应答，把状态改为"在用"
```

台账表结构（维护在 `WORKBENCH.local.md`）：

```markdown
| 端口 | 服务 | 项目路径 | 状态 |
```

## 4. 边界

- 只管**宿主端口**的查询、分配与登记；不管理容器生命周期，不执行 `docker compose up/down`、`docker prune` 等操作，除非用户另行要求。
- 不改**已在运行**服务的端口；要改属于迁移，单独确认。
- 台账不记动态快照（进程、连接数），只记分配决策；查询结果不回写台账。
- 不为公司项目另立规则；公司项目先读其自身约束，本规则适用于个人工作区。
