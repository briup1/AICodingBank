# 可视化文档工作台

作为个人工具使用策略，把“制作、审核、分享可视文档”统一起来，不为每个业务项目复制一套工具。本 Skill 提供操作约束、建设方案和白名单只读分享辅助脚本；**不附带通用发布 CLI、账号认证或多人审核后台**。现有脚本用法见 [分享操作](references/sharing-operations.md)，是否正在运行以本机真实配置和实例检查为准。

## 先分清本次意图

| 用户意图 | 本次边界 |
| --- | --- |
| 把此类任务统一管理、沉淀方案 | 更新本策略或参考方案；不启动服务、不搬迁项目文档 |
| 把规则或报告变成可视文档 | 读取项目原文，生成并验证项目内产物；不自动分享 |
| 分享已经存在的 HTML | 核对分享范围和文件依赖，复用本机现有发布入口；无入口时提出最小方法 |
| 更新正在审核的页面 | 发布新版本，保留旧版本依据和审核记录；不能静默沿用已变更路径的批准 |
| 只需一张临时示意图或产品页面 | 使用对应绘图或前端能力，不强行建立发布、版本和审核流程 |

进入目标项目前读其 AGENTS / README；进入本工作台时按 WORKBENCH.md 读取本机上下文。只加载当前阶段需要的内容：工具建设与长期版本设计读 [统一工具方案](references/tool-plan.md)；实际分享已有页面读 [分享操作](references/sharing-operations.md)。

## 1. 分类与证据先于绘图

- 一级分类使用用户明确的业务维度与处理方向，再拆子情况；用户未明确时先说明分类依据。不要把输入字段、来源类型和处理动作混为同一层级。
- 规则图沿“用户最小示例 → 来源返回 → 判断条件/计算步骤 → 结果”展开，复杂分支可折叠；普通报告选择适合其内容的视图，不机械套用规则图。
- 为每条路径保留稳定编号。重排分类不改编号；语义变化记录规则版本，必要时建立新路径并关联旧路径。
- 分开记录**业务状态**（已确认、推断、待确认、已废弃）与**证据覆盖**（直接案例、通用条款、推断支撑、未覆盖）。旧案例不一定覆盖新算法。
- 原文证据挂到对应路径，注明文档、章节/定位、原文摘录及读取版本或内容哈希。明确它支持的是主例、反例还是部分条件；数字、比较符或适用范围不同要写出差异。
- 用户本轮确认与产品原文分列。没有依据的公式、拆分方式和结果保留待确认，不借相邻案例补造。
- 文档内的审核选项只是意见，不自动批准业务规则；明确确认后的结论才按项目约束回填原文。

## 2. 制作与验证

优先复用宿主已有、适合的绘图/HTML 能力；本策略不复制第三方 Skill，也不假设任一插件必定存在。共用机制由工作台维护，业务内容与原文仍归项目。

对可审核文档，按所用功能验证：

- 稳定编号唯一，分类与子分类能对应用户模型，证据摘录与原文一致。
- 直接案例、缺口、本轮补充可区分；筛选、折叠、原文定位不会隐藏必要条件。
- 浏览器无脚本错误，目标设备可阅读，声明离线可用时实际验证离线打开；HTTP 与离线验证分别报告。
- 审核记录绑定文档、发布版本与路径的规则版本。规则改变后，保留原意见但标记需要重新审核；旧意见不能自动成为新版本批准。
- 本地存储按文档和版本隔离。导出至少包含文档标识、发布版本、路径标识、规则版本、意见与备注；未建立身份机制时不能把自由填写姓名当成已认证身份。
- 本地浏览器记录不等于多人共享记录。更换访问地址、浏览器或设备不保证记录可用，迁移前先导出；尚无导入能力时明确说明。

无法执行的验证明示“未验证”，不以静态检查冒充浏览器、局域网或多人协作验收。

## 3. 分享与更新

先查本机是否已有统一分享工具、配置和运行入口。没有时不要每个项目各造服务；按参考方案提出可复用的最小实现，等待相应实施授权。只要求写方案，不执行安装、监听、开机启动或网络配置。

分享时遵循：

1. 确认哪些文件可以给谁看。HTML 内嵌的原文快照、截图和脚本同样在检查范围内；隐藏区块不等于未泄露。
2. 只发布明确选定的 HTML 与必要资源副本；不共享整个仓库、个人目录、配置目录或指向源仓库的软链接，不开放上传和目录遍历功能。
3. 草稿与已发布副本分离。未发布的源文件变化不自动影响审核者；发布版本不可原地覆盖，稳定入口只指向明确发布的版本。
4. 分清本机预览与局域网分享。根据当前网卡、服务监听和访问测试给出真实地址；不长期保存会变化的 IP，不把本机回环地址发给同事。
5. 需要认证的内容在具备访问控制前不发布；同一局域网不等于都有权限。不擅自关闭防火墙、开放公网或创建网络隧道。
6. 更新、停止、撤下只针对已识别的发布项或服务实例，不关闭其他项目的服务。撤下在线副本不等于收回已下载内容。

## 4. 复用与交付

- 使用一个本机工具入口按项目/文档区分内容；端口、发布目录和生命周期由工具统一配置，不散落进业务仓库。
- 工作台保存策略与工具能力；本机偏好和配置定位保存于 WORKBENCH.local.md；项目保存原文与工作稿；发布目录只保存可分享副本。不要复制同一正文到多个入口。
- 只有真实实现后才提供可执行命令；参考方案中的动作名称不是已安装 CLI。
- 交付说明本次产物位置、规则与证据缺口、真实验证、是否发布、访问范围、审核意见如何收回及停止方式。不能把“登记了 Skill”说成“服务已可用”。
