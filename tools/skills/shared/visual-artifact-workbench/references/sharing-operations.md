# 白名单只读分享服务

现有辅助脚本：[serve.py](../scripts/serve.py)。它只负责提供已经准备好的发布文件，以及服务状态检查、停止；没有通用发布 CLI、账号认证、上传或多人审核后台。局域网地址可以被同网段可达设备访问，链接不是身份认证。

## 先找真实配置

从工作台的 WORKBENCH.local.md 读取本机配置文件指针，不复制固定 IP、端口或项目路径到本手册。配置包含监听地址、端口、发布根目录以及 URL 到文件的白名单。配置、日志和发布记录放在公开目录之外。

命令形态如下；`PYTHON` 必须替换为本机上下文规定并已验证的解释器，`SKILL` 与 `CONFIG` 为实际绝对路径，不是已安装命令名：

```bash
"$PYTHON" "$SKILL/scripts/serve.py" status --config "$CONFIG"
"$PYTHON" "$SKILL/scripts/serve.py" serve --config "$CONFIG"
"$PYTHON" "$SKILL/scripts/serve.py" stop --config "$CONFIG"
```

- 先查 status；已有服务时不要再起一个。serve 是前台命令；需要后台运行时明确记录日志与运行状态，不默认配置开机启动。
- status 对真实 HTTP 实例进行校验，不仅看 PID 文件。stop 还核对进程命令，拒绝按过期记录终止其他进程。
- 当前健康检查固定为 `/_health`，只返回实例标识，不包含本机文件路径。不要把它当成用户认证机制。

## 当前发布方式：人工核对，显式文件清单

1. 检查原文、资源依赖和分享权限；已有页面优先复制，不改业务判断。
2. 从批准文件生成独立版本目录。为可审核页面补充发布版本、来源哈希，以及按文档/版本隔离的存储键；导出记录包含每条规则版本和意见时间。保留变换前后哈希与变换说明。
3. 对副本做浏览器验证。发布配置只登记必需的文件；源仓库、原文外链、日志、配置和内部发布记录不登记。
4. 配置中的 `routes` 精确匹配 URL；文件项包含发布根目录内相对 `file` 和真实 `sha256`。稳定入口可用 `redirect` 指向已登记的版本 URL。其他 URL 一律不提供文件。
5. 不原地覆盖版本文件。新文件和首页验证完成后再原子更新配置；端口或监听地址改变需显式重启，单纯更新路由不需重启。
6. 撤下只删除相应路由及更新公开索引，保留或清理历史副本另按用户要求执行；停止服务不删除源文件。

当前脚本拒绝目录列举、清单外文件、软链接、越界文件路径、内容哈希已变化的版本，以及上传。它不是经过生产安全认证的 Web 平台；需要认证的内容先补齐访问控制，不能靠局域网或隐藏地址代替。

## 验证边界

- 本机通过真实局域网 IP 访问，只能证明本机监听和 HTTP 可用；第二台设备的连通性必须由同事实际打开确认。
- 审核意见只在各自浏览器中保存，需导出交回。源页面原来的浏览器意见不自动迁移到新域名/端口/发布版本。
- 分享期间保持电脑和服务运行；网络改变后重新核对网卡地址。不要自动关闭防火墙或建立公网隧道。
- 分享的 HTML 内嵌原文也会提供给访问者；对敏感内容的筛查不能只看首页可见区。
