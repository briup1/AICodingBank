# 安全检查清单

## Callback 与会话

- [ ] state 随机、短期、一次性消费；失败也不能重放。
- [ ] state 与浏览器或请求 binding 绑定。
- [ ] provider 在登录开始时固定，callback 不接受客户端替换。
- [ ] redirect URL、登录 URL 和 logout URL 由服务端固定构造。
- [ ] callback 校验来源、CSRF、有效期和消费状态。
- [ ] Cookie 使用 HttpOnly、Secure、合适的 SameSite 和轮换策略。
- [ ] 旧 Session 在重新登录、注销或作用域失效后不可继续访问。
- [ ] 个人身份、企业身份和多企业切换规则明确。

## 身份与授权

- [ ] 不信任请求体、Header 或 URL 中的 user / enterprise / tenant 标识。
- [ ] 只使用服务端外部身份核验结果。
- [ ] 外部身份不自动获得本地管理员、部门或全平台权限。
- [ ] 企业授权、产品授权和动作授权分层执行。
- [ ] 跨企业、跨产品、停用产品和过期授权有负向测试。
- [ ] 本地执行主体唯一且不会与内部身份 key 碰撞。
- [ ] Request、Job / Run、Worker、事件和结果保持同一主体与 Grant。

## 凭证与日志

- [ ] 明文凭证不写入 URL、Cookie、localStorage、日志、异常或业务消息。
- [ ] 如需后台调用，凭证只以加密密文保存，并有明确清理时机。
- [ ] 日志只记录稳定错误码和脱敏标识，不记录 callback query 原文。
- [ ] 测试 fixture、截图、快照和文档不包含真实凭证或用户资料。
- [ ] 上游网络失败不会被误报为用户密码错误，也不会静默降级。

## 验证证据

每个新增安全约束都要有一个能在修复前失败、修复后通过的负向测试。HTTP 200、mock 调用次数和“登录页出现”不能单独证明安全闭环；需要回读 Session、授权、业务数据或协议结果。
