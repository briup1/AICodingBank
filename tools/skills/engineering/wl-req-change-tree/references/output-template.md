# 理解层输出模板

这是输出骨架，不是必须填满的表单。空栏目省略，相同事实只完整写一次。

```markdown
# <需求名称>：需求变化树

依据：<原始材料路径或名称>；现状仅按原文描述，未作运行核验。

## 总变化
<一段话：场景 + 对象/能力 + 明确旧状态→目标。新增写新增，未知旧状态不编造。>

## 主变化树
<文字树：C1、C2……主要业务变化；必要时下一层列交互/逻辑/数据语义等，短标题导航，不重复详细规则。>

## 变化展开
### C1 <具体业务变化>〔来源：原文章节〕

**变化定位：**
- **场景**：<谁在什么业务入口、什么操作或状态下遇到该变化>
- **对象**：<发生变化的业务对象、界面区域、任务或状态>
- **从**：<原文明确的旧状态/当前状态；未说明则写“原文未说明旧状态”>
- **到**：<触发动作或条件后的目标状态；新增能力写新增后的状态>
- **结果/边界**：<直接结果、适用范围、保持不变项或禁止副作用>

交互：
- <页面/位置 + 新增/修改/删除 + 具体表现；仅列原文信息>

业务逻辑：
- <条件 → 原文已知旧结果/新增 → 目标结果>

数据语义/流程/其他实际变化面：
- <只放前面未表达的实际内容；无对应变化省略>

保留边界：<仅本包的必要边界，或引用 R…>

### C2 …

**变化定位：**
- **场景**：<谁在什么业务入口、什么操作或状态下遇到该变化>
- **对象**：<发生变化的业务对象、界面区域、任务或状态>
- **从**：<原文明确的旧状态/当前状态；未说明则写“原文未说明旧状态”>
- **到**：<触发动作或条件后的目标状态；新增能力写新增后的状态>
- **结果/边界**：<直接结果、适用范围、保持不变项或禁止副作用>

交互：<按需展开；无对应变化面可省略。>

## 共享规则与保留边界
- R1 <只写一次的跨包规则>；适用 C1、C2。
<包内已有完整表达的边界只引用，不另抄清单；没有额外内容可省略本章。>

## 待确认/待补读
- Q1 <确实影响业务理解的缺口；指出影响哪个节点，不替用户决定>
<关联需求仅引用未读取：标待补读，不直接判冲突。无问题则省略。>

## 来源覆盖
<原文章节→C/R/Q 简短映射；只定位，不重写规则；列必要未覆盖项。>
```

每个主要变化包必须保留“变化定位”五项，但不要把它扩写成独立的六栏行为卡。不要增加技术方案或完整测试用例章，也不要为了固定章节顺序将同一规则再讲一遍。
