# HGJ 内部平台路由

仅做平台识别和技能路由，不保存平台凭证，也不替代专项技能。

## 路由表

| 用户意图或关键词 | 加载技能 |
|---|---|
| 服务状态、Pod、K8s、伏羲、日志、Loki、Arthas、请求是否到达 | `hgj-fuxi` |
| TAPD、需求、缺陷、任务、迭代、工时、待办 | `hgj-tapd` |
| 查库、数据不对、SQL、MySQL、Mongo、Redis、ES、数据库连接 | `hgj-db` |
| Apollo、Nacos、配置项、namespace、data-id、环境配置 | `hgj-config` |
| 登录、SSO、Cookie、Token、密码、凭证失效或配置认证 | `hgj-auth` |

若任务跨平台，只加载实际需要的技能。例如“根据 TAPD 缺陷排查日志”加载 `hgj-tapd` 和 `hgj-fuxi`；只有需要核对数据时再加载 `hgj-db`。

## 路由流程

```text
识别任务意图
  ↓
选择最少的专项技能
  ↓
先执行只读、低风险检查
  ↓
需要写入或高风险操作？── 是 ──> 明确对象、环境和影响后等待授权
  │
  否
  ↓
执行并返回脱敏证据
```

## 全局安全边界

- 不读取、打印、复制或写入明文密码、Token、Cookie、Secret、私钥。
- 缺少凭证时加载 `hgj-auth`，引导用户在本机交互配置，不要求在聊天中粘贴。
- 内部诊断默认只读；生产环境、发布、删除、数据写入、批量修改必须获得明确授权。
- 平台输出先脱敏，再写入报告、日志或回复。
- 无匹配场景时，不加载任何内部平台技能。

## 触发示例

- “看一下 dev 的服务错误日志。”
- “帮我查 TAPD 需求和关联缺陷。”
- “核对这条订单在数据库里的状态。”
- “查看 beta 的 Nacos 配置。”
- “内部平台登录凭证失效了。”

## 反例

普通代码修改、文档写作或不涉及内部平台的任务，不应加载本技能或任何 `hgj-*` 平台技能。
