这是生成 HTML 前的内部工作结构，不要求作为第二份交付物提交。需求简单时可以在上下文中完成；需求复杂或多分支时可暂存到项目 `.work/`。

- 目标结果：

- 以前：
- 改后：
- 关键变化：旧 → 新 → 下游结果

技术承接：
- 改哪里：现有入口、模块、接口、数据或展示节点
- 怎么改：转换、校验、传递、保存、读取、回写、失败
- 为什么：复用、兼容、边界、代价；必要时比较替代方案
- 技术流程：输入 → 转换 → 保存/传递 → 读取/使用 → 结果

专项适用性：
- 数据与存储：涉及 / 无 / 待确认 + 依据
- 接口与契约：涉及 / 无 / 待确认 + 依据

- 性能/容量：涉及 / 无 / 待确认 + 依据
- 外部依赖/发布/恢复：涉及 / 无 / 待确认 + 依据

验收：可观察结果与禁止副作用
