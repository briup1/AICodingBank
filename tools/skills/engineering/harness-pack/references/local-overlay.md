# 个人接入与公共结构保护

setup/sync命中共享项目时读取。个人资料在当前仓库 `.harness-local/`，内部沿同一rules/wiki模板；不建仓库外目录。团队根/子树规则优先，个人记录不得扩大授权或取代公共Owner。

## 写入前后

1. 核对真实目录不是符号链接，保留已有内容；用 `git ls-files -- .harness-local` 检查无已跟踪文件，用 `git check-ignore -v --no-index .harness-local/AGENTS.md` 查看覆盖规则。
2. 已被忽略则不重复添加；否则取得当前仓库许可后向 `.gitignore` 追加 `/.harness-local/`，不动原规则。公共忽略改动也需许可；不允许时经同意可用 `.git/info/exclude`，不能自动采用或改全局配置。
3. 没有许可/无法核验时只给拟定补丁，不写未忽略个人资料；已跟踪则停下，不自动rm --cached或删历史。
4. 写后核对实际新文件均被忽略且未跟踪，公共diff只有获准的最小忽略项，重跑不重复追加。Gitignore不是加密，不阻止强制add，不能保证备份/其他用户不可读。

## 使用与维护

个人AGENTS链接真实团队规则及资料Owner；缺口才补个人规则/Wiki，明确个人补充及来源，沿固定章节写差异，不复制团队正文。个人需求笔记在changes下按日期-主题组织，团队已有需求/用例只引用。sync发现公共正文需改时给建议补丁，不擅自写入。

根目录工作时隐藏AGENTS不保证自动发现，优先核对目标宿主支持的显式上下文入口，否则提供“先读当前仓库.harness-local/AGENTS.md，再按团队规则工作”的提示。未经实测不声称自动生效，不为此装扩展或覆盖根规则。账号卡另按[测试入口卡](testing-entry.md)处理。
