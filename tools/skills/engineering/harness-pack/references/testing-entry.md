# 测试入口卡

个人 `.harness-local/testing.md` 只回答“去哪测、用谁测”，不是测试手册。固定两节：测试地址、测试账号；必要备注可省略。即使账号未知，也必须保留可填写的账号 JSON，不能用“暂无账号”的段落代替。已有账号索引则在必要备注中引用，不复制真实账号清单。具体业务数据/预期归本需求用例，方法/命令/证据归测试规范，实际ID和结果归执行记录。

````markdown
# 测试入口

## 测试地址

默认环境：本地开发。

| 入口 | 地址 |
|---|---|
| 管理后台 | https://admin.example.com |
| 产品入口 | https://app.example.com |

## 测试账号

填写提示：“环境”填写对应入口的完整 URL（含协议、实际端口及必要路径），不要用“本机8010／DEV身份”等标签代替；地址已知时由 Agent 按已确认资料填入，未知才留空待用户填写，不能把已知地址留给用户补。URL 不包含凭据或带令牌的查询参数。只保留“入口、环境、账号、密码”四个字段，账号填用户名或邮箱，密码仅在下述安全条件成立时填写；未知留空，多个账号复制对象。不使用密码登录的接口简短注明，必要的鉴权说明放备注；Token/Cookie/密钥继续使用原受控入口，不填入账号 JSON。不增加角色、登录方式、凭据位置或核验记录字段。JSON 不支持注释或末尾多余逗号，字符串中的双引号、反斜杠需转义。

```json
{
  "测试账号": [
    {
      "入口": "待填写：对应上方入口",
      "环境": "https://admin.example.com",
      "账号": "",
      "密码": ""
    }
  ]
}
```

## 必要备注

确需后端查验时写一行默认库标识；账号未核验或不可用时简短注明。
````

示例不是实际身份，不据此新增账号、猜测角色或搜索凭据。未知网址也保留一行“待填写”的最小地址表；未知账号保留上面的最小 JSON 对象，由负责人在首次功能验收前补齐。已知入口按实际需要预留对象，不生成无关环境或角色的整套占位。没有独立登录的 API 对象明确写“不适用：使用何种鉴权”，不要误导用户填写不存在的账户。登记不等于本轮已登录。

setup 验货时检查：有填写提示、示例中的四个账号字段及至少一个可填写对象或现有账号索引引用，JSON 可解析，“环境”为已确认完整 URL 或明确未知的空值，已知地址与上方入口对应、未被文字标签代替；示例域名生成项目卡时须替换或留空，不能冒充实际地址。未知信息未被伪造。sync 涉及测试入口时按同一结构补缺，保留用户已填账号、密码和URL，格式迁移不能覆盖已填值或重复创建同一账号；删除用户字段须有明确授权，不自动丢弃额外信息；已有真实值只在获准且必要时局部读取/编辑，不全文回显。结构检查器不会读取个人账号卡，须由执行者在安全边界内核对，不能声称该检查器已验证账号卡或登录成功。

## 获准明文测试密码

用户允许直接记录获准测试账号的真实明文密码，但只写入已核验忽略且未跟踪的个人文件；先按[个人接入](local-overlay.md)核对真实路径，个人目录/文件通常700/600，不擅自改变共享目录权限。已跟踪、非Git或无法核验保护时不写真实值，先报告。

此例外只适用于获准使用且权限已明确的测试账号，不适用于生产密码、跨环境复用的工作凭证或未获准账号。真实值不进共享规范/模板、AGENTS、报告、回复、截图、命令参数和日志；只在获准登录/维护时由工具读取必要内容，避免全文输出。Token/Cookie/storage-state继续沿既有受控入口，不一并迁入。

setup/sync不为填卡主动搜索真实密码，也不因此创建账户或秘密管理服务。可直接复用原密码管理器。存放许可不等于上传/提交/使用账号执行业务写入许可；共享文档只记录个人卡定位或非秘密引用。
