# 测试规范

> 虚构成稿，输入及局部范围见[业务模型](../wiki-examples/业务模型.md#角色与能力边界)；仅示范表达，不是可运行项目或实测证据，设定不得移植为目标事实。

范围：待办完成操作的验证（局部示范）；状态：当前；依据：虚构 package.json、tests/ 与测试约定。“当前”仅指示例设定。

## 按改动选择验证

默认按直接影响选测，不每次全跑；具体数据/步骤/预期归本需求用例。

| 改动 | 最小入口 / 验证重点 | 扩大条件 |
|---|---|---|
| 完成规则 | todo-service.test.ts：目标更新、其他待办不变、保存失败不返回成功 | 改保存加存储测试/浏览器 |
| 本地读写 | todo-storage.test.ts：写入/读回、失败报告 | 格式变更加旧数据兼容 |
| 勾选/样式 | 浏览器：前后状态、失败提示、刷新恢复；关键状态截图 | 调用变化加服务测试 |
| 取消完成（尚未实现） | 先确认契约/状态，再补服务与页面验证 | 变更格式加读回/兼容；未知 ID、重复/并发未定不猜预期 |

新增保护条件须有拒绝案例；替身与故障注入不能代替真实存储证据。

## 执行入口与证据

示例 package.json 设定 test=vitest run、check=静态及类型检查；目标项目须核实自身声明，不照抄。

```bash
npm test -- tests/todo-service.test.ts
npm test -- tests/todo-storage.test.ts
npm run check
```

| 验证 | 通过判据 / 能证明什么 |
|---|---|
| 程序套件 | 退出0且目标用例通过；服务替身只证明服务行为 |
| 静态检查 | 只证明声明的检查项，不代替浏览器交互 |
| 浏览器 | 实际勾选、显示与刷新读回；沿需求用例执行，关键状态留证 |

## 环境与副作用边界

| 对象 | 要求 |
|---|---|
| 地址/身份 | 引用个人 .harness-local/testing.md；本例无真实网址/账号，登记不证明登录成功 |
| 数据/上下文 | 合成待办、专用浏览器上下文，不清空日常 localStorage |
| 副作用/清理 | 不执行未授权外部写入；关闭本次创建的上下文，不影响用户实例 |
| 未决条件 | 目标、数据归属或授权不明则停止相关验证 |

## 结果与未覆盖

沿本需求 `test-runs/轮次/` 的既有结果格式记录；没有格式先确认，不另造字段。

| 记录 | 必须区分 |
|---|---|
| 版本、环境、实际命令/操作 | 本次对象与历史版本 |
| 结果、证据路径、未运行原因 | 服务/存储/浏览器各自通过范围；失败/未验不写通过 |

证据不存登录态或完整浏览器配置；不复制用例预期作为执行结果。

## 来源与未覆盖

- 来源为虚构 package.json、两份 tests/ 与协作约定；测试隔离写法见[编码规范](编码规范.md)，无真实执行结果。
- 浏览器自动化、CI、跨标签页验证未建立；首次需要时核实能力与预期，不宣称自动覆盖。
