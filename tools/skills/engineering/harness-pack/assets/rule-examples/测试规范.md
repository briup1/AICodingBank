## 按改动选择验证

| 改动面 | 最小验证 | 何时扩大 |
|---|---|---|
| 待办完成规则 | todo-service.test.ts：目标待办更新、其他待办不变、保存失败不返回成功 | 同时改持久化时，加存储测试及浏览器验证 |
| 本地存储读写 | todo-storage.test.ts：写入与读回一致、写入失败可报告 | 变更数据格式时，加旧数据兼容验证 |
| 勾选交互或完成样式 | 浏览器核对勾选前后、失败提示及刷新恢复；样式改动保留对应状态截图 | 服务调用也变化时，加服务测试 |

具体身份、数据、步骤与预期只维护在本需求用例中；这里说明选哪类验证，不要求每次全量运行。

## 执行入口与证据

示例 package.json 设定 test 为 vitest run、check 为静态及类型检查。仅在目标项目确有相同声明时，才可参考这些命令：


```bash
npm test -- tests/todo-service.test.ts
npm test -- tests/todo-storage.test.ts
npm run check
```

退出码为 0 且目标用例通过，才记录该项通过。检查器通过不代表浏览器交互通过。服务测试使用替身，只证明服务行为；真实保存能力还须通过浏览器操作和刷新读回证明。浏览器步骤引用本需求用例，证据保存到本需求 test-runs/轮次/，不得将登录态或完整浏览器配置存入证据目录。

## 环境与副作用边界

网址与账号入口仅引用个人 .harness-local/testing.md；本示例没有真实网址和账号。执行前核对目标地址，不能把登记了入口当作登录成功。

使用专用浏览器上下文和合成待办，不复用日常浏览器的待办数据。测试结束关闭本次创建的上下文；不清空日常 localStorage，不执行外部写入。目标环境、数据归属或授权不明时停止相关验证并报告。
