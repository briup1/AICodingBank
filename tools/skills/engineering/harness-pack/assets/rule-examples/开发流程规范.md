# 开发流程规范

> 虚构成稿，输入及局部范围见[业务模型](../wiki-examples/业务模型.md#角色与能力边界)；仅示范表达，不是可运行项目或实测证据，设定不得移植为目标事实。

范围：待办完成操作的协作（局部示范）；状态：当前；依据：虚构协作约定与 docs/changes/README.md。“当前”仅指示例设定。

## 需求与资料归宿

每项需求使用 `docs/changes/YYYY-MM-DD-主题/`，向需求/方案/用例能力显式传目录，不另存副本。

| 资料 | 唯一正文 / 建立条件 |
|---|---|
| 目标、范围与批准 | requirement.wl-req-confirm.md；HTML 同源生成 |
| 方案 | design.wl-design-doc.html；需要设计时建立 |
| 具体数据、步骤、预期 | test-cases.wl-qa-test-planner.md；HTML 同源生成 |
| 实际结果与证据 | test-runs/轮次/，执行后建立，沿既有结果格式 |
| 长期知识 | 原 rules/wiki；重要规则/取舍变化在同需求记规范变更.md |

小范围文案/链接修正在原文修改，不强制生成整套产物。

## 从需求到交付

```text
提出“勾选后保存” → 确认结果与范围 → 用例/必要方案
  → 获准实施 → 聚焦验证 → 交接实际差异、证据与缺口
```

| 阶段 | 负责人动作 / 下一位消费者 |
|---|---|
| 确认 | 执行者核对当前行为，用户确认目标；用例与方案引用同一批准版本 |
| 实施 | 执行者沿已批准范围实现；验证方读取用例，不从流程重建步骤 |
| 验证/交付 | 执行者按[测试规范](测试规范.md)选测，将结果交用户评估 |

## 确认与操作边界

以下为已确认的示例协作约定，非工具自动强制。

| 操作 / 变化 | 边界 |
|---|---|
| 需求确认 | 不自动授予实施权限，已有明确授权不重复询问 |
| 提交、发布、外部写入 | 分别核对本轮授权，测试通过不等于获准发布 |
| 增加跨设备同步 | 重新确认范围/用例与必要方案，不能顺手实现 |

## 完成与资料回写

| 情况 | 本次交付负责人动作 |
|---|---|
| 实际交接 | 说明改动、实测、失败/未验项；结果写原需求记录，不把未运行写通过 |
| 首次实现 / 职责、接口、状态变化 | 回读入口与受影响正文，补齐原“暂无代码”项；必要时用 sync，不重跑 setup |
| 重要规则/取舍改变 | 原位更新正文并在本需求留规范变更.md |
| 普通样式、链接无稳定事实变化 | 说明无需同步，不另建台账或规范记录 |

例如获准增加取消完成，应同步业务、状态、接口及页面消费者；当前仅是扩展方向，不是已实现能力。

## 来源与未覆盖

- 来源为虚构协作约定、归档入口，无真实批准/交付记录；验证步骤及判定由测试规范维护。
- 首次发布的审批人与回退办法未定，发布前确认，不宣称已具备发布能力。
