## 1. 目录结构

按实际工作区逐个生成**实测目录树**，每个目录一行注释，写它**实际**承担的职责。树是探查枚举的结果，不是约定或期望。

### {工作区/子系统名}（`{路径}/`）

{形态示例，非内容示例：}

```text
src/
├── views/          # 页面视图；不直接发 API 请求；测试在 views/__tests__/
├── stores/         # 状态管理；不存放仅服务端才有的状态
├── api/            # REST 客户端封装；不做页面跳转
└── utils/          # 杂物间：无稳定惯例，新增代码原则上不放此处
```

生成规则：

- 注释必须基于证据（目录内文件的真实 import、调用方、注册关系），写"实际承担什么"，不写"应该放什么"。
- 写不出职责边界的目录如实标注"混杂/杂物间"，不硬编职责；名义与实际不符照实注释（`# 名义 common/，实际为订单领域模块`）。
- 树展开到"最后一跳可由一次 ls 完成"的深度，不展开单文件细节。
- 构建产物、vendor、生成物不入树；排除项在树后一行说明。
- **全栈通用**：不预设任何语言/框架的分层命名。controller/service/repository 只是某些 Java 项目的形态；Python、TS、Go、前端、多栈混合的真实形态都是合法的树。
- 生产目录全量覆盖；复杂目录在注释中分项说明。
