> 虚构示例：与四份规则范文共用“本地待办应用”，仅演示结构、粒度和表达，不代表真实项目或实测结果。不得把示例中的路径、技术栈、契约或规则直接当作目标项目事实。

范围：本地待办应用；状态：当前；依据：虚构的 Todo 类型、todo-service 与 todo-storage；“当前”仅指示例设定。

## 数据所有权总览

| 数据或状态 | 谁负责决定或保存 | 消费方与边界 |
|---|---|---|
| 待办及完成状态 | todo-service 决定合法变化，todo-storage 将结果存入 localStorage | 页面通过服务读取和修改，不直接写存储 |
| 页面列表与提示 | TodoPage 展示服务结果和本次错误 | 是展示副本，不是另一份持久化事实 |

没有数据库不代表没有状态。单浏览器场景的已保存数据以存储模块读回结果为准；模块依赖见[工程结构](../rule-examples/工程结构.md)。

## 对象与状态

### 待办 Todo

#### 结构与来源

示例将 Todo 类型定义随 src/todo-service.ts 维护，序列化读写由 src/todo-storage.ts 负责。这里只摘要影响修改的约束：ID 定位对象，标题用于展示，completed 表示完成状态；不抄一份可编辑的完整类型定义。

“买牛奶”的标题相同不表示 ID 相同；名称含义见[领域术语](领域术语.md)。

#### 生命周期与隔离

新增待办由服务交给存储模块保存 → 页面读取并展示 → 完成操作按 ID 更新 → 刷新时从存储恢复。删除及取消完成的行为未设定，不补画状态分支。

localStorage 按站点来源和浏览器上下文隔离；同一来源、同一上下文的标签页不能视为互相隔离。应用没有账号，不存在已实现的用户或租户隔离承诺。

#### 并发与失败恢复

单次完成操作只更新目标待办，保存失败向调用方报告，不返回成功结果；页面按[业务模型](业务模型.md)保留原展示并提示。是否需要事务或额外恢复机制，不能从这份示例推断。

待确认：同一标签页快速连续操作、多标签页同时修改时的顺序与覆盖策略，以及存储内容损坏时如何恢复；首次涉及这些场景时确认并增加相应验证，不宣称已有锁、重试或自动修复。
