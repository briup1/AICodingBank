## 角色与能力边界

使用者在当前浏览器记录待办，并标记已经完成的事情。示例具备新增、查看和完成待办的能力，以下只展开“完成待办”这条代表链路。

没有账号或服务端，不提供跨设备同步，也不能把“同一浏览器”理解为按登录用户隔离。技术职责见[工程结构](../rule-examples/工程结构.md)。

## 能力与流程

### 完成一条待办

#### 入口与角色

使用者在列表勾选已有的“买牛奶”；操作对象是该条待办，不是整个列表。

#### 主链与结果

使用者勾选“买牛奶” → 服务按待办 ID 处理完成状态 → 存储模块保存 → 页面显示已完成 → 刷新后仍可读回完成状态。

服务决定状态变化，存储模块负责保存；数据依据与展示副本的区别见[数据模型](数据模型.md)。这里的“完成”表示事情已办妥，不表示待办被删除。

#### 规则与错误路径

已确认（示例设定）：只有保存成功，页面才展示本次完成结果；保存失败则保留操作前的展示并提示失败。更新“买牛奶”不改变其他待办。

失败后不应将页面上的勾选当作已保存证据；再次操作仍须经过服务与保存步骤。不存在的 ID 如何处理尚未设定，见[接口协议](接口协议.md)中的缺口，不自行给出成功预期。
