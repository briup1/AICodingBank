# 业务模型

> 八份范文共用以下虚构输入，仅示范成稿，不是可运行项目或实测证据；路径、技术栈、规则不得当作目标项目事实。

范围：本地待办完成操作（局部示范）；状态：当前；依据：虚构需求与页面/服务设定。“当前”仅指示例设定。

## 角色与能力边界

用户只要求整理已展示待办的“完成操作”，不是全项目初始化。没有账号/服务端，不提供跨设备同步；其他能力未调查不等于不存在。

| 共用输入 | 值 |
|---|---|
| 待办一 | `{ id: "todo-1", title: "买牛奶", completed: false }` |
| 待办二 | `{ id: "todo-2", title: "交电费", completed: false }` |
| 已给定行为 | 服务按 ID 更新，经存储保存；成功页面采用返回目标对象，失败保留原展示并提示 |

## 能力与流程

### 完成一条待办

```text
使用者勾选“买牛奶”(todo-1，尚未完成)
  → TodoPage 交 ID → todo-service 更新 → todo-storage 保存
  ├─ 成功：返回目标对象 → 页面按 ID 替换 → 刷新读回仍完成
  └─ 失败：页面保留原展示、提示重试 → 再次操作仍走服务/保存
```

| 场景 | 业务规则（已确认的示例设定） |
|---|---|
| 操作目标 | 只更新 todo-1，todo-2 不变，不返回整份列表 |
| 成功判定 | 保存成功才显示本次完成；点击不是保存证据 |
| 完成含义 | 事情已办妥，不是删除记录 |

未知 ID、重复及并发的处理尚未设定，调用前确认，不外推自动重试或切换状态。
