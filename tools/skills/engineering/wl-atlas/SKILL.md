# wl-atlas

把“希望产品做什么 → 模块怎样配合 → 已有什么和缺什么 → 明确建设哪些”讲给负责人和陌生接手者。默认交付独立 HTML 与旁边的一份 JSON 内容源；不启动服务、不更改业务数据、不自动展开实现任务。

## 1. 查目标与事实

- 读目标项目自己的规则、README、目标/架构资料及当前需求和进度；已有明确输入不再追问。遵守项目规定的源码查询入口，按能力沿真实入口、实现与测试核实，避免全库漫扫。
- 区分既定目标、当前范围、候选方向。先盘点已存在但不扩建的公开入口、调度、人工确认、用量归属等实际能力，不只看近期新增；不做新渠道不能吞掉已有命令行/接口。可选领域仍保留来源目标中的具体职责及未决项，不以模块总称代替。参考架构只作查漏，不自动变必做；不固定模块数或能力数。
- 选当前项目一个小场景，用 3～5 步“谁对什么做什么”解释实际与目标差异。开发交付与用户使用是不同操作链时分别表达，不把构建流程混进用户请求顺序。
- 给每项关键现状保留短依据：文件路径/符号/需求或测试记录位置、它证明什么、尚未证明什么。代码存在只证明实现基础；历史测试只证明原样本与原环境。资料未核对就写尚未核实，不能把助手自述当验收。

## 2. 划模块，下探一层

先读 [语义与确认指引](references/semantics.md)。按职责划模块，再列模块内能力；每项回答“是什么、有什么用、是否必要及条件、完成情况与限制、建设决定及采用方式”。

- 用真实 `relations` 驱动简明 HTML/CSS 结构：主链卡自上而下，以动作箭头连接；每个主链节点的按需子卡紧邻其下并列展示（含外部系统），虚线分支和动作写明真实来源与目标。卡片本身就是可展开模块，不另造图形副本或第二套卡片目录。独立数据链、贯穿支撑另外分组，只用明确标为补充的关系行说明作用对象，不冒充处理顺序连线；外部系统的授权与正式记录不归本项目冒领。
- 按模块成立条件核对生命周期、权限/凭据、失败/质量、维护责任及未决方向，具体见语义指引；从资料核实，不把通用查漏清单自动列为必做。合并后将来源重要语义逐一映射到能力及字段，不能用大词吞掉更新/删除、旧索引、受控发布、操作留痕等职责。不同状态或不同取舍的方向拆开，不用条目总数代替覆盖。
- 每项定义核对来源中的对象、动作、结果，三者一致才可视为等价；不靠“路由”“引用”等同名词合并，不用想象的新 UI 替换原职责或抬高目标。主链标题不能代替独立能力定义。名称、定义、用途和关系动作先用白话讲操作结果，技术名仅放在其后的括号或依据中。
- 分开判断三个维度：**必要性**（必要/条件必要/扩展）、**实现程度**（已完成/部分完成/未完成/尚未核实）、**建设决定**（沿用现有/已确认要做/当前不做/尚未决定）。实现程度表达目标范围内开发完成情况，不因本轮未复测或未测全部组合降级；验证限制记在 current/evidence。缺目标行为、直接反证或实现依据不足才据实判部分/未知；若目标本身是证明效果或恢复演练，缺其结果可为实际差距。不从决定或测试执行范围自动推导实现状态，也不批量刷完成。
- 必要性从本项目职责推导，并写理由。可选模块内的必需能力写“条件必要：决定建设该模块时”，不能在表格中丢掉条件。不把“已确认要做”自动改成“必要”。

## 3. 收敛决定，再渲染

- 只追问会改变范围、数据使用或风险的问题。一次用一个场景给少量可选方式；不理解时缩小场景。后来的明确选择覆盖旧选择，同步能力、边界与待确认项。
- 人工方式与现有外部服务都是合法采用方式，不默认新增产品页面。沿用人工入口不取消已确认的交付评估/开放判断等质量补齐工作；必要时分别列为能力，保留各自决定。选了方式不等于已验证，也不能当作必要性理由；不做不授权删除现有能力。没作决定就写尚未决定，不为了收尾代选。
- 在内容源中同步明确决定后，再制作候选报告；保留未确认问题。用户要求草稿时如实输出草稿，不谎称目标或取舍已获批准。
- 读 [数据格式](references/data-format.md)，以 [虚构小项目](assets/example.json) 为语法示例创建本项目数据，禁止继承示例事实。只填纯文本，不填 HTML。根据真实关系选择 placement，不为模板凑层数。

从本 Skill 目录运行（`python3` 需 3.9+，渲染与单测仅用标准库）：

```sh
python3 scripts/render.py /absolute/project/docs/atlas.json --check
python3 scripts/check_content.py /absolute/project/docs/atlas.json  # 启发式提示，须逐条人工裁定
python3 scripts/render.py /absolute/project/docs/atlas.json /absolute/project/docs/atlas-candidate.html
```

先创建获准输出目录。渲染器拒绝覆盖已有文件；每轮用新候选名。默认使用项目文档目录；用户指定隔离评测目录时优先遵从。不得拷贝参考好版本正文或修改候选 HTML 补洞；调整内容源或通用模板再渲染。

模板 [report.html](assets/report.html) 随包自足：线性主链与按需子卡、两层原生 details、收起仍有职责与各维度计数、按模块六列表、链接展开定位和移动焦点、展开模块/全部收起、打印前展开后恢复。结构随正文宽度排版，手机分支改成单列，只有表格容器横向滚动；不需要大图拖动或缩放。主链按关系排序，按需子卡跟随实际 from/to 改变位置。仅支持简单主链、每主链节点一层按需子卡且每子卡一个父节点；多入/多层/循环等不可表达拓扑明确拒绝。数据/支撑边仅作带类型和端点的可见关系补充，可有多个作用对象；不要把真实调用改成数据/支撑来绕过限制。表格/详情/摘要从同一 JSON 派生；不内联项目 JSON 到脚本，不依赖网络或固定节点数。只用完成程度颜色，不给模块染总完成色，不算百分比。

## 4. 核验与迭代

先读并执行 [核验清单](references/verification.md)，区分结构检查、语义审核和浏览器证据。

```sh
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
# 若本机已有 Node，可补充交互脚本的模拟 DOM 单测（不代替真实浏览器）
node tests/test_interactions.cjs
```

把报告用在本轮真实场景：负责人是否能解释目标、配合、现状与取舍；陌生接手者能否指出已确认建设项、限制与下一步缺口。用户选择复现/审核时，由其安排不继承作者上下文的人只读项目资料与此 Skill 重新分析生成；审核者才可接触参考好版本。不得把好版本或项目专用测试喂给复现者，不用同数同名代替语义覆盖。

发现缺陷 → 归因内容分析/指引/渲染器/模板 → 修对应唯一来源 → 同一数据重跑回归、由执行者重新生成 → 审核。每轮保留输入、候选、问题与实际证据；没过就不登记 verified。无法运行浏览器、依赖或独立审核时说明未覆盖，不能用单测冒充实用通过。独立审核与委派仅在获准且工具实际可用时进行；禁止委派时只交付等待审核。

## 5. 交付与停止

- 默认交付新报告、JSON 内容源、关键未确认项与验证边界。README 只追加一句介绍和相对链接，保留原正文；正式入口替换前核对授权。隔离评测或候选阶段不改 README、正式报告。
- 报告能说明目标与操作链、模块职责与配合、条件必要性、可信现状与差距、准确取舍，并通过获准层级的检查后停止；不擅自转入方案/编码/部署。
- 本 Skill 产出不是接口与业务规则规格，也不证明业务已验收。安装、登记、同步、提交、上传均需要单独授权，不是生成地图的附带动作。
