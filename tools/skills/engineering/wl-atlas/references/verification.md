# 核验与实用迭代

## 先核对语义（不能用脚本替代）

1. 目标与场景：拿一个真实输入走完目标链；模块职责与外部边界是否足以解释结果？开发者交付与终端用户使用是否分清？逐个核对存量公开入口、调度、人工确认、用量归属等项目实际职责，是否因只看近期新增而遗漏？不扩建渠道是否误删已有命令行/接口？主链标题是否冒充了独立能力？参考架构不能机械变待办。
2. 逐项对照来源：定义、用途、必要性条件、现状限制、决定与采用方式、依据是否齐全？实现状态是否按已定义目标行为判断，而非按本轮是否复测？未复测/未覆盖全部组合只记验证限制，不能据此降级；有目标行为缺失、直接反证或实现依据不足则据实判断，不批量刷完成。若目标本身是证明效果或实际演练，缺结果可以是实际差距。选择人工方式是否被误写成已实现/已验证？
3. 选择一致：把负责人每个明确选择映射到一个或多个能力 ID、边界与待确认项；后来决定覆盖旧决定。已决定不做的方向没有变待办；未决定不被相邻决定代选。不同取舍是否已拆开？
4. 合并逐义检查：按模块成立条件，从来源逐个核对生命周期（含更新删除及旧副本/索引失效）、权限/凭据、失败/质量/受控发布、维护责任/操作留痕和未决方向。对每个重要语义记录“来源 → 能力 ID/字段 → 已覆盖/待核实/不适用及理由”，不能只核条目数。检查模型访问凭据与部署密钥等不同边界是否被一个大词吞并。非近期可选领域也要按来源保留受控发布、血缘、质量失败/责任等具体职责与未决项，不能只剩总称；不适用方向不自动变必做。合并或替换前逐项比较对象、动作、结果：自动选择产品≠网关版本/地区分流，能核对来源≠统一引用 UI。不得以新界面增强替换已有职责，再判原能力未知或待决定。
5. 必要性独立检查：暂时遮住 decision，仅凭项目职责、necessity.reason 和 condition 能否解释分类？“已确认建设/已选择人工”不能作为理由。采用的引用、反馈等能力也不自动升为必要。
6. 人工采用与补齐检查：分别核对原选择的采用方式和原确认的质量补齐；继续用人工测试不取消交付评估与开放判断的补齐工作，必要时拆成相关能力。定义和动作先讲白话效果，技术名只在括号或依据。
7. 覆盖对照：若有获准参考好版本，按“参考语义 → 本轮能力 ID → 等价/遗漏/合理拆并及理由”核对，不要求逐字逐像素一致。复现者只读项目与 Skill；对照材料仅由作者/审核者读取，不作为生成输入。

## 再做自动检查

在 Skill 目录执行：

```sh
python3 scripts/render.py /absolute/path/atlas.json --check
python3 scripts/check_content.py /absolute/path/atlas.json
python3 -B -m unittest discover -s tests -p 'test_*.py' -v
node tests/test_interactions.cjs  # 仅本机已有 Node 时，无需安装
python3 scripts/render.py /absolute/path/atlas.json /absolute/path/new-candidate.html
```

Python 测试覆盖 HTML 转义/脚本隔离、摘要计数、表格与详情同源、条件必要性、任意模块数与分组、锚点/离线、坏输入和覆盖保护；`tests/test_structure.py` 使用虚构入口/执行/检索/模型/外部业务/数据/支撑节点，检查主链按边排序、from/to 改变会移动实际子卡、模块卡只出现一次且自身是 details、无 SVG 或大画布、独立与支撑有明确关系补充，并拒绝非法关系、多入、多层、反向调用、断裂或成环主链。Node 模拟 DOM 覆盖展开/收起、能力定位和键盘焦点、打印恢复；不是浏览器视觉证据。

`check_content.py` 是提示器：标出必要性理由中的决定/现状字眼、白话字段的括号外英文词、沿用人工但仍有缺口的能力，以及部分/未知状态下“已有实现却本轮未复测”的降级风险。降级提示仅要求核对目标与依据：真实行为差距或目标自身要求而缺少的验证仍可保留原状态。提示可能误报或漏报；逐项对照来源裁定，不自动分类，不把零提示当通过。生命周期覆盖和合并语义仍须上面的人工映射检查，不能靠关键词证明。

检查生成物中每个模块/能力在图与表之间恰好对应，全部能力计数等于各模块计数总和，状态与决定分别计数；外部系统不算本项目模块。表格用途一句、详情完整定义，两者不维护两份解释。数据不得进入 JS；恶意 `</script>` 或 HTML 片段只作为可见文本，不变成标签或属性。数据字段不能插入模板、脚本或 CSS。

## 真实浏览器最小矩阵

遵守当前宿主浏览器规则与授权。直接打开本地候选 HTML，不起业务服务、不访问公司系统、不生成真实业务数据。允许时保留关键状态截图；否则明确未覆盖，不假装通过。

- 结构：打开系统结构区立即看到主链卡片和动作连接，无大片坐标留白，不拖动/缩放大图。卡片自身可展开，不存在另一套图节点或卡片目录。执行节点下方按需分出实际依赖，外部业务卡与知识/模型子卡一样挂在真实来源下。改 from 后子卡移动到新父卡下面，改 to 后分支目标也改变；不能只换文字。数据链与支撑分组并配明确标注的补充关系行，不要求跨卡全连线。
- 桌面：初始收起时看得见职责、必要性理由、三类必要性数、四状态数、四决定数；不给模块一个总完成色。两层折叠可用键盘；表格点击一个收起能力，应展开所属模块和能力、定位、焦点落到 summary。
- 全局：展开模块只展开模块，不强制全部能力；全部收起关闭两层。直接打开能力锚点、刷新该锚点仍能展开定位。
- 窄屏（例如 390px）：正文不横向溢出；结构自然缩为单列，仅表格容器内横向滚动，标题、条件与计数不重叠。一个模块与多模块、不同分组数量、长中文/长标识文本均应可读，不硬编码列数匹配某项目。
- 禁用脚本：降级说明可见，所有模块、能力与表格已存在，可手动展开全部正文；全局按钮隐藏，不出现假交互承诺。
- 打印：先记录打开状态，再打印预览，全部详情展开；退出预览后恢复原状态，重复 beforeprint 不覆盖原快照。无脚本时按降级说明手动展开。
- 离线/安全：断网或观察网络面板无外部请求，无字体/CDN/图片依赖；测试含引号、尖括号、`</script>` 的虚构文字不执行。检查 CSP 无外部连接授权。

## 实用复现与停止

先用虚构小项目走通“内容源 → 校验 → 报告 → 阅读/交互”；再在获准真实项目按同流程从资料重新分析。缺陷修内容源、语义指引或通用模板/渲染器，不手补报告掩盖问题，不通过复制参考内容或降低检查标准获胜。

每轮简记输入范围、失败场景、原因、修改来源、实际重跑结果、剩余未覆盖。只有独立复现/审核实际完成才称独立通过。禁止委派或用户安排下一轮时在此停止交接，不自动发起执行者。

交付时说清：已生成什么；结构/核心逻辑/浏览器/语义/独立复现分别做了什么；还有什么不确定。当前只通过结构测试，不能标 verified、发布或宣称跨项目稳定。README 在正式交付获准时只追加介绍链接，隔离评测完全不动。
