# 可达性审查方法与报告模板

## 逐跳检查面

每个交接点只检查影响目标可达性的项目：

| 检查面 | 必答问题 |
|---|---|
| 职责 | 谁触发、谁处理、谁拥有状态、谁处理失败？是否有无人负责或双重负责？ |
| 数据 | 输入由谁生产？必填值能否产生？类型、枚举、空值、默认值、标识符及版本是否一致？ |
| 控制 | 下一步如何触发？同步/异步、等待、取消和超时语义是否明确？ |
| 状态 | 真相源是谁？写入、投影、恢复和冲突规则是什么？迟到结果会否回滚新状态？ |
| 错误 | 错误如何产生、传递、转换、展示？部分成功如何补偿或安全重试？ |
| 时序 | 重复、乱序、并发、断线、重启、页面刷新后能否收敛？副作用是否幂等？ |
| 边界 | 身份、权限、租户、会话及关联 ID 是否跨边界完整且原样传递？ |
| 兼容 | 旧数据、新旧版本和发布/回滚顺序会否让契约暂时不成立？ |
| 可观测 | 如何关联一次端到端执行并定位断点？用户失败但系统成功或反之能否被发现？ |
| 可验证 | 该跳应由单元、契约、集成、故障注入还是端到端测试证明？ |

## 常见设计 Gap

- 消费者需要的数据没有生产者，或生产时机晚于消费时机；
- 状态发生变化却没有唯一写入者、持久化位置或恢复来源；
- 接口结构一致但字段语义、单位、时区、精度、生命周期不同；
- 调用完成却缺少稳定关联 ID，无法把响应、事件或审批归回原请求；
- 异步任务没有完成通知、查询路径、超时终态或重复投递策略；
- 局部成功后，重试会重复副作用，取消或回滚无法恢复一致状态；
- 模块隐式共享身份、租户、会话、事务或顺序，但契约没有携带；
- 正常路径闭环，断线、重启、刷新、乱序或旧版本路径不收敛；
- 验收只检查某个接口成功，未检查用户目标及最终状态真正成立。

## 最小修正原则

修正设计 Gap 时依次选择：

1. 复用现有状态所有者、协议、扩展点或恢复链路；
2. 补足缺失字段、状态、失败语义或验证证据；
3. 调整有冲突的职责或契约；
4. 仅在现有结构无法闭环时引入新机制。

不要借审查新增产品能力、顺手重构或把非阻断优化升级为前置条件。

## 固定报告模板

```markdown
# 方案可达性审查报告

## 1. 裁决

- **结论：** 可通过 / 有条件通过 / 不可通过 / 信息不足
- **一句话证明或断点：**
- **独立上下文：** 是 / 否（说明原因）

## 2. 目标、原点与边界

- **最终可观察目标：**
- **当前真实原点：**
- **硬约束与 Out of Scope：**
- **证据范围：**

## 3. 证据账本

| 陈述 | 分类 | 证据位置 | 影响步骤 |
|---|---|---|---|

## 4. 端到端逐跳推演

| 步骤 | 前置状态 | 触发方 → 处理方 | 输入/契约/状态变化 | 后置状态 | 结果 | 证据或缺口 |
|---|---|---|---|---|---|---|

结果只能是：成立 / 有条件成立 / 不成立 / 无法验证。

## 5. 契约对接矩阵

| 提供方 | 消费方 | 契约及语义 | 数据/控制/身份/错误是否衔接 | 验证方式 |
|---|---|---|---|---|

## 6. 思维实验

| 场景 | 起始条件 | 关键路径 | 预期终态 | 是否收敛 | 缺口/证据 |
|---|---|---|---|---|---|

覆盖正常路径及所有与目标相关的高风险分支；不适用项说明依据。

## 7. Gap 与不成立假设

### [阻断/高风险/待澄清/优化] 标题

- **发生位置：**
- **已知事实：**
- **方案约定或假设：**
- **断裂过程：**
- **对最终目标的影响：**
- **最小修正：**
- **验证方式：**

## 8. 假设清单

| 假设 | 依赖步骤 | 状态：已验证/待验证/已否定 | 不成立后果 | 所需证据或处理 |
|---|---|---|---|---|

## 9. 最小闭环清单

1. **必须修改：**
2. **必须补充的契约：**
3. **必须验证的假设：**
4. **必须增加的测试或证据：**

## 10. 可达性证明

真实原点
  → [步骤及证据]
  → [契约及状态变化]
  → [失败收敛机制]
  → 最终可观察目标

任一箭头缺少事实、明确契约或可执行验证时，不得给出“可通过”。
```
