# 执行环境、运行结果与证据保留

各执行能力可单独遵守本约定，不要求先生成总流程私有文件。

## 最小产物交接（生成由调用方负责）

```text
需求 Markdown → 同源需求 HTML
用例 Markdown（唯一数据/步骤/预期正文）→ 同源 HTML 阅读页
需求 HTML → 整体相对链接 → 实际存在的用例 HTML（同步版本、A/B 业务分组）
```

- 新用例默认正文 `test-cases.wl-qa-test-planner.md`，阅读页 `test-cases.wl-qa-test-planner.html`，放本需求实际文档目录；同源 HTML 按 A/B 业务部分组织、保留 TC 编号与来源，版本从 Markdown 同步，不另维护第二份预期。
- 调用方负责将 QA 输出保存为 Markdown 并生成 HTML、核对两者版本/内容一致及整体相对链接可达。例如同目录的需求 HTML 使用 `href="test-cases.wl-qa-test-planner.html"`，链接目标必须实际存在后才可声称阅读页交接完成；不能只写计划文件名或链接 Markdown 冒充 HTML。不要求逐条双向链接。
- 历史名称沿实际文件，不重命名复制双正文；已有旧 AC 或外部用例沿原权威正文读取。需要阅读页时从该实际正文同源生成、链接实际 HTML，而不是再抄一套用例。单独设计可接已确认外部用例，不要求改名或补总流程专属文件。
- 单独调用 QA 仍可独立产出中文 Markdown 用例和缺口后停止，**不以 HTML 生成作为 QA 前置**，不要求浏览器/渲染器先可用；负责人拿到 QA 结果后再负责阅读页。HTML 未生成时仅记调用方阅读交接缺口，不阻塞 QA 自身交付、不重写其五步核心。

## 轻量恢复记录

复用项目已有 `progress.md`；没有时在本需求目录维护同名短记录即可，不另建流程 DB。实际文件和批准记录优先于摘要，恢复时先核对路径/分支/版本，不能凭“上轮已完成”跳过缺口。

```text
实际产物/版本：需求 <路径@版本>；用例 <Markdown/HTML实际路径@同版>；方案 <路径@版本>
确认范围：需求/用例/方案的范围、人工批准或委托证据位置；环境/操作授权边界
当前阶段：Confirm / Design / Execute / Verify 等；目标目录/分支/代码版本
未决项/下一步：<阻塞/Q/缺陷及最小下一动作；无则明确无>
run链接：<本轮绝对目录或持久报告链接>；复测关联 <旧run/缺陷>
```

## 先约定，再核对，再执行

需求+用例确认时记录：目标环境、URL、角色、前后端分支/commit/部署版本、数据范围、允许的写操作、用例版本和证据目录。沿已有已确认项目设置；无设置时推荐公司业务 Dev / 私人项目本地，并随确认一次确定。生产永不默认，读写分别获准。

执行前核对实际 URL、角色和两端版本与约定一致。缺版本证据或环境不可用就记阻塞；不静默切 Dev/Beta/生产，不用本地自测冒充目标环境验收。网页提交等真实写入需环境+数据+动作授权，自动方案决策不代替这些授权。

## 运行结果与交接

实际执行测试前读取 [测试执行记录约定](../../../../execution-profiles/test-execution.md)。目录、result.json字段、检查点保存、进度和中断恢复以它为唯一正文，不再并行维护Markdown结果或单独问题表。

- progress.md只记录阶段、确认范围、下一步和运行链接，不抄执行项结果。
- 失败项记录问题、环境与数据/版本、复现与证据、预期引用及必要的需求范围依据；代码确认未完成时写“根因待确认”。修复及复测通过新轮次关联原失败，不覆盖历史。不要另建一套缺陷字段模板。
- 观察到页面失败不等于根因已确认；环境/权限阻塞不能归为代码通过；需求外问题只记录，不自动扩修。
- done门槛仍为目标环境所有适用用例通过，有依据的不适用另列；失败/阻塞/未执行不算完成，不能自行改预期或降级为不适用。目标环境通过不等于发布或需求关闭。

保留分类不等于自动删除授权：

- **长期摘要**：已有项目进度只保留基线、阶段、运行及确认/复测关系的链接，不复制步骤结论。
- **关键证据**：result.json及支撑结论的脱敏附件；有缺陷、待复测、hold或证据依赖时保留。
- **临时产物**：可再生下载、调试中间件和非关键完整dump；未分类清楚就保留，不因名称叫“临时”自动删除。

原始截图、日志和浏览器资料不自动入Git；不落盘口令、Token、Cookie或完整网络头。Worktree回收前核对必要记录已持久保存且引用可读，不只留指向已删除Worktree的链接；缺证据则阻塞回收。历史轮次原位保留，不批量迁移或清理。

## 保留与清理：默认保留、仅预览

7 天/30 天只是**待用户确认的建议**，不是已启用策略。没有明确授权的保留策略就继续保留，不建后台清理器。

只有“发布成功 + 需求关闭”两项有证据且满足已授权保留策略，才可进入清理判断；合入 master 不算发布或关闭。存在缺陷、待复测、hold 或证据依赖时不清理，保留到解除并重新确认。

清理前只预览：运行路径、所属项目/需求、状态、关闭和发布证据、期限、hold/缺陷、拟删除范围及长期摘要。实际删除仍需对应授权并校验路径边界；不跟随符号链接，不删除摘要或其他需求目录。删除后摘要保留清理时间、授权与清单，不再承诺原附件可用。

本地 down 是停止工具，不是自动证据清理器：默认保留日志/产物，不默认停共享 MQ；证据删除、共享件停机和 volume 删除须独立显式选择，且确认其他使用者不受影响。临时夹具可用于隔离测试，不据此对真实证据启用清理。
