# wl-herdrs

## 默认方式

仅由负责人委派一层，执行者不得再次委派；用户明确要求自己完成或不要委派时不启动执行者。已知明确禁令或审批拒绝时直接停止，不再加载启动指南或切换通道。

用户显式指定 Orca、Herdr 或其他工具时，按该工具选择最小指南，不先试 Herdr；明确要求 Orca 协调时不以原生 subagent 替代。显式工具不可用时说明阻断，不擅自换通道。

未指定工具时，先用环境变量与命令是否存在做轻量检查（Herdr 必须 `HERDR_ENV=1` 且 CLI 可用），不为判断可用性先读多个指南。Herdr 可用才读取当前 `herdr` Skill；本策略在该条件下授权采用 Herdr。否则跳过其正文，按备用方式选择宿主已有且获准的能力，再只读选中指南。通过 Herdr 固定启动 Pi，显式指定 high。

新执行者使用独立 Tab，保持目标项目目录、不抢焦点，完成后保留。一次交代任务边界和成功标准，由负责人核验结果；状态不明先检查，不重复派发。high 由负责人核对启动参数，执行者不再确认思考级别。无审批模式仅在已授权范围且当前 Pi 明确支持时使用，不增加操作权限。

## 备用方式

Herdr 因环境、工具不可用或宿主执行限制而无法使用时，负责人可改用当前 Agent 宿主原生支持且获准使用的 subagent 能力，无需另行请示。保持同一任务范围、一层委派和验收责任，并简要说明切换原因；不强制套用 Pi、独立 Tab 等仅适用于 Herdr 的要求。原任务状态不明时先核查，不在两个通道重复派发。

明确的用户禁令、组织策略、审批拒绝或资源访问限制，不属于可切换绕过的故障；备用能力本身不可用或未获授权时停止说明。

调度查询优先在工具侧提取当前状态、阻断和产物；保留任务/执行批次标识、存活判断、待处理消息、交付结果和下一步动作，省略重复不变的详情。遇到异常、状态变化或缺交付信号时再展开相关证据；空回执不等于工作未推进，不限制合理阻塞等待。Orca 消息须逐条处理，保留确认所需标识，遵守其等待、心跳、交付与回收约定；无消息或状态未知不能当作退出、完成或重复派发的依据。

派单示例与常用 Herdr 命令按需看 [PM 手册](../../../../roles/project-manager/ROLE.md#三段式派单)；本策略是行为约定，不代表工具权限隔离或备用通道已实测。
