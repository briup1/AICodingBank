# wl-herdrs

本 Skill 只定义个人编排策略。Herdr 的 workspace、tab、pane、Agent 生命周期和 CLI 语法以上游 `herdr` Skill 及当前 `herdr --help` 为准，不在这里复制。

## 进入条件

### 统一委派约定（2026-10-19 用户确认）

调用资格：仅项目经理。当前负责人可承担项目经理职责；已接到执行任务的岗位不得通过自称项目经理继续委派。一层链路为“项目经理 → 执行岗位 → 项目经理回收”，不允许嵌套子代理。工具是否可见不改变职责边界；目前尚未验证工具级禁用。

无论负责人使用哪个 Code Agent，只要确需把明确子任务交给另一个 Agent，就进入本 Skill。负责人宿主可以变化，委派方式不跟着变化。

- 本 Skill 是个人委派策略的唯一正文；岗位与宿主入口引用这里，不各自选择执行工具。
- 固定执行选择见 [统一子代理执行配置](../../../execution-profiles/delegation.md)。不使用宿主内置子代理，不自动改用其他 CLI；下方兼容性表仅用于历史参考，不作为工具选择菜单。
- 有可拆分任务不等于必须委派；负责人可以直接可信完成时保持直接执行。
- Herdr 不可用、启动失败或不能确认思考级别时，不切换备选通道。能自行完成则说明后自己完成；确实要求独立执行或验证则报告阻塞。
- 子任务使用统一任务包：目标与非目标、当前阶段、读写范围、必要资料、已确认结论、完成标准与证据要求。不得默认转发完整上下文。
- 子 Agent 的完成声明不是验收证据；负责人负责回收、核对和最终交付。

```text
收到任务
  -> 是否确需委派且有边界清楚、可验收的子任务？
       ├─ 否：负责人直接完成
       └─ 是：读取固定执行配置，检查 HERDR_ENV=1 与启动前提
                ├─ 满足：使用上游 herdr Skill 委派
                └─ 不满足：负责人可完成则自己做；必须独立执行则报告阻塞
```

- 用户明确提到 Herdr 时总是检查本策略。
- 用户未提 Herdr，只要确需委派仍先应用本策略，不因负责人宿主变化而换通道。
- `HERDR_ENV` 不是 `1` 时不控制 Herdr；按上述阻塞处理，不以本地完成冒充独立验证。
- 不为很小的任务、当前步骤的即时阻塞项或写集合重叠的任务创建子 Agent。

## 拆分规则

子任务必须同时满足：

1. 有一个清晰目标和可量化完成标准。
2. 明确允许读取和修改的路径。
3. 能独立运行聚焦验证。
4. 与并行任务不存在共享写集合。
5. 主 Agent 不依赖其即时结果才能继续当前步骤。

优先按垂直结果拆分，例如“实现并验证一个完整行为”；不要按模型、控制器、测试等水平层拆分。主 Agent 始终负责上下文、排序、冲突处理、集成和最终验证。

## 子 Agent 默认 YOLO

通过 Herdr 新启动的编码子 Agent 使用固定执行配置指定的工具，在获准范围内使用当前 CLI 支持的无人工权限确认模式；启动前核验当前帮助，不从兼容性表选择其他工具。

当前已验证映射见 `references/compatibility.md`。原生参数必须放在 `herdr agent start ... --` 之后。

YOLO 只用于用户已经批准的目标项目或隔离 worktree 内的开发任务。子 Agent 提示必须限制写入范围，并排除：

- 生产环境、发布和外部系统写操作
- Token、密码、Cookie、私钥和客户敏感数据
- 未经授权的 Git push、破坏性 Git 操作和目录删除
- 超出任务边界的配置、依赖或权限修改

命中这些范围时不以 YOLO 委派；由主 Agent 停下并取得明确授权。

## 委派与回收

岗位任务优先通过[岗位运行与恢复入口](../../../execution-profiles/role-runtime.md)登记与交接：先 list/recover 核对旧任务，再 dispatch；执行岗位 checkpoint，项目经理核验证据后 accept。不绕开记录直接重复发送；返工先 rework，再显式确认继续。该入口不是权限隔离。

岗位入组遵守用户确认的固定工位布局：一名成员一个独立 Tab，不用 pane split。通过 tab create 在调用者所属工作区创建工位，保持目标项目 cwd 且不抢焦点；使用返回的 root pane ID 执行 agent start，后续 prompt/wait/get/read 走 agent 命令。Tab 是布局，Agent 是执行者，不能仅创建 Tab 就宣布岗位就绪。旧任务 dispatch 仅兼容历史任务；新增项目组使用入组入口。只有隔离确有价值时才创建 worktree。

每个子 Agent 的提示至少包含：

- 目标和非目标
- 当前执行岗位不得创建子代理或调用委派入口；所需协作返回项目经理
- 允许读写路径
- 现有架构或规范入口
- 完成标准和验证命令
- 禁止的高风险操作
- 输出：改动文件、执行命令、结果、假设和剩余风险

`blocked` 不视为完成。出现 blocked、unknown、超时或启动失败时，读取状态和最近输出；只有确需用户决策或高风险授权时才打断用户。子 Agent 的完成声明不是证据，主 Agent 必须在集成后重新运行相关验证。

## 完成标准

- 每个委派任务都有独立产物或结论及验证输出。
- 并行任务没有未处理的写冲突。
- 主 Agent 已检查完整 diff，并重新运行最终测试或审查。
- 没有因 YOLO 绕过生产、凭证、发布或破坏性操作的授权边界。
