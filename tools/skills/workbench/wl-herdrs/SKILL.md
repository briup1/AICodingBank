# wl-herdrs

## 默认方式

确需委派时优先使用 Herdr，按需读取当前可用的 `herdr` Skill；该委派意图即为使用 Herdr 的指示。通过 Herdr 固定启动 Pi，显式指定 high。仅由负责人委派一层，执行者不得再次委派；用户明确要求自己完成或不要委派时不启动执行者。

新执行者使用独立 Tab，保持目标项目目录、不抢焦点，完成后保留。一次交代任务边界和成功标准，由负责人核验结果；状态不明先检查，不重复派发。high 由负责人核对启动参数，执行者不再确认思考级别。无审批模式仅在已授权范围且当前 Pi 明确支持时使用，不增加操作权限。

## 备用方式

Herdr 因环境、工具不可用或宿主执行限制而无法使用时，负责人可改用当前 Agent 宿主原生支持且获准使用的 subagent 能力，无需另行请示。保持同一任务范围、一层委派和验收责任，并简要说明切换原因；不强制套用 Pi、独立 Tab 等仅适用于 Herdr 的要求。原任务状态不明时先核查，不在两个通道重复派发。

明确的用户禁令、组织策略、审批拒绝或资源访问限制，不属于可切换绕过的故障；备用能力本身不可用或未获授权时停止说明。

派单示例与常用 Herdr 命令按需看 [PM 手册](../../../../roles/project-manager/ROLE.md#三段式派单)；本策略是行为约定，不代表工具权限隔离或备用通道已实测。
