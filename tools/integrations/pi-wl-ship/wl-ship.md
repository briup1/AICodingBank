执行本次 `/wl-ship`，范围：${ARGUMENTS:-当前仓库全部可交付改动}。
调用即授权该范围的临时附件清理、提交和推送，不限于当前 Agent 所写，无需例行二次确认；阅读或安装模板不算调用。遵守项目规则、既有保留/禁传要求与工具审批。

1. **核对**：查看当前仓库、分支、工作区、暂存区、未跟踪文件及已有未推送提交。核实 upstream 和实际推送目标，必要时 fetch；非仓库、游离 HEAD、未完成的 Git 操作、敏感内容、并发改动、目标不明或会夹带范围外历史提交时停止询问。
2. **筛文档、清附件**：结合内容、任务记录和引用判断用途，不按扩展名、目录名或“AI 生成”直接删除。
   - README、使用说明、接口文档，以及需求分析、正式方案、测试用例均属于可交付文档；在本次范围内按项目规则提交并推送，不作为临时附件清理。
   - 临时截图、日志、测试运行结果、草稿和重复报告，只有确认属本次范围、未进入 HEAD、无需留证且没有保留文档或代码引用时，才按明确文件路径删除；新文件已暂存的，同步精确移出暂存区。先简报清单再执行，不额外等待批准。
   - HEAD 中已有文件、验收/故障证据、用途或归属不明的文件不自动删除；待判定过程文档保留且不提交，不阻塞其他明确改动。重要文件已暂存但不应提交时，仅精确取消其暂存，保留文件和原有修改；无法安全分离则询问。不要扫历史目录、递归清空产物目录或自动改 `.gitignore`。已在待推送历史中的不应上传内容必须先停下处理。
3. **分批与验证**：按业务目的分组，相关代码、测试和必要文档同批，小改动不强拆。简报分组与推送目标，完成项目门禁及直接相关检查；失败或必要检查无法执行就停，不顺便修复。危险测试、付费调用、外部业务写入不在授权内。
4. **提交**：逐批按明确路径或补丁暂存，复核完整 staged diff，隔离未选中的暂存内容；无法安全拆分或内容变化时停下核对。禁止整库暂存。说明遵循项目规范，无规范则用 `type(scope): 具体目的`；不跳过 Hook，Hook 改写后重新检查。
5. **推送**：所有计划提交成功后，复核完整待推送范围，用明确 remote 和 refspec 正常推送当前分支一次，不推其他分支或标签。失败保留本地提交，不自动回滚；重试核对远端，不重复创建提交。无改动时仅处理已获准的未推送提交，否则报告无需操作。
6. **回报**：核实远端结果，简报已删除附件、留本地文档、各提交 SHA/目的、推送目标与结果、遗留项。推送成功不等于部署成功。

不合并、不发布、不创建 PR、不切分支或处理其他仓库/子模块；不强推、改写历史、自动 pull/rebase/stash/reset 或更改 Git 持久配置。例外需另行授权；公司 Git 连接失败按需读取 hgj-git-connect。
