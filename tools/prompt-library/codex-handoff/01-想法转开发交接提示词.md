# 01 把想法转成开发交接提示词

**什么时候用**：已有产品想法，希望整理成能交给编码 Agent 的任务说明
**什么时候别用**：目标尚不清楚，需要先探索或访谈
**产出**：可直接交给 Codex 的开发交接提示词
**来源**：用户提供，原始出处未标注
**状态**：未实测

---

复用时，将下面费用分摊的例子替换成自己的产品想法。

```text
给 Codex 写一份交接提示词。

我想开发一款应用：面向室友或出行场景的本地费用分摊工具。
用户可以创建群组、添加成员、录入共同开销，选择付款人和每笔开销的参与者，
并查看简洁的结算汇总，清楚地知道谁欠谁多少钱。

请写一段可以直接复制给 Codex 的提示词，说明：
- 应用目标和用户
- 核心页面或功能
- 限制条件
- 不在开发范围内的内容
- 可能涉及的文件或系统
- 验收标准
- Codex 应如何验证开发成果

最终提示词要直白、实用，因为我接下来会直接把它粘贴给 Codex。
```

## 英文原文

```text
Write a handoff prompt for Codex.

I want to build this app: a local expense splitter for roommates or trips. Users can create a group, add people, enter shared
expenses, choose who paid, choose who participated in each expense, and see a simple settlement summary showing who owes whom.

Write a copy-paste Codex prompt that explains the app goal, the user, the core screens or features, the constraints, what is
out of scope, likely files or systems involved, acceptance criteria, and how Codex should verify the work.

Make the final prompt direct and practical, because I'm going to paste it into Codex next.
```
