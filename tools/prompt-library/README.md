# 提示词库

按**来源方法论**分包存放外部收集的提示词。一套方法一个目录，中文命名，纯 Markdown。

## 目录清单

| 目录 | 方法论 | 来源 | 条目 |
| --- | --- | --- | --- |
| [sdd/](sdd/README.md) | Spec 驱动开发（SDD） | 公众号文章，2026-11-09 入库 | 6 |

## 加一套新的

```text
1. 建目录：本层新建 <方法论短名>/    例：req-engineering/
2. 建 sdd/README.md 同构的 README：出处、适用前提、条目清单表、与现有 Skill 的关系
3. 放提示词：<序号>-<中文名>.md，序号表达该套方法内部的执行顺序
4. 回上表加一行
```

一篇方法论哪怕只有 1 条提示词，也单独建目录。不留"散装"目录——一旦有散装区，半年后它就是最大且没人清理的那个。

## 找一条

```text
我整套看着套讲什么        → 进对应目录，读它的 README
我要找讲某个环节的        → grep -rl 关键词 tools/prompt-library/
我说不清要什么            → 整目录进 OpenViking，用自然语言检索
```

## 边界

- 这里只存**能替换变量直接复用的文本块**。需要读文件、跑命令、多阶段、要验证的，归 `tools/skills/`。
- 这里不收项目专属提示词，那些留在目标项目的文档里。
- 收录不等于验证。每篇开头自报状态；没在真实任务里用过的，不标可用。
- 条目过 40 或方法论过 6 个，再考虑加生成脚本。现在手写。

拓展与归档规则见 [EXTENDING.md](../../EXTENDING.md)。
