# 03 技术方案：先读代码再设计

**什么时候用**：Spec 已确认，要为存量项目出实施方案
**什么时候别用**：全新空项目（无现成代码可读）；需求还没确认
**产出**：plan.md（模块职责、数据模型、API 契约、异常与并发、风险）
**状态**：未实测（2026-11-09 入库）

---

```text
请基于已经确认的 spec.md，制定完整的技术实现方案。

首先阅读项目现有代码、AGENTS.md 和架构文档，理解现有技术栈和模块职责。然后完成：
1. 分析需要修改和新增的模块。
2. 设计模块职责和依赖关系。
3. 设计数据模型及数据库变更。
4. 设计 API Contract。
5. 设计异常处理、事务和并发控制。
6. 分析安全性和兼容性。
7. 识别技术风险和潜在问题。
8. 生成 plan.md。

要求：
1. 优先复用现有架构。
2. 不要无理由引入新依赖。
3. 不要擅自改变已有业务逻辑。
4. 所有设计必须能够追溯到 Spec 中的需求。
5. 对存在争议的方案，说明不同选择及其取舍。

完成后等待人工审核，不要开始编码。
```

---

## 差异

`wl-design-doc` 已覆盖同类产物。本条唯一值得单独记下的是那句硬约束：
**「不要让 AI 在没有阅读现有代码的情况下直接设计技术方案」**，
以及「所有设计可追溯到 Spec 需求」——后者是 06 追踪矩阵的一半。
