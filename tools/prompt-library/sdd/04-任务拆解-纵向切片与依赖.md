# 04 任务拆解：纵向切片与依赖

**什么时候用**：Plan 已确认，要把开发工作变成可执行、可验证的小任务
**什么时候别用**：任务只有一两步；需求或方案还没确认
**产出**：tasks.md（任务表 + 依赖关系 + 需求 ID 关联）
**状态**：未实测（2026-11-09 入库）

---

```text
请根据已经确认的 spec.md 和 plan.md，拆解完整的开发任务。

要求：
1. 将开发工作拆解成小型、可独立验证的任务。
2. 明确任务之间的依赖关系。
3. 每个任务关联对应的需求 ID。
4. 明确修改范围、预期结果和测试要求。
5. 标记数据库迁移、API 变更和配置变更。
6. 优先采用纵向功能切片，确保每批任务都能形成可运行、可验证的功能。

检查所有功能需求是否都有对应的开发任务，不能遗漏。
生成 tasks.md，不要开始编码。

例如：
| ID | 开发任务 | 关联需求 |
| --- | --- | --- |
| T-001 | 创建 Tenant 数据模型 | FR-001 |
| T-002 | 实现 Tenant 数据访问层 | FR-001 |
| T-003 | 实现 Session 创建接口 | FR-001 |
| T-004 | 实现 Session 权限校验 | FR-002 |
| T-005 | 实现 Session 查询接口 | FR-002 |
| T-006 | 编写跨租户访问测试 | FR-002 |

不要让 AI 一次性完成所有任务。
建议每次执行一个任务或一组紧密关联的任务，完成后检查结果，再继续下一批。
```

## 差异

`wl-ticket-run` 已有等价规则：`SKILL.md:61`「默认按纵向业务结果拆分」，且明确反对按
