# 测试执行记录约定

状态：2026-10-20 用户确认；供人工与 Agent 共用。只约定结果记录，不授予测试、登录、数据写入或发布权限。

## 职责与目录

```text
读取指定版本用例 → 创建本轮 result.json → 按检查点执行并保存
                                      → 中断核实后继续 / 新轮复测关联旧轮
```

- 用例正文只维护场景、数据、步骤和预期，不写测试进度或实际结果，不增加“开始测试”按钮或记录页面。
- 默认目录：`<项目根>/.work/<任务编号>/test-runs/<轮次>/`，必须被 Git 忽略。轮次可用 `20261020-001`，创建前检查不存在，冲突换新编号，不能覆盖旧轮。
- 每轮只维护一份 `result.json`；有截图、日志、响应摘要等证据时才建 `evidence/`，截图也放这里。不再拆 `run.json`、`result.md`、问题表或进度文件。
- 需求进度文件只链接本轮记录，不另抄步骤结果。问题直接放失败项，可关联已有缺陷系统，不另建缺陷管理系统。
- 用户明确指定持久运行目录时沿用同样结构和内容约定；不因此复制两份记录。Worktree 回收前按项目要求保存必要记录并更新引用，不删唯一证据。
- 生成用例不创建空测试轮次；实际获准执行时才创建。现有历史轮次保留原状，不批量迁移或删除。

## result.json 最小格式

统一用以下字段名，界面/对话可用中文解释。示例为格式示意，不是已执行结果。

```json
{
  "schemaVersion": 1,
  "runId": "20261020-001",
  "taskId": "R-example",
  "cases": {
    "path": "docs/iteration/requirement/test-cases.wl-qa-test-planner.md",
    "version": "0.4",
    "sha256": "填写实际用例文件的SHA-256"
  },
  "environment": "local",
  "versions": { "frontend": "实际版本或待确认", "backend": "实际版本或待确认" },
  "status": "未开始",
  "startedAt": null,
  "updatedAt": "实际ISO-8601时间，含时区",
  "endedAt": null,
  "previousRun": null,
  "items": [
    {
      "caseId": "TC-001",
      "step": "1.1.3",
      "entry": "供应商端/角色A",
      "variant": "文件识别",
      "status": "未执行",
      "actual": "",
      "issue": "",
      "evidence": [],
      "updatedAt": null
    }
  ]
}
```

- `cases.path` 相对项目根，`evidence` 路径相对本轮目录；不得包含密码、Token、Cookie等凭证。`previousRun` 为旧轮次结果路径，无则为 `null`。
- 用例版本和文件哈希固定本轮预期；执行前及恢复时核对。用例或被测版本变化，新建轮次，不从当前实现反推预期，也不把结果套到另一基线。
- 开始前展开本轮范围：每个可判定检查点一项；公共步骤在不同入口/数据分支下分别展开。唯一键为 `caseId＋step＋entry＋variant`，不能把两端或多数据合并为一项通过。父节点只导航，不重复计入进度。
- `entry` 包含实际角色及入口标识；需要的无凭证URL、会话/任务/记录号可加在项的 `context` 对象，不强制为每项创建空对象。
- `actual` 记录真实观察；`issue` 记录差异、阻塞原因或不适用依据，可附问题编号/链接，不复制完整预期。依据仍引用固定用例的步骤位置。
- 失败、阻塞、不适用必须写原因；不适用须有已确认范围/规则依据，不能用来绕过失败。未执行保留为未执行，知道依赖阻断时注明原因。
- `evidence` 只放必要且脱敏的证据位置；不得用截图存在代替结果比对。异常项可增加原始错误/时间等必要上下文，不另开问题文件。

## 保存、进度与恢复

1. 先列出本轮执行项，初始均为“未执行”；真正开始时更新本轮开始时间和状态。
2. 开始一个检查点先记“进行中”，涉及写操作时在动作前保存；完成后立即填写实际、问题、证据并更新状态/时间，不等整轮结束。
3. 执行项状态固定为：未执行、进行中、通过、失败、阻塞、不适用。未获得结果或证据不足不能记通过。
4. 本轮状态为：未开始、进行中、已暂停、已结束。“已结束”只表示停止本轮，不等于验收通过；存在失败/阻塞/未执行仍要如实报告。
5. 进度直接统计 `items`，不维护另一份计数/百分比。全部适用项通过、有依据的不适用另列，才能声称本轮范围通过；单轮通过不等于全需求验收或发布。
6. 保存时写同目录临时文件并原子替换 `result.json`，完成后不保留备份文件。每轮一个写入负责人；并发执行者返回结果给负责人合并，不能多进程各自覆盖整个文件。
7. 中断保留已完成结果并将本轮记“已暂停”。恢复先核对基线、授权和环境；“进行中”的项先按已有任务/请求/记录号回读，结果不确定就保留阻塞原因，不能盲目重放提交。
8. 修复后创建新轮次，用 `previousRun` 关联旧轮；只列获准复测范围，不把未复测项目复制成通过，不覆盖旧失败或修改预期凑通过。

## 工具接入

- 实际执行测试的岗位/Skill先读本约定；生成用例的Skill只引用，不执行或代填结果。
- `wl-web-auto` 用 `scripts/run.mjs init --task <slug> --mode verify --test-run <本轮绝对目录>` 接入已存在且含有效 `result.json` 的轮次，`mixed` 同样支持。不与 `--project/--run-root` 混用；创建轮次及更新执行项由测试负责人完成，接入命令不自动跑测试或保存检查点。
- 测试模式不创建另一套 `run.json/result.md/screenshots`；浏览器截图和日志均按需存本轮 `evidence/`。`wl-web-auto` 页面执行使用 Ego TaskSpace；工具状态不替代业务结果，可在 `result.json` 的 `tools` 对象记录 spaceId、Page label 与任务收尾状态，不另建生命周期账本。
- 普通网页查询/填表任务不是用例测试时，沿用该工具原有运行文件，不强行创建测试轮次。
- 不自动清理旧轮或原始证据；停止浏览器/服务不等于授权删记录。本约定不改变各项目的授权与证据保留边界。
