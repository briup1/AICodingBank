# 最佳实践记录规范

这是本项目最佳实践记录的唯一编写规范。入口在 [README](README.md)，新记录从 [模板](TEMPLATE.md)开始；其他文档只引用，不复制规则。

## 存什么、不存什么

存两类可复用内容：一是具体问题的调查、尝试、解决路径、验证与踩坑；二是从提示词、清单或短笔记中提炼的方法，讲清它希望达到什么效果、适用什么场景、怎样使用。技术、内容创作及其他问题都可以记录，用 category 和 tags 分类。字数少、没有执行日志，不单独构成舍弃理由；关键是能否解释清楚可复用的主题和方法。

不存：原样对话、命令流水账、凭证、客户敏感资料、大型视频、业务源码副本。原始日志、项目验收及产物留在原项目，记录只保留足够理解的摘要与证据指针。研究还在推进且没有可复用结论时留在研究入口，不伪装已验证最佳实践。

最佳表示当前证据支持的推荐，不表示永远正确。失败尝试有价值，不因整理而抹除；“本次未成功”不能无依据写成“这条路径必然错误”。不必为每次小任务建记录，先查同题，有新适用条件或证据则更新原记录。

## 目录与命名

一件问题一个目录，正文为 README.md，必要附件同目录；大文件只保留外部指针。格式：

```text
best_practices/YYYY-MM-DD-主题-解决的问题/
├── README.md
└── 必要附件或历史原文
```

例如：`2026-10-18-B站字幕-提取完整带时间轴字幕`。名称描述能解决什么，不用“总结”“最终版”“资料”代替主题。中文可直接使用，多个词用短横线，不使用空格或路径分隔符。日期使用真实实践日期；未知则用记录日期并注明 date_basis: recorded-date。迁入历史材料只能使用可核实的首次入库日期，date_basis: first-repository-record，不把 Git 日期伪装为实际成功日期。同一天同题优先更新原记录，确属不同问题时在问题部分消歧。

已有记录不因复核日期变化就反复改名；更新 updated，保留首次形成日期与变更说明。

## 最小元数据

- title：主题和可解决的问题。
- date、date_basis：文件名日期与依据。
- updated：最近实际修改/复核日期，不因移动而伪造重新验证。
- category：技术 / 内容创作 / 其他；tags 为可多选的具体主题。
- status：verified / partial / historical-unverified / superseded。
- source：项目文件、版本、来源链接或提交定位，不写凭证 URL。

verified 必须有适用条件和实际验证证据；partial 指部分路径有验证、剩余明确未覆盖；historical-unverified 指只有历史方法/模板/示例，不能证明当前可用；superseded 必须指向替代记录。迁移不是验证，不修改 Skill 的 verified 状态。

## 正文必须回答的七个问题

1. **问题与适用条件**：想解决什么、何时适用、有哪些前提与风险。
2. **调查与尝试**：每条路径的动机、操作摘要、观察结果与证据；未做的不能列为已尝试。
3. **当前推荐路径**：可复用的关键步骤和必要检查，而不是粘贴所有终端输出。
4. **踩坑与未采用路径**：失败、绕路、排除理由，区分已证实原因与猜测。
5. **验证与未覆盖**：实际结果、版本/时间、最小证据定位、未验证事项。
6. **下次使用与失效条件**：从哪里开始，什么变化会让结论不再适用，旧授权不继承。
7. **来源与修订**：引用原始项目依据；新证据修正旧结论，必要时标 superseded。

实际问题记录按以上七个问题组织，可合并章节。方法提炼记录则以“主题/预期效果 → 适用场景 → 原文意图 → 建议用法 → 注意事项 → 验证状态与来源”为主，不必反复堆空的尝试/踩坑章节。无真实证据时集中说明尚未实测；推演的效果、建议和风险必须明确标记，不编造成实际尝试或成功。

## 历史材料迁入

先保留原文和来源，再分析它想解决什么问题、想达到什么效果，提炼适用场景与可复用方法，不能只写“内容短、未经验证”的存档说明。模板、清单和示例可作为 historical-unverified 材料保留并提炼，方法价值与验证状态分开判断，不自动当作个人实践成功记录。完整 Skill 包应迁到 tools/skills，不混放进最佳实践；说明页可链接它。历史原文不强行重写、不补造过程，后续真实应用再更新证据。

## 写入与验证

执行岗位提炼候选，项目经理核对范围、同题记录、事实与证据；没有项目经理实例时由当前任务负责人完成，不为归档强行召集多人。用户要求“沉淀/最佳实践记录”时按本规范写入；未获授权不把对话、代码自动上传到 OpenViking 或其他服务。

写后检查名称/日期、状态/来源、正文缺口、相对链接和敏感信息。跨项目知识库只放指针或独立综合观点，不再保存同一正文。稳定且值得复用的操作才另行提炼进 Skill；案例不是权限或行为规则的替代品。
