# Compass 跨仓回归导航

> 例：“Compass 的港口标准化改完了，帮我确认该怎么回归，先不发查价。”

```text
确认本次需求和分支 → 读 Compass 的业务预期 → 按验证目标选页面证据或行为评估 → 对照本次版本
```

| 要回答什么 | 去哪里 | 看什么 |
| --- | --- | --- |
| 哪些港口输入应澄清、哪些能继续查价？ | 按 [工作台入口](../../AGENTS.md) 定位 Compass 需求 Worktree；从它的 Agent 入口进入需求与港口解析契约。 | 需求定义预期；项目已有用例、验收记录、版本与部署证据留在项目。需求编号不明确时先核实，不按关键词随便选分支。 |
| 查价 Web 页有没有发新任务、有没有展示当轮结果？ | [Compass Web 对话 E2E](../../tools/compass-platform-e2e/README.md)。若要测运营后台、管理页或小程序，回 Compass 项目找对应验收入口。 | 回读已有轮次的 `result.json` 和必要截图；对照用例、环境、被测版本和逐轮结果。通用查询历史不等于港口专项覆盖。 |
| Agent 有没有正确澄清、选对港口、传对参数？ | 由本机项目索引定位 `langfuse_runner`，读取它的 Agent 入口和 README，按其规则找用例、实验和已有证据。 | 对照用例与评估规则版本、被测 Agent 版本、环境和实际调用；Runner 有入口不代表已有匹配用例，行为评估也不等于 Web 通过。 |

只做回归规划或历史回读时，不启动登录、查价、Agent 或 Judge，不重跑历史轮次。最终只报告本次确认的目标分支及环境、可引用的已有证据和未覆盖项；环境、被测版本或用例不匹配的，只当历史参考。需要新跑时，再按各入口确认环境、用例和当次授权。工作台不另存日志、不另建测试账本。
