# 个人 AI 工作台重构规划稿

状态：讨论稿，不是实施授权。依据：工作台 main 分支 a60ae39 的入口、能力登记和历史验收记录；未运行宿主、业务服务或自动化任务。

## 一、它替你做什么

你同时推进多个项目，一个项目还可能有多个工作副本。你的稀缺资源不是存放文件的位置，是注意力：每次换项目、换会话或看交付，都得重新回答「说的是哪件事、做到哪了、这个结果算不算」。工作台最值得替你承担的，就是这三次判断之前的查找和核对。

**定位：个人跨项目工作台。你定目标、作取舍、抽查结果；工作台帮你找对项目、选对方法、带回可信的结果。** 它不接管业务仓库，也不要求你天天更新一份总台账。

| 你在什么时候用 | 工作台应交给你什么 | 给你的价值 |
|---|---|---|
| 开工：「继续昨天那个需求」 | 对应项目与工作副本、上次停点、下一步；有两个候选就说清差别 | 少复述背景，不在错分支开工 |
| 切换项目：「今天哪件事要我决定？」 | 只列等你决定或受阻的事项，以及不决定会影响什么；来源过期就明示 | 不用逐个翻会话看进度 |
| 抽查：「这次到底验过没有？」 | 针对哪个版本和环境、哪些通过、哪些未知、原始证据在哪 | 不把“有人提交了”误当“已经验收了” |
| 复用：「下个项目也要这样验」 | 已验证的方法及适用边界；项目专属数据不带走 | 下一次少试错，也不会照搬业务假设 |

以上是目标体验，不是对现有自动化程度的描述。第一版允许你通过一句话发起查询，不必先有大屏。

## 三、目标结构：按用途找，按责任存

**人看到的首页只回答四个问题：开始或继续工作｜今天要我决定什么｜查看交付与证据｜查找并复用方法。** 岗位、技能、模板、安装器仍然存在，但不再是你开工前必选的菜单。维护工作台另设次级入口。这里设计的是中文入口，不是要求创建五套目录。

底层只问一句：**这条信息将来变了，谁有资格改它？**

| 内容 | 正文或原始记录归谁 | 工作台做什么 |
|---|---|---|
| 需求、业务规则、项目进度、验收结论 | 目标项目的现有记录；原始运行证据由实际产生它的工具保存 | 指回本次需求、版本和证据，不复制日志或另写结论 |
| 跨项目方法、岗位职责、通用模板 | 工作台相应维护者；有上游的能力保留上游来源 | 中文说明「何时用、何时不用、去哪里改」；区分已收录、此宿主可用、真实任务已验证 |
| 项目位置、工作副本、会话和安装状态 | 本机索引、Git 或实际宿主分别负责 | 查询时核对；私有路径与凭证不进共享文档，目录登记不能代替运行状态 |
| 一次尝试、可复用经验、长期知识 | 一次尝试留任务；有证据的通用经验归工作台；来源资料归知识库 | 需要时提炼方法或引用原文，不把每次对话都变成新技能 |

**命名约定：** 人常找的资料目录、文件名和入口尽量直接用中文。名称写用途，例如「验收结果怎么看」，不把它藏在「执行配置」里。工具约定的 `AGENTS.md`、`SKILL.md` 和已被调用的技能标识保留。机器能否处理中文路径要实际验证，不能把「有引用」一概当作不能改，也不能因想改名就断开现有引用。

## 四、用同一个例子检验设计

> 「Compass 港口标准化，现在可以算验收通过吗？先不要发查价。」

```text
定位到具体需求 → 查项目约定的通过条件 → 对照已有证据 → 给出结论或缺口
```

依据[已有走查](../迁移记录/2026-11-18-workbench-task-navigation.md)，同一个关键词可能命中两个任务；有 Dev 页面记录，也不代表其被测版本已确认。目标答复示例：**「现有记录不足以判定本次通过。缺的是这份结果对应的版本；先对上版本，再判断要不要补测。本次没有发起查价。」** 这比给你一串工具链接有用。若下个项目也需要这类判断，可复用的是「版本与证据怎么对」，不是 Compass 的用例与结果。

## 五、迁移顺序：每一步都可以停

| 批次 | 拟做什么 | 怎样判定值得继续 |
|---|---|---|
| ① 先验证入口，不搬文件 | 选一个真实任务，用现在的入口记录查找步数、误选点、能否找到原始证据；再用中文入口草图走同一条路 | 不熟悉目录的人能在两次导航内找到权威入口；换一个新会话，无需口头补背景也能给出有据结论或明确缺项。两次是导航目标，不限制核验证据的步骤。 |
| ② 固定归属，再做局部迁移 | 从试点链路纠正过期说法；盘点受影响的人读资料、机器入口、外部引用和维护处。先迁一个低风险的资料组，不碰技能安装链 | 从旧任务仍能找到原文；新资料有唯一归宿；相对链接、结构测试和已知宿主入口均通过。找不到外部调用方，或无法恢复旧路径，就不迁。 |
| ③ 扩到第二个项目 | 用不同项目重走「接续、抽查、复用」；检验哪些真是共性，删去方案中只适用于单项目的假设。不迁业务仓资料 | 同一中文入口能指向各项目自己的证据；新增一个项目不用复制流程或再填一套进度表。每批保留新旧路径对照，失败只恢复本批。 |
| ④ 有价值才做自动汇总 | 若两个项目反复发生同类人工查询，先试只读汇总「待我决定、受阻、待抽查」；显示来源与最近核验时间。先不做后台调度 | 对照原始记录无误报；数据过期、来源缺失能被看见；你少翻会话，不增加手工填报。否则保留按需查询即可。 |

**首期不做：** 全仓中文改名、合并所有工作流、新看板服务、自动安装和跨项目搬迁历史资料。保留现有权限门槛；看结果不会触发执行，规划确认也不会触发迁移。

**建议先评审的决定：** 是否接受「人按用途进入，资料按维护责任存放；工作台负责找回结论，不重新拥有结论」。若接受，下一次只评审第一批的中文入口草图和同一任务的新旧对照，不先审批全仓目录树。
